* 模块 0：DuckDB 是什么
 
** 本模块解决的问题
建立对 DuckDB 的准确定位：它是什么，用来做什么，不用来做什么。
** 本模块不解决的问题
不讲安装，不讲 SQL 语法，不比较所有数据库。
** 一句话定位
 
#+begin_quote
DuckDB 是一个嵌入式列式 OLAP 数据库。
核心价值：无需服务器，用标准 SQL 分析本地数据文件。
#+end_quote
 
它就像"数据分析界的 SQLite"——单文件，零配置，但专为分析优化。
** 解决什么问题
 
| 场景                        | DuckDB 合适？ | 备注                           |
|-----------------------------+---------------+--------------------------------|
| 分析一个 CSV / Parquet 文件 | ✅ 强项   | 直接 SQL 查询文件，无需导入    |
| 本地数据探索、ETL           | ✅ 强项   | 比 pandas 更快，比搭 PG 更省事 |
| 复杂 GROUP BY / 窗口函数    | ✅ 强项   | 向量化执行，大文件快           |
| 应用内嵌入式存储            | 🟡 可以 | SQLite 更成熟                  |
| 多人并发写入                | ❌ 不适合 | 不支持多进程并发写             |
| 实时事务（转账、登录）      | ❌ 不适合 | 用 MySQL / PostgreSQL          |
| 分布式大数据                | ❌ 不适合 | 用 BigQuery / Snowflake        |
** DuckDB vs 常见工具一句话对比
 
| 对比          | 结论                                                       |
|---------------+------------------------------------------------------------|
| vs SQLite     | SQLite 擅长 OLTP（应用存储），DuckDB 擅长 OLAP（数据分析） |
| vs pandas     | DuckDB 用 SQL，pandas 用 Python；100MB+ 文件 DuckDB 更快   |
| vs PostgreSQL | PostgreSQL 需要服务器进程，DuckDB 是单文件零配置           |
** 检查标准（口答）
 
1. 你有一个 50MB 的 Package 下载记录 CSV，想按分类统计数量 → DuckDB 合适吗？
   （合适，这是典型的本地分析场景）
 
2. 你在开发一个 Emacs 插件，需要在本地存储用户配置 → DuckDB 合适吗？
   （不合适，用 SQLite 更合适）

* 模块 2：数据建模
 
** 本模块解决的问题
 
为 Emacs Package 数据设计一个最小可用的表结构：够用，不过度设计。
** 本模块不解决的问题
 
不讲数据库范式、不讲索引优化、不讲多表关联建模（模块 9 涉及）。
** 从"要回答的问题"推导字段
 
好的数据模型从问题出发，而不是把所有字段都塞进去：
 
| 分析问题           | 需要的字段                  |
|--------------------+-----------------------------|
| 一共有多少个包？   | name（计数行即可）          |
| 每个分类有多少包？ | category                    |
| 哪些下载量最高？   | downloads                   |
| 哪些最近更新？     | last_updated                |
| 哪些长期无人维护？ | last_updated, is_maintained |
| 按作者分析？       | author                      |
| 找到包的源码？     | repo_url                    |
** CREATE TABLE：最小可用 DDL
 
#+begin_src sh
  DB="$HOME/duckdb/emacs_packages.duckdb"
  duckdb "$DB" <<'SQL'
  -- IF NOT EXISTS 保证重复运行不报错
  DROP TABLE IF EXISTS packages;
 
  CREATE TABLE packages (
      name          VARCHAR     PRIMARY KEY,   -- 包名，全局唯一标识
      version       VARCHAR     NOT NULL,      -- 版本（字符串：格式多样）
      author        VARCHAR,                   -- 主要作者
      category      VARCHAR,                   -- 分类 / keyword
      downloads     INTEGER     DEFAULT 0,     -- 累计下载次数
      last_updated  DATE,                      -- 最后更新日期
      description   VARCHAR,                   -- 单行描述
      repo_url      VARCHAR,                   -- 源码仓库 URL
      is_maintained BOOLEAN     DEFAULT TRUE   -- 是否仍在维护
  );
 
  -- 验证：查看字段列表
  DESCRIBE packages;
  SQL
#+end_src
** 字段类型决策说明
 
| 字段          | 类型    | 为什么这样选                                           |
|---------------+---------+--------------------------------------------------------|
| version       | VARCHAR | ~"3.3.0" / "33" / "20240115"~ 格式不一，不能用数字类型 |
| downloads     | INTEGER | 计数值，最大 ~20 亿，INTEGER 够用                      |
| last_updated  | DATE    | 选 DATE 而非 VARCHAR，才能用日期函数做运算             |
| is_maintained | BOOLEAN | 只有 TRUE/FALSE 两值，布尔类型语义最清晰               |
** 预期输出示例

  ┌───────────────┬─────────────┬─────────┬──────────────────┐

  │ version       │ VARCHAR     │ NO      │                  │
  │ author        │ VARCHAR     │ YES     │                  │
  │ category      │ VARCHAR     │ YES     │                  │
  │ downloads     │ INTEGER     │ YES     │                  │
  │ last_updated  │ DATE        │ YES     │                  │
  │ description   │ VARCHAR     │ YES     │                  │
  │ repo_url      │ VARCHAR     │ YES     │                  │
  │ is_maintained │ BOOLEAN     │ YES     │                  │

** 常见错误
 
| 错误                         | 原因                                              |
|------------------------------+---------------------------------------------------|
| 把 version 设为 FLOAT        | "3.3.0" 不是合法浮点数，导入时报 Conversion Error |
| 把 last_updated 设为 VARCHAR | 无法使用 DATE_DIFF / INTERVAL 等日期运算函数      |
| 没有 DROP TABLE IF EXISTS    | 重新运行脚本时报 Table already exists             |

** 步骤 2：直接查询 CSV（不建表，快速验证数据）
 
DuckDB 可以直接 SQL 查询 CSV 文件，这是它的核心能力之一：
 
#+begin_src sh
  CSV="$HOME/duckdb/emacs_packages.csv"
  duckdb -c "
  SELECT name, category, downloads, last_updated
  FROM read_csv_auto('$CSV')
  ORDER BY downloads DESC
  LIMIT 5;
  "
#+end_src
 
#+begin_quote
*=read_csv_auto()= 解决什么问题*：自动推断列名和类型，无需手写 schema，
适合"先看看数据长什么样"的探索阶段。
#+end_quote
** 步骤 3：导入到持久化表（推荐方式）
 
#+begin_src sh
  DB="$HOME/duckdb/emacs_packages.duckdb"
  CSV="$HOME/duckdb/emacs_packages.csv"
 
  # 用 CREATE TABLE AS 一步完成建表+导入
  duckdb "$DB" <<SQL
  DROP TABLE IF EXISTS packages;
 
  CREATE TABLE packages AS
      SELECT * FROM read_csv('$CSV',
          header    = true,
          columns   = {
              'name':          'VARCHAR',
              'version':       'VARCHAR',
              'author':        'VARCHAR',
              'category':      'VARCHAR',
              'downloads':     'INTEGER',
              'last_updated':  'DATE',
              'description':   'VARCHAR',
              'repo_url':      'VARCHAR',
              'is_maintained': 'BOOLEAN'
          }
      );
 
  SELECT COUNT(*) AS imported_rows FROM packages;
  SQL
#+end_src
** 步骤 4：验证数据完整性
 
#+begin_src sh
  DB="$HOME/duckdb/emacs_packages.duckdb"
  duckdb "$DB" <<'SQL'
  -- 总行数
  SELECT COUNT(*) AS total_packages FROM packages;
 
  -- NULL 值检查
  SELECT
      COUNT(*) - COUNT(name)         AS null_names,
      COUNT(*) - COUNT(downloads)    AS null_downloads,
      COUNT(*) - COUNT(last_updated) AS null_dates
  FROM packages;
 
  -- 数值范围快检
  SELECT
      MIN(downloads)   AS min_dl,
      MAX(downloads)   AS max_dl,
      MIN(last_updated) AS earliest,
      MAX(last_updated) AS latest
  FROM packages;
  SQL
#+end_src
** 两种导入方式对比
 
| 方式                                         | 语法         | 适用场景                   |
|----------------------------------------------+--------------+----------------------------|
| =read_csv_auto()=                            | 自动推断类型 | 快速探索，对类型精度要求低 |

| =COPY packages FROM 'file.csv' (FORMAT CSV)= | 标准 SQL     | 向已存在的表追加数据       |

| =File not found=                           | 路径错误            | 使用绝对路径；确认文件存在                                        |
| =PRIMARY KEY violation=                    | CSV 中有重复的 name | 先 =SELECT name, COUNT(*) GROUP BY name HAVING COUNT(*) > 1= 检查 |

** Q2：都有哪些分类，按名称排序
 
#+begin_src sh
  DB="$HOME/duckdb/emacs_packages.duckdb"
  duckdb "$DB" <<'SQL'
  SELECT DISTINCT category
  FROM packages
  ORDER BY category;
  -- DISTINCT 去重：每个 category 只出现一次
  -- 不加 DISTINCT 则每行都会出现对应 category

** 9.1 CTE（公共表表达式）
 
*CTE 解决的问题*：把嵌套子查询拆成有名字的逻辑步骤，让 SQL 可读如代码。
 
#+begin_src sh
  DB="$HOME/duckdb/emacs_packages.duckdb"
  duckdb "$DB" <<'SQL'
  -- 没有 CTE 的写法（难读，容易出错）
  -- SELECT * FROM (SELECT category, COUNT(*) cnt FROM packages GROUP BY category) t WHERE cnt > 2;
 
  -- 用 CTE 的清晰写法
  WITH
  category_stats AS (                            -- CTE 1：分类统计
      SELECT
          category,
          COUNT(*)       AS pkg_count,
          SUM(downloads) AS total_downloads
      FROM packages
      GROUP BY category
  ),
  high_volume AS (                               -- CTE 2：筛选高量分类
      SELECT *
      FROM category_stats
      WHERE pkg_count >= 3
  )
  SELECT
      category,
      pkg_count,
      total_downloads,
      ROUND(100.0 * total_downloads / SUM(total_downloads) OVER (), 1) AS share_pct
  FROM high_volume
  ORDER BY total_downloads DESC;
  -- WITH 子句后的查询可以像表一样引用每个 CTE
  -- 多个 CTE 用逗号分隔
  SQL
#+end_src
** 9.2 窗口函数：全局排名（RANK / ROW_NUMBER）
 
*窗口函数解决的问题*：在不合并行的前提下，为每行计算"相对于其他行"的统计值。
 
#+begin_src sh
  DB="$HOME/duckdb/emacs_packages.duckdb"
  duckdb "$DB" <<'SQL'
  SELECT
      name,
      category,
      downloads,
      ROW_NUMBER() OVER (ORDER BY downloads DESC) AS global_row_num,
      RANK()       OVER (ORDER BY downloads DESC) AS global_rank,
      DENSE_RANK() OVER (ORDER BY downloads DESC) AS global_dense_rank
  FROM packages
  ORDER BY downloads DESC
  LIMIT 10;
  -- ROW_NUMBER()：1, 2, 3, 4...（无并列）
  -- RANK()      ：1, 2, 2, 4...（并列跳号）

** 9.5 窗口函数：组内占比和累计占比

** 窗口函数语法结构
 
#+begin_example
  函数名() OVER (
      [PARTITION BY 分组列]        -- 在哪个范围内计算（可选）
      [ORDER BY 排序列 DESC]        -- 如何排序（可选）
      [ROWS/RANGE BETWEEN ...]      -- 滑动窗口范围（高级，可选）
  )
 
  常用窗口函数速查：
    ROW_NUMBER()      行号（无并列）
    RANK()            排名（并列跳号）
    DENSE_RANK()      排名（并列不跳号）
    SUM(col)          组内累计/总计
    AVG(col)          组内平均
    MIN(col)          组内最小
    MAX(col)          组内最大
    LAG(col, n)       当前行前 n 行的值
    LEAD(col, n)      当前行后 n 行的值
    FIRST_VALUE(col)  组内第一行的值
    PERCENT_RANK()    百分位排名（0~1）
#+end_example

* 模块 11：可复用分析模板
 
** 本模块解决的问题
 
把本教程的分析流程提炼为通用模板，下次换数据集时可以直接套用。
** 通用 DuckDB 数据分析模板
 
#+begin_src sql
  -- ════════════════════════════════════════════════════════
  -- DuckDB 通用数据分析模板 v1.0
  -- 替换：<TABLE>  <ID_COL>  <GROUP_COL>  <VALUE_COL>  <DATE_COL>
  -- ════════════════════════════════════════════════════════
 
  -- ── Step 0: 探索数据结构 ────────────────────────────────
  DESCRIBE <TABLE>;
  SELECT * FROM <TABLE> LIMIT 5;
 
  -- ── Step 1: 数据概况 ────────────────────────────────────
  SELECT
      COUNT(*)                      AS total_rows,
      COUNT(DISTINCT <GROUP_COL>)   AS unique_groups,
      MIN(<VALUE_COL>)              AS min_value,
      MAX(<VALUE_COL>)              AS max_value,
      ROUND(AVG(<VALUE_COL>), 2)    AS avg_value,
      -- 检查 NULL
      COUNT(*) - COUNT(<VALUE_COL>) AS null_count
  FROM <TABLE>;
 
  -- ── Step 2: 分组统计 ────────────────────────────────────
  SELECT
      <GROUP_COL>,
      COUNT(*)                   AS count,
      SUM(<VALUE_COL>)           AS total,
      ROUND(AVG(<VALUE_COL>), 2) AS avg_val,
      MAX(<VALUE_COL>)           AS max_val
  FROM <TABLE>
  GROUP BY <GROUP_COL>
  HAVING COUNT(*) >= 2
  ORDER BY total DESC;
 
  -- ── Step 3: 时间趋势（如有日期列）──────────────────────
  SELECT
      EXTRACT(year FROM <DATE_COL>)::INTEGER AS year,
      COUNT(*)                               AS count,
      SUM(<VALUE_COL>)                       AS total
  FROM <TABLE>
  GROUP BY year
  ORDER BY year;
 
  -- ── Step 4: TOP N 列表 ──────────────────────────────────
  SELECT
      ,*,
      RANK() OVER (ORDER BY <VALUE_COL> DESC) AS global_rank
  FROM <TABLE>
  ORDER BY <VALUE_COL> DESC
  LIMIT 10;
 
  -- ── Step 5: 组内 TOP N ──────────────────────────────────
  WITH ranked AS (
      SELECT *,
          ROW_NUMBER() OVER (PARTITION BY <GROUP_COL>
                             ORDER BY <VALUE_COL> DESC) AS rn
      FROM <TABLE>
  )
  SELECT * FROM ranked WHERE rn <= 3
  ORDER BY <GROUP_COL>, rn;
 
  -- ── Step 6: 导出结果 ────────────────────────────────────
  COPY (
      SELECT * FROM <TABLE>
      ORDER BY <VALUE_COL> DESC
  ) TO 'output_analysis.csv' (FORMAT CSV, HEADER TRUE);
#+end_src

      downloads,

*** 练习 11：CTE + 组内均值过滤
 
#+begin_src sh
  DB="$HOME/duckdb/emacs_packages.duckdb"
  duckdb "$DB" <<'SQL'
  WITH cat_avg AS (
      SELECT
          category,
          AVG(downloads) AS avg_dl
      FROM packages
      GROUP BY category
  )
  SELECT
      p.name,
      p.category,
      p.downloads,
      ROUND(a.avg_dl, 0) AS category_avg,
      p.downloads - ROUND(a.avg_dl, 0) AS above_avg_by
  FROM packages p
  JOIN cat_avg a ON p.category = a.category
  WHERE p.downloads > a.avg_dl
  ORDER BY p.category, p.downloads DESC;
  SQL
#+end_src

2. 模块 0：DuckDB 是什么

2.1. 本模块解决的问题

建立对 DuckDB 的准确定位：它是什么，用来做什么，不用来做什么。

2.2. 本模块不解决的问题

不讲安装，不讲 SQL 语法，不比较所有数据库。

2.3. 一句话定位

DuckDB 是一个嵌入式列式 OLAP 数据库。 核心价值：无需服务器，用标准 SQL 分析本地数据文件。

它就像"数据分析界的 SQLite"——单文件，零配置，但专为分析优化。

2.4. 解决什么问题

场景 DuckDB 合适？ 备注
分析一个 CSV / Parquet 文件 ✅ 强项 直接 SQL 查询文件，无需导入
本地数据探索、ETL ✅ 强项 比 pandas 更快，比搭 PG 更省事
复杂 GROUP BY / 窗口函数 ✅ 强项 向量化执行，大文件快
应用内嵌入式存储 🟡 可以 SQLite 更成熟
多人并发写入 ❌ 不适合 不支持多进程并发写
实时事务（转账、登录） ❌ 不适合 用 MySQL / PostgreSQL
分布式大数据 ❌ 不适合 用 BigQuery / Snowflake

2.5. DuckDB vs 常见工具一句话对比

对比 结论
vs SQLite SQLite 擅长 OLTP（应用存储），DuckDB 擅长 OLAP（数据分析）
vs pandas DuckDB 用 SQL，pandas 用 Python；100MB+ 文件 DuckDB 更快
vs PostgreSQL PostgreSQL 需要服务器进程，DuckDB 是单文件零配置

2.6. 检查标准（口答）

  1. 你有一个 50MB 的 Package 下载记录 CSV，想按分类统计数量 → DuckDB 合适吗？ （合适，这是典型的本地分析场景）
  2. 你在开发一个 Emacs 插件，需要在本地存储用户配置 → DuckDB 合适吗？ （不合适，用 SQLite 更合适）

6.10. SQL 执行顺序（避免错误的关键）

    COUNT(*) AS package_count

7.4. Q2：每个分类的总下载量、平均下载量、最高下载量

duckdb "$DB" <<'SQL'
SELECT
    category,
    COUNT(*)                     AS pkg_count,
    SUM(downloads)               AS total_downloads,
    ROUND(AVG(downloads), 0)     AS avg_downloads,
    MAX(downloads)               AS top_downloads
FROM packages
GROUP BY category
ORDER BY total_downloads DESC;
-- SUM()：组内求和；AVG()：组内平均值
-- ROUND(值, 小数位)：控制小数精度
SQL

DB="$HOME/duckdb/emacs_packages.duckdb"

    category,
    COUNT(*) AS pkg_count
FROM packages
GROUP BY category
HAVING COUNT(*) >= 3
ORDER BY pkg_count DESC;

-- WHERE vs HAVING 的本质区别：
-- WHERE  在 GROUP BY 之前执行，过滤原始行
-- HAVING 在 GROUP BY 之后执行，过滤聚合结果
-- 因此：不能写 WHERE pkg_count >= 3（pkg_count 还不存在）
SQL

7.6. Q4：哪些作者维护的包最多，累计下载量是多少？

    author,
    COUNT(*)                     AS pkg_count,
    SUM(downloads)               AS total_downloads
FROM packages
WHERE is_maintained = TRUE
GROUP BY author
HAVING COUNT(*) >= 2
ORDER BY total_downloads DESC;
-- WHERE 先过滤掉废弃包，再做 GROUP BY
-- HAVING 只保留维护 2 个以上包的作者
SQL

    COUNT(*)                                          AS total_packages,
    COUNT(DISTINCT category)                          AS total_categories,
    COUNT(DISTINCT author)                            AS total_authors,
    SUM(downloads)                                    AS total_downloads,
    ROUND(AVG(downloads), 0)                          AS avg_downloads,
    SUM(CASE WHEN is_maintained = FALSE THEN 1 END)   AS abandoned_count
FROM packages;
-- COUNT(DISTINCT col)：统计不重复值的数量

7.8. GROUP BY 执行逻辑图解


原始数据：
  name       category    downloads
  company    completion  890000
  helm       completion  750000
  vertico    completion  250000
  flycheck   tools       680000

GROUP BY category 后（相同 category 合并为一行）：
  category    COUNT(*)   SUM(downloads)   MAX(downloads)
  completion  3          1890000          890000
  tools       1          680000           680000

  1. GROUP BY 中的列（category）
  2. 聚合函数（COUNT / SUM / AVG 等）
  3. 不能出现未聚合的其他列（如 name）

    category,
    name       AS top_package,
    author,
    downloads
FROM packages
ORDER BY category, downloads DESC;
-- DISTINCT ON (category)：每个 category 只保留第一行
-- 与 ORDER BY category, downloads DESC 配合：
--   先按 category 分组，再按 downloads 排序，取下载量最高的那行

    category,
    COUNT(*)                                                        AS total,
    SUM(CASE WHEN is_maintained = TRUE  THEN 1 ELSE 0 END)          AS active,
    SUM(CASE WHEN is_maintained = FALSE THEN 1 ELSE 0 END)          AS abandoned,
    ROUND(
        100.0 * SUM(CASE WHEN is_maintained = FALSE THEN 1 ELSE 0 END)
              / COUNT(*), 1
    )                                                               AS abandon_pct
FROM packages
GROUP BY category
ORDER BY abandon_pct DESC, total DESC;
-- CASE WHEN 条件求和 = 透视表的核心手法
-- 100.0 * ... / COUNT(*)：避免整数除法，结果保留小数

8.6. Q4：下载量分层（数据分桶，理解分布）

DB="$HOME/duckdb/emacs_packages.duckdb"

    CASE
        WHEN downloads >= 1000000 THEN '🔥 百万级（≥100万）'
        WHEN downloads >= 500000  THEN '⭐ 热门（50-100万）'
        WHEN downloads >= 200000  THEN '📦 常用（20-50万）'
        ELSE                           '🌱 小众（<20万）'
    END                                                AS tier,
    COUNT(*)                                           AS count,
    STRING_AGG(name, ' / ' ORDER BY downloads DESC)    AS packages
FROM packages
GROUP BY tier
ORDER BY MIN(downloads) DESC;
-- CASE WHEN 创建"计算列"，把连续数值离散化为分层标签
-- GROUP BY 可以使用计算列（tier）

FROM packages
GROUP BY author

LIMIT 8;

11.3. 9.1 CTE（公共表表达式）

CTE 解决的问题：把嵌套子查询拆成有名字的逻辑步骤，让 SQL 可读如代码。 

DB="$HOME/duckdb/emacs_packages.duckdb"
duckdb "$DB" <<'SQL'
-- 没有 CTE 的写法（难读，容易出错）
-- SELECT * FROM (SELECT category, COUNT(*) cnt FROM packages GROUP BY category) t WHERE cnt > 2;

-- 用 CTE 的清晰写法
WITH
category_stats AS (                            -- CTE 1：分类统计
    SELECT
        category,
        COUNT(*)       AS pkg_count,
        SUM(downloads) AS total_downloads
    FROM packages
    GROUP BY category
),
high_volume AS (                               -- CTE 2：筛选高量分类
    SELECT *
    FROM category_stats
    WHERE pkg_count >= 3
)
SELECT
    category,
    pkg_count,
    total_downloads,
    ROUND(100.0 * total_downloads / SUM(total_downloads) OVER (), 1) AS share_pct
FROM high_volume
ORDER BY total_downloads DESC;
-- WITH 子句后的查询可以像表一样引用每个 CTE
-- 多个 CTE 用逗号分隔
SQL

11.4. 9.2 窗口函数：全局排名（RANK / ROW_NUMBER）

窗口函数解决的问题：在不合并行的前提下，为每行计算"相对于其他行"的统计值。 

DB="$HOME/duckdb/emacs_packages.duckdb"
duckdb "$DB" <<'SQL'
SELECT
    name,
    category,
    downloads,
    ROW_NUMBER() OVER (ORDER BY downloads DESC) AS global_row_num,
    RANK()       OVER (ORDER BY downloads DESC) AS global_rank,
    DENSE_RANK() OVER (ORDER BY downloads DESC) AS global_dense_rank
FROM packages
ORDER BY downloads DESC
LIMIT 10;
-- ROW_NUMBER()：1, 2, 3, 4...（无并列）
-- RANK()      ：1, 2, 2, 4...（并列跳号）
-- DENSE_RANK()：1, 2, 2, 3...（并列不跳号）
SQL

11.10. 窗口函数语法结构


函数名() OVER (
    [PARTITION BY 分组列]        -- 在哪个范围内计算（可选）
    [ORDER BY 排序列 DESC]        -- 如何排序（可选）
    [ROWS/RANGE BETWEEN ...]      -- 滑动窗口范围（高级，可选）
)

常用窗口函数速查：
  ROW_NUMBER()      行号（无并列）
  RANK()            排名（并列跳号）
  DENSE_RANK()      排名（并列不跳号）
  SUM(col)          组内累计/总计
  AVG(col)          组内平均
  MIN(col)          组内最小
  MAX(col)          组内最大
  LAG(col, n)       当前行前 n 行的值
  LEAD(col, n)      当前行后 n 行的值
  FIRST_VALUE(col)  组内第一行的值
  PERCENT_RANK()    百分位排名（0~1）

11.11. 常见错误

错误 原因
窗口函数写在 WHERE 里报错 窗口函数不能用于 WHERE，用 CTE 包一层再过滤
PARTITION BY 和 GROUP BY 混淆 GROUP BY 合并行，PARTITION BY 保留行但划定计算范围
CTE 中定义但未使用 DuckDB 会优化掉，但写了未用是逻辑问题，建议删除

13.2. 通用 DuckDB 数据分析模板

-- ════════════════════════════════════════════════════════
-- DuckDB 通用数据分析模板 v1.0
-- 替换：<TABLE>  <ID_COL>  <GROUP_COL>  <VALUE_COL>  <DATE_COL>
-- ════════════════════════════════════════════════════════

-- ── Step 0: 探索数据结构 ────────────────────────────────
DESCRIBE <TABLE>;
SELECT * FROM <TABLE> LIMIT 5;

-- ── Step 1: 数据概况 ────────────────────────────────────
SELECT
    COUNT(*)                      AS total_rows,
    COUNT(DISTINCT <GROUP_COL>)   AS unique_groups,
    MIN(<VALUE_COL>)              AS min_value,
    MAX(<VALUE_COL>)              AS max_value,
    ROUND(AVG(<VALUE_COL>), 2)    AS avg_value,
    -- 检查 NULL
    COUNT(*) - COUNT(<VALUE_COL>) AS null_count
FROM <TABLE>;

-- ── Step 2: 分组统计 ────────────────────────────────────
SELECT
    <GROUP_COL>,
    COUNT(*)                   AS count,
    SUM(<VALUE_COL>)           AS total,
    ROUND(AVG(<VALUE_COL>), 2) AS avg_val,
    MAX(<VALUE_COL>)           AS max_val
FROM <TABLE>
GROUP BY <GROUP_COL>
HAVING COUNT(*) >= 2
ORDER BY total DESC;

-- ── Step 3: 时间趋势（如有日期列）──────────────────────
SELECT
    EXTRACT(year FROM <DATE_COL>)::INTEGER AS year,
    COUNT(*)                               AS count,
    SUM(<VALUE_COL>)                       AS total
FROM <TABLE>
GROUP BY year
ORDER BY year;

-- ── Step 4: TOP N 列表 ──────────────────────────────────
SELECT
    *,
    RANK() OVER (ORDER BY <VALUE_COL> DESC) AS global_rank
FROM <TABLE>
ORDER BY <VALUE_COL> DESC
LIMIT 10;

-- ── Step 5: 组内 TOP N ──────────────────────────────────
WITH ranked AS (
    SELECT *,
        ROW_NUMBER() OVER (PARTITION BY <GROUP_COL>
                           ORDER BY <VALUE_COL> DESC) AS rn
    FROM <TABLE>
)
SELECT * FROM ranked WHERE rn <= 3
ORDER BY <GROUP_COL>, rn;

-- ── Step 6: 导出结果 ────────────────────────────────────
COPY (
    SELECT * FROM <TABLE>
    ORDER BY <VALUE_COL> DESC
) TO 'output_analysis.csv' (FORMAT CSV, HEADER TRUE);

15.4.2. 练习 9：全局排名 + 百分位

DB="$HOME/duckdb/emacs_packages.duckdb"
duckdb "$DB" <<'SQL'
SELECT
    name,
    downloads,
    RANK()                                                     AS dl_rank,

SQL

15.4.3. 练习 11：CTE + 组内均值过滤

DB="$HOME/duckdb/emacs_packages.duckdb"
duckdb "$DB" <<'SQL'
WITH cat_avg AS (
    SELECT
        category,
        AVG(downloads) AS avg_dl
    FROM packages
    GROUP BY category
)
SELECT
    p.name,
    p.category,
    p.downloads,
    ROUND(a.avg_dl, 0) AS category_avg,
    p.downloads - ROUND(a.avg_dl, 0) AS above_avg_by
FROM packages p
JOIN cat_avg a ON p.category = a.category
WHERE p.downloads > a.avg_dl
ORDER BY p.category, p.downloads DESC;
SQL
