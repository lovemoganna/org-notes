* 一句话
 
DuckDB 负责把数据查出来；本体建模负责把数据背后的“东西、属性、关系”说清楚。
 
这不是给 SQL 加一层玄学，而是把你已经会写的表、行、列、JOIN、CTE，整理成更稳定的知识网络。
* 为什么要放进 org-roam
 
配置目录里的教程适合“按章节学习”。org-roam 里的节点适合“反复想起、反复连接、慢慢内化”。
 
以后你看到一个 SQL 模型，可以从这个节点开始问：
 
- 这里有哪些 =Class=？
- 哪些行可以看成 =Individual=？
- 哪些列只是 =DataProperty=？
- 哪些外键或 JOIN 暗示 =ObjectProperty=？
- 哪些 CTE 只是临时查询，哪些已经像领域概念？
* 核心映射
 
| DuckDB 里的东西 | 本体里的说法            | 人话解释                             |
|-----------------+-------------------------+--------------------------------------|
| 表              | =Class= 的线索          | 表名常提示“一类东西”，但表本身不是类 |
| 行              | =Individual=            | 一条具体记录，一个具体对象           |
| 普通列          | =DataProperty=          | 对象身上的一个值                     |
| 外键列          | =ObjectProperty= 的线索 | 它常常表示两个对象有关               |
| JOIN            | 关系查询                | 通过列相等把关系查出来               |
| CTE/View        | 概念视图                | 给一组查询结果起名字                 |
* 学生表例子
 
以 =students/classes= 为例：
 
#+begin_example
  student_1 type Student
  student_1 hasName "小明"
  student_1 hasScore 90
  student_1 belongsToClass class_1
  class_1 type ClassGroup
  class_1 hasName "一班"
#+end_example
 
这里最值得记住的是：
 
#+begin_quote
=class_id= 在数据库里是一个整数；在本体里它背后的意思是 =belongsToClass=。
#+end_quote
* 卡片：Class
 
=Class= 是“一类东西”。
 
在 DuckDB 学生例子里：
 
#+begin_example
  Student
  ClassGroup
  ScoreBand
#+end_example
 
注意：=students= 是表名，=Student= 才是概念名。表负责存放学生记录，概念负责说明“学生是什么”。
* 卡片：Individual
 
=Individual= 是一个具体东西。
 
在学生表里，一行记录通常可以变成一个个体：
 
#+begin_example
  student_1
  student_2
  class_1
  class_2
#+end_example
 
如果你能指着它说“就是这个学生、这个班级”，它就很像一个 =Individual=。
* 卡片：DataProperty
 
=DataProperty= 是“对象到值”。
 
#+begin_example
  student_1 hasName "小明"
  student_1 hasGender "M"
  student_1 hasScore 90
#+end_example
 
判断方法：右边如果是数字、字符串、日期这类值，它通常是 =DataProperty=。
* 卡片：ObjectProperty
 
=ObjectProperty= 是“对象到对象”。
 
#+begin_example
  student_1 belongsToClass class_1
  student_2 belongsToClass class_1
#+end_example
 
判断方法：右边如果也是一个对象，而不是普通值，它通常是 =ObjectProperty=。
 
这个概念很适合从 JOIN 里发现：
 
#+begin_src sql :eval no
  SELECT students.name, classes.name
  FROM students
  INNER JOIN classes
    ON students.class_id = classes.id;
#+end_src
 
SQL 用列相等连接表；本体给这个连接起名字。
* 卡片：CTE 与派生概念
 
CTE 可以帮你发现“正在变成概念的查询”。
 
#+begin_src sql :eval no
  WITH high_score_students AS (
    SELECT name, score
    FROM students
    WHERE score >= 85
  )
  SELECT name, score
  FROM high_score_students;
#+end_src
 
如果 =high_score_students= 只是这一次查询方便阅读，它还只是 CTE。
 
如果“高分学生”会反复出现在你的分析、报告和讨论里，它就可能值得变成 =HighScoreStudent=。
* 复习问题
 
每次学完一段 DuckDB，可以拿这几个问题检查是否真的内化：
 
1. 这张表背后对应哪类东西？
2. 一行记录能不能变成一个具体对象？
3. 哪些列只是值？
4. 哪些列暗示另一个对象？
5. 这个 JOIN 的关系名应该叫什么？
6. 这个 CTE 是临时查询，还是稳定概念？
* 下一步
 
下次学新的 DuckDB 文件时，不要急着只看 SQL 结果。顺手补一句：
 
#+begin_quote
如果把这个 SQL 当成知识，它背后的对象和关系是什么？
#+end_quote
