* DuckDB Keywords | Cast
 
** Overview
 
*** 关键字 CAST：类型转换与表关联
=CAST= 用于转换数据类型。它不负责关联数据表。 =JOIN ... ON= 负责比较关联字段, =WHERE= 负责筛选记录。
** Content
*** CAST 常见用法
 
| 写法                   | 作用       | 示例                     |
|------------------------+------------+--------------------------|
| =CAST(x AS VARCHAR)=   | 转为字符串 | =123= 转为 ='123'=       |
| =CAST(x AS INTEGER)=   | 转为整数   | ='123'= 转为 =123=       |
| =CAST(x AS DOUBLE)=    | 转为浮点数 | ='12.5'= 转为 =12.5=     |
| =CAST(x AS DATE)=      | 转为日期   | ='2026-10-11'= 转为日期  |
| =CAST(x AS TIMESTAMP)= | 转为时间戳 | 日期时间字符串转为时间戳 |
*** 当前查询中的 CAST
 
目标：查询 UID 为 =784231905= 的法币交易，并返回用户名称、订单号、金额和状态。
 
#+begin_src sql
  -- 目标：查找 UID 为 784231905 的法币交易
 
  SELECT
      u.user_name,       -- 用户名称
      f.fiat_order_id,   -- 法币订单号
      f.amount,          -- 交易金额
      f.status           -- 交易状态
 
  FROM main.users AS u
 
  -- 通过共同的 uid 建立关联
  JOIN main.fiat_transactions AS f
      ON CAST(u.uid AS VARCHAR) = CAST(f.uid AS VARCHAR)
 
  -- 只查询指定用户
  WHERE CAST(u.uid AS VARCHAR) = '784231905'
 
  -- 按订单号排列
  ORDER BY f.fiat_order_id;
#+end_src
 
| 位置                   | 作用                                          |
|------------------------+-----------------------------------------------|
| =JOIN= 中的两个 =CAST= | 将两张表的 =uid= 转为字符串，再比较是否相同。 |
| =WHERE= 中的 =CAST=    | 将 =users.uid= 转为字符串，再筛选指定用户。   |
 
例如，假设 =users.uid= 是 =BIGINT=, 值为 =784231905 。 而 =fiat_transactions.uid= 是 =VARCHAR=, 值为 =784231905=.
 
两个字段的类型不同。可以通过 =CAST= 转成相同类型，再比较其值。
 
#+begin_src sql
  CAST(u.uid AS VARCHAR) = CAST(f.uid AS VARCHAR)
#+end_src
 
以上仅为示例，不代表实际表结构。
*** 先检查 UID 的真实类型
 
直接查看字段定义，不需要先查询交易记录。
 
#+begin_src sql
  -- 查看两个表中 uid 字段的实际声明类型
  SELECT
      table_name,
      column_name,
      data_type
  FROM information_schema.columns
  WHERE table_schema = 'main'
    AND table_name IN ('users', 'fiat_transactions')
    AND column_name = 'uid';
#+end_src
 
也可以使用 =typeof()= 检查字段类型。
 
#+begin_src sql
  -- 检查 users 表的 uid 类型
  SELECT typeof(uid) AS uid_type
  FROM main.users
  LIMIT 1;
 
  -- 检查 fiat_transactions 表的 uid 类型
  SELECT typeof(uid) AS uid_type
  FROM main.fiat_transactions
  LIMIT 1;
#+end_src
 
注意：=typeof(uid)= 查询至少需要返回一行数据。空表不会返回结果。检查字段定义时，优先使用 =information_schema.columns=。
*** 如何判断是否需要 CAST
 
| 情况             | 处理方式                           |
|------------------+------------------------------------|
| UID 类型相同     | 通常无需 =CAST=，可直接比较。      |
| UID 类型不同     | 先核对字段含义，再统一比较类型。   |
| UID 存在格式差异 | 先检查原始值，不能只依靠类型转换。 |
 
类型转换可能增加计算开销，也可能改变比较结果。
UID 是用户标识符。若原始值存在前导零等格式差异，转换类型不一定能正确关联。 =CAST= 不是数据清洗工具。
*待确认：* 两张表的 =uid= 实际类型、原始值格式，以及上述 SQL 的执行结果，尚未经过验证。

1.1. Overview

1.1.1. 关键字 CAST：类型转换与表关联

CAST 用于转换数据类型。它不负责关联数据表。 JOIN ... ON 负责比较关联字段, WHERE 负责筛选记录。

1.2. Content

1.2.1. CAST 常见用法

写法 作用 示例
CAST(x AS VARCHAR) 转为字符串 123 转为 '123'
CAST(x AS INTEGER) 转为整数 '123' 转为 123
CAST(x AS DOUBLE) 转为浮点数 '12.5' 转为 12.5
CAST(x AS DATE) 转为日期 '2026-10-11' 转为日期
CAST(x AS TIMESTAMP) 转为时间戳 日期时间字符串转为时间戳

1.2.2. 当前查询中的 CAST

目标：查询 UID 为 784231905 的法币交易，并返回用户名称、订单号、金额和状态。 

-- 目标：查找 UID 为 784231905 的法币交易

SELECT
    u.user_name,       -- 用户名称
    f.fiat_order_id,   -- 法币订单号
    f.amount,          -- 交易金额
    f.status           -- 交易状态

FROM main.users AS u

-- 通过共同的 uid 建立关联
JOIN main.fiat_transactions AS f
    ON CAST(u.uid AS VARCHAR) = CAST(f.uid AS VARCHAR)

-- 只查询指定用户
WHERE CAST(u.uid AS VARCHAR) = '784231905'

-- 按订单号排列
ORDER BY f.fiat_order_id;
位置 作用
JOIN 中的两个 CAST 将两张表的 uid 转为字符串，再比较是否相同。
WHERE 中的 CAST 将 users.uid 转为字符串，再筛选指定用户。

例如，假设 users.uid 是 BIGINT, 值为 784231905 。 而 =fiat_transactions.uid 是 VARCHAR, 值为 784231905.

两个字段的类型不同。可以通过 CAST 转成相同类型，再比较其值。 

CAST(u.uid AS VARCHAR) = CAST(f.uid AS VARCHAR)

以上仅为示例，不代表实际表结构。

1.2.3. 先检查 UID 的真实类型

直接查看字段定义，不需要先查询交易记录。 

-- 查看两个表中 uid 字段的实际声明类型
SELECT
    table_name,
    column_name,
    data_type
FROM information_schema.columns
WHERE table_schema = 'main'
  AND table_name IN ('users', 'fiat_transactions')
  AND column_name = 'uid';

也可以使用 typeof() 检查字段类型。 

-- 检查 users 表的 uid 类型
SELECT typeof(uid) AS uid_type
FROM main.users
LIMIT 1;

-- 检查 fiat_transactions 表的 uid 类型
SELECT typeof(uid) AS uid_type
FROM main.fiat_transactions
LIMIT 1;

注意：typeof(uid) 查询至少需要返回一行数据。空表不会返回结果。检查字段定义时，优先使用 information_schema.columns。

情况 处理方式
UID 类型相同 通常无需 CAST，可直接比较。
UID 类型不同 先核对字段含义，再统一比较类型。
