* 1. 贯穿模型
 
贯穿案例：从订单表中过滤指定国家、状态和最低金额，再汇总并生成报告。
 
#+name: orders
| uid | country | amount | status |
|-----+---------+--------+--------|
| u01 | TR      |    120 | paid   |
| u02 | TR      |     80 | refund |
| u01 | TR      |     30 | paid   |
| u03 | US      |    200 | paid   |
| u04 | TR      |    300 | paid   |
 
固定逻辑：过滤、汇总、报告、断言。
 
可变参数：=country=、=status=、=min_amount=。固定逻辑只写一次，变化从 =:var= / =#+call:= 传入。
* 2. Noweb：组合源码，而不是复制源码
 
Noweb 解决“把多个代码片段组合成一段最终源码”的问题。
 
#+name: normalize-number
#+begin_src python :var value=0 :results silent
  value = float(value)
#+end_src
 
#+name: apply-tax
#+begin_src python :var value=0 tax_rate=0 :results silent
  value = value * (1 + tax_rate)
#+end_src
 
#+name: noweb-price
#+begin_src python :var value=100 tax_rate=0.08 :noweb yes :results value replace
  <<normalize-number>>
  <<apply-tax>>
  return round(value, 2)
#+end_src
 
#+results: noweb-price
: 108.0
 
执行前先按 =C-c C-v v=。你应该看到接近下面的展开结果：
 
#+begin_example
  value = 100
  # Babel 会按 backend 方式注入 tax_rate 等变量
  value = float(value)
  value = value * (1 + tax_rate)
  return round(value, 2)
#+end_example
 
这两个片段本身也可以单独执行：Header 中给了安全默认变量，=:results silent= 不往文档写结果。它们被 Noweb 展开时只展开 Block body，片段自己的 =:var= 不会替调用方注入变量。最终执行 Block 仍必须显式提供 =value=、=tax_rate=。官方文档也明确说明 Noweb 引用不会自动继承被引用 Block 的变量绑定。
* 3. Session：共享状态要显式
 
默认使用无状态 Block；它更容易单独重跑、缓存和回归。
 
只有确实需要长生命周期状态时才用 Session。
 
#+name: session-init
#+begin_src python :session tutorial-session :results output replace
  x = 10
  print(x)
#+end_src
 
#+results: session-init
: 10
 
#+name: session-use
#+begin_src python :session tutorial-session :results output replace
  x += 5
  print(x)
#+end_src
 
#+results: session-use
: 15
 
这两个 Block 有顺序依赖：单独运行第二个 Block 可能失败。这正是 Session 的成本。
 
非 Session 的 =:results value= 和 Session 的 Python 返回方式也不同：前者可显式 =return=；Session 更适合让最后一个顶层表达式产生值，避免在顶层直接写 =return=。
* 4. Cache：只缓存纯计算
 
#+name: pure-square
#+begin_src python :var n=12 :cache yes :results value replace
  return n * n
#+end_src
 
#+results: pure-square
: 144
 
适合缓存：输入固定、输出确定、没有外部状态的纯计算。
 
不适合直接缓存：远程 API、实时文件状态、随机数、有副作用的 Session。
 
还有一个容易踩的坑：Org 判断 =:cache yes= 是否命中时，会计算代码与参数的 SHA1，但官方文档明确说明这个变化检测不会展开 Noweb 引用。因此一个“看起来纯”的缓存 Block 如果依赖 =<<fragment>>=，fragment 改了，缓存键不一定跟着变。实际工程里不要默认把 =Noweb + cache= 当成安全组合；要么关闭缓存，要么把依赖版本显式变成参数，并为该组合单独做回归。
* 5. Tangle：Org 才是 Source of Truth
 
Tangle 把 Org 中的代码抽取为正常源码文件。
 
下面会创建 =org-babel-build/generated_report.py=。这是 WRITE 操作，所以示例固定写入独立构建目录；=:mkdirp yes= 允许 Tangle 创建父目录。标准 =C-c C-v t= 会直接写目标文件，并不会先给你 Diff。若目标是已有项目源码，不要把“先看 Diff”当成 Tangle 自带能力：先 Tangle 到 staging/build 路径再比较，或确保目标受版本控制后再写。
 
#+name: report-function
#+begin_src python :results silent
  def render_report(summary) -> str:
      count, total = summary
      return f"count={int(count)}, total={float(total):.2f}"
#+end_src
 
#+name: report-program
#+begin_src python :noweb yes :results output replace :tangle org-babel-build/generated_report.py :mkdirp yes :comments link
  <<report-function>>
 
  if __name__ == "__main__":
      sample_summary = [2, 420.0]
      print(render_report(sample_summary))
#+end_src
 
#+results: report-program
: count=2, total=420.00
 
运行 =C-c C-v t= 后，再从命令行验证：
 
#+name: run-tangled-file
#+begin_src sh :results output replace
  python3 org-babel-build/generated_report.py 2>/dev/null || python org-babel-build/generated_report.py
#+end_src
 
#+results: run-tangled-file
: count=2, total=420.00
 
如果 =org-babel-build/generated_report.py= 报错，长期修复路径是：
 
#+begin_example
  Runtime Error
  → org-babel-build/generated_report.py 定位错误
  → 回到对应 Org Block
  → 修改 Org
  → Retangle
  → Execute
#+end_example
 
不要长期直接维护生成文件。
* 6. Library of Babel：跨文件复用
当某个 Block 已稳定并被多个 Org 文件复用，把它放入公共 Org 文件，例如 =babel/core.org=：
 
#+begin_example
  ,#+name: percentage
  ,#+begin_src python :var part=1 total=1 :results value replace
  return 0 if total == 0 else round(part / total * 100, 2)
  ,#+end_src
#+end_example
 
然后在 Emacs 中 ingest：
 
#+begin_example
  (org-babel-lob-ingest "babel/core.org")
#+end_example
 
之后其他 Org 文件可直接：
 
#+begin_example
  ,#+call: percentage(part=25, total=200)
#+end_example
 
预期：12.5。
 
为了让这一节本身也能一键验证，下面给一个完全隔离的 E2E：它只在系统临时目录创建 Library 文件，ingest、调用、断言后立即删除，不污染项目目录。
 
#+name: lob-self-contained-demo
#+begin_src emacs-lisp :results value replace
  (let* ((dir (make-temp-file "org-lob-demo-" t))
         (lib (expand-file-name "core.org" dir))
         (old-library org-babel-library-of-babel))
    (unwind-protect
        (progn
          (with-temp-file lib
            (insert "#+name: percentage\n")
            (insert "#+begin_src python :var part=1 total=1 :results value replace\n")
            (insert "return 0 if total == 0 else round(part / total * 100, 2)\n")
            (insert "#+end_src\n"))
          (org-babel-lob-ingest lib)
          (let ((actual (org-babel-ref-resolve "percentage(part=25,total=200)")))
            (unless (= actual 12.5)
              (error "Library of Babel expected 12.5, got %S" actual))
            actual))
      (setq org-babel-library-of-babel old-library)
      (delete-directory dir t)))
#+end_src
 
#+results: lob-self-contained-demo
: 12.5
 
复用优先顺序：已有 Block → 扩展已有 Block → 新增通用 Block → 最后才复制代码。
* 7. 完整案例：订单分析流水线
现在把 01 模块的执行基础与本文件的组合机制串起来。
** 7.1 Parameters
 
| Variable   | Meaning  | Default | Example |
|------------+----------+---------+---------|
| country    | 国家代码 | TR      | US      |
| status     | 订单状态 | paid    | refund  |
| min_amount | 最低金额 | 100     | 200     |
** 7.2 Block Contract：filter-orders
 
Input Contract：
 
- =rows=：订单二维列表；每行至少 4 列；
- 第 2 列 country；
- 第 3 列 amount，可转 float；
- 第 4 列 status；
- =min_amount >= 0=。
 
Execution Contract：无 Session、无网络、无文件写入，PURE。
 
Output Contract：只返回满足国家、状态、金额阈值的订单。
 
Assertions：
 
- 所有返回行的国家等于 =country=；
- 状态等于 =status=；
- 金额不低于 =min_amount=。
 
#+name: filter-orders
#+begin_src python :var rows=orders country="TR" status="paid" min_amount=100 :results value table
  threshold = float(min_amount)
  assert threshold >= 0
  assert all(isinstance(row, (list, tuple)) and len(row) >= 4 for row in rows)
  for row in rows:
      float(row[2])
 
  selected = [
      row for row in rows
      if row[1] == country
      and row[3] == status
      and float(row[2]) >= threshold
  ]
  assert all(row[1] == country for row in selected)
  assert all(row[3] == status for row in selected)
  assert all(float(row[2]) >= threshold for row in selected)
  return selected
#+end_src
 
预期结果：
 
#+begin_example
  | u01 | TR | 120 | paid |
  | u04 | TR | 300 | paid |
#+end_example
** 7.3 Block Contract：summarize-orders
 
Input：经过过滤的订单行。
 
Output：单行二维列表，两个元素依次为 =count= 与 =total=。
 
Assertions：count 非负；total 非负。
 
#+name: summarize-orders
#+begin_src python :var rows=filter-orders(country="TR", status="paid", min_amount=100) :results value table
  count = len(rows)
  total = round(sum(float(row[2]) for row in rows), 2)
  assert count >= 0
  assert total >= 0
  return [[count, total]]
#+end_src
 
预期：
 
#+begin_example
  | 2 | 420.0 |
#+end_example
** 7.4 Minimal Call
 
正常使用时只改这一行：
 
#+call: summarize-orders(rows=filter-orders(country="TR", status="paid", min_amount=100))
 
换成美国订单：
 
#+call: summarize-orders(rows=filter-orders(country="US", status="paid", min_amount=100))
 
预期：1 笔，200。
** 7.5 报告文本
 
#+name: order-report
#+begin_src python :var summary=summarize-orders() :results value replace
  count, total = summary[0]
  return f"selected orders: count={int(count)}, total={float(total):.2f}"
#+end_src
 
#+results: order-report
: selected orders: count=2, total=420.00
 
这里故意不把 =TR / paid / >=100= 写死进文本。=summary= 可以来自其他筛选条件；如果标签固定而数据可变，就会出现“数字正确、语义错误”。需要带条件的报告时，让条件和结果来自同一个调用契约，而不是手写标签。
 
依赖 DAG：
 
#+begin_example
  orders + country + status + min_amount
                ↓
          filter-orders
                ↓
        summarize-orders
           ┌────┴────┐
           ↓         ↓
         table   order-report
                     ↓
                   scalar
#+end_example
* 8. Golden Regression：修当前问题不能破坏历史能力
 
维护四个稳定 Case：
 
| Case | Input            | Expected           |
|------+------------------+--------------------|
| G1   | TR, paid, >=100  | u01(120), u04(300) |
| G2   | US, paid, >=100  | u03(200)           |
| G3   | TR, refund, >=50 | u02(80)            |
| G4   | TR, paid, >=120  | u01(120), u04(300) |
 
用一个断言 Block 一次验证：
 
#+name: golden-regression
#+begin_src python :var g1=filter-orders(country="TR", status="paid", min_amount=100) :var g2=filter-orders(country="US", status="paid", min_amount=100) :var g3=filter-orders(country="TR", status="refund", min_amount=50) :var g4=filter-orders(country="TR", status="paid", min_amount=120) :results value replace
  assert g1 == [["u01", "TR", 120, "paid"], ["u04", "TR", 300, "paid"]]
  assert g2 == [["u03", "US", 200, "paid"]]
  assert g3 == [["u02", "TR", 80, "refund"]]
  assert g4 == [["u01", "TR", 120, "paid"], ["u04", "TR", 300, "paid"]]
  return "GOLDEN_PASS"
#+end_src
 
#+results: golden-regression
: GOLDEN_PASS
 
这里不复制过滤或汇总算法。Golden Case 直接断言真实 =filter-orders(...)= 的行级输出；=summarize-orders= 由 E2E 的 Full Workflow 单独验证。这样生产 Block 改坏时，测试不会因为复制了同一份错误逻辑而“陪着通过”。
 
延伸：Golden 负责历史行为不退化；完整能力闭包见 [[file:org-babel-03-verification-debugging.html#e2e-matrix][03｜E2E 验证矩阵]]。
* 9. Library、Tangle、Session 应该怎么选
 
| 需求                  | 首选机制               |
|-----------------------+------------------------|
| 同一文档多处复用计算  | #+name + :var / #+call |
| 拼装源码片段          | Noweb                  |
| 多文档共享稳定能力    | Library of Babel       |
| 生成独立 .py/.sh 源码 | Tangle                 |
| 共享解释器状态        | :session               |
| 避免重复执行纯计算    | :cache yes             |
 
不要把所有问题都解决成 Noweb，也不要把所有 Block 都塞进 Session。
* 10. 三层练习
 
| 层级 | 任务                                                               | 验收                                                 |
|------+--------------------------------------------------------------------+------------------------------------------------------|
| L1   | =country="TR", min_amount=100= 改为 =min_amount=200=               | 先预测，再执行                                       |
| L2   | 调用 =filter-orders(country="TR", status="refund", min_amount=50)= | 1 笔、80                                             |
| L3   | 新增 =max_amount=                                                  | 不复制实现；更新 Contract + Golden；只重跑受影响节点 |

3. 2. Noweb：组合源码，而不是复制源码

Noweb 解决“把多个代码片段组合成一段最终源码”的问题。 

value = float(value)

value = value * (1 + tax_rate)

<<normalize-number>>
<<apply-tax>>

执行前先按 C-c C-v v。你应该看到接近下面的展开结果： 


value = 100
# Babel 会按 backend 方式注入 tax_rate 等变量

value = value * (1 + tax_rate)
return round(value, 2)

这两个片段本身也可以单独执行：Header 中给了安全默认变量，:results silent 不往文档写结果。它们被 Noweb 展开时只展开 Block body，片段自己的 :var 不会替调用方注入变量。最终执行 Block 仍必须显式提供 value、tax_rate。官方文档也明确说明 Noweb 引用不会自动继承被引用 Block 的变量绑定。

4. 3. Session：共享状态要显式

默认使用无状态 Block；它更容易单独重跑、缓存和回归。

只有确实需要长生命周期状态时才用 Session。 

x = 10
print(x)


10

x += 5
print(x)


15

这两个 Block 有顺序依赖：单独运行第二个 Block 可能失败。这正是 Session 的成本。

非 Session 的 :results value 和 Session 的 Python 返回方式也不同：前者可显式 return；Session 更适合让最后一个顶层表达式产生值，避免在顶层直接写 return。

5. 4. Cache：只缓存纯计算

return n * n


144

适合缓存：输入固定、输出确定、没有外部状态的纯计算。

不适合直接缓存：远程 API、实时文件状态、随机数、有副作用的 Session。

还有一个容易踩的坑：Org 判断 :cache yes 是否命中时，会计算代码与参数的 SHA1，但官方文档明确说明这个变化检测不会展开 Noweb 引用。因此一个“看起来纯”的缓存 Block 如果依赖 <<fragment>>，fragment 改了，缓存键不一定跟着变。实际工程里不要默认把 Noweb + cache 当成安全组合；要么关闭缓存，要么把依赖版本显式变成参数，并为该组合单独做回归。

6. 5. Tangle：Org 才是 Source of Truth

Tangle 把 Org 中的代码抽取为正常源码文件。

下面会创建 org-babel-build/generated_report.py。这是 WRITE 操作，所以示例固定写入独立构建目录；:mkdirp yes 允许 Tangle 创建父目录。标准 C-c C-v t 会直接写目标文件，并不会先给你 Diff。若目标是已有项目源码，不要把“先看 Diff”当成 Tangle 自带能力：先 Tangle 到 staging/build 路径再比较，或确保目标受版本控制后再写。 

def render_report(summary) -> str:
    count, total = summary
    return f"count={int(count)}, total={float(total):.2f}"

<<report-function>>

if __name__ == "__main__":
    sample_summary = [2, 420.0]
    print(render_report(sample_summary))

运行 C-c C-v t 后，再从命令行验证： 

python3 org-babel-build/generated_report.py 2>/dev/null || python org-babel-build/generated_report.py

如果 org-babel-build/generated_report.py 报错，长期修复路径是： 


Runtime Error
→ org-babel-build/generated_report.py 定位错误
→ 回到对应 Org Block
→ 修改 Org
→ Retangle
→ Execute

不要长期直接维护生成文件。

7. 6. Library of Babel：跨文件复用

当某个 Block 已稳定并被多个 Org 文件复用，把它放入公共 Org 文件，例如 babel/core.org： 


#+name: percentage
#+begin_src python :var part=1 total=1 :results value replace
return 0 if total == 0 else round(part / total * 100, 2)
#+end_src

然后在 Emacs 中 ingest： 


(org-babel-lob-ingest "babel/core.org")

之后其他 Org 文件可直接： 


#+call: percentage(part=25, total=200)

预期：12.5。

为了让这一节本身也能一键验证，下面给一个完全隔离的 E2E：它只在系统临时目录创建 Library 文件，ingest、调用、断言后立即删除，不污染项目目录。 

(let* ((dir (make-temp-file "org-lob-demo-" t))
       (lib (expand-file-name "core.org" dir))
       (old-library org-babel-library-of-babel))
  (unwind-protect
      (progn
        (with-temp-file lib
          (insert "#+name: percentage\n")
          (insert "#+begin_src python :var part=1 total=1 :results value replace\n")
          (insert "return 0 if total == 0 else round(part / total * 100, 2)\n")
          (insert "#+end_src\n"))
        (org-babel-lob-ingest lib)
        (let ((actual (org-babel-ref-resolve "percentage(part=25,total=200)")))
          (unless (= actual 12.5)
            (error "Library of Babel expected 12.5, got %S" actual))
          actual))
    (setq org-babel-library-of-babel old-library)
    (delete-directory dir t)))


12.5

复用优先顺序：已有 Block → 扩展已有 Block → 新增通用 Block → 最后才复制代码。

8.2. 7.2 Block Contract：filter-orders

Input Contract：

  • rows：订单二维列表；每行至少 4 列；
  • 第 2 列 country；
  • 第 3 列 amount，可转 float；
  • 第 4 列 status；
  • min_amount > 0=。

Execution Contract：无 Session、无网络、无文件写入，PURE。

Output Contract：只返回满足国家、状态、金额阈值的订单。

Assertions：

  • 所有返回行的国家等于 country；
  • 状态等于 status；
  • 金额不低于 min_amount。
threshold = float(min_amount)
assert threshold >= 0
assert all(isinstance(row, (list, tuple)) and len(row) >= 4 for row in rows)
for row in rows:
    float(row[2])

selected = [
    row for row in rows
    if row[1] == country
    and row[3] == status
    and float(row[2]) >= threshold
]
assert all(row[1] == country for row in selected)
assert all(row[3] == status for row in selected)
assert all(float(row[2]) >= threshold for row in selected)
return selected

9. 8. Golden Regression：修当前问题不能破坏历史能力

维护四个稳定 Case：

Case Input Expected
G1 TR, paid, >=100 u01(120), u04(300)
G2 US, paid, >=100 u03(200)
G3 TR, refund, >=50 u02(80)
G4 TR, paid, >=120 u01(120), u04(300)

用一个断言 Block 一次验证： 

assert g1 == [["u01", "TR", 120, "paid"], ["u04", "TR", 300, "paid"]]
assert g2 == [["u03", "US", 200, "paid"]]
assert g3 == [["u02", "TR", 80, "refund"]]
assert g4 == [["u01", "TR", 120, "paid"], ["u04", "TR", 300, "paid"]]
return "GOLDEN_PASS"


GOLDEN_PASS

这里不复制过滤或汇总算法。Golden Case 直接断言真实 filter-orders(...) 的行级输出；summarize-orders 由 E2E 的 Full Workflow 单独验证。这样生产 Block 改坏时，测试不会因为复制了同一份错误逻辑而“陪着通过”。

延伸：Golden 负责历史行为不退化；完整能力闭包见 03｜E2E 验证矩阵。

10. 9. Library、Tangle、Session 应该怎么选

需求 首选机制
同一文档多处复用计算 #+name + :var / #+call
拼装源码片段 Noweb
多文档共享稳定能力 Library of Babel
生成独立 .py/.sh 源码 Tangle
