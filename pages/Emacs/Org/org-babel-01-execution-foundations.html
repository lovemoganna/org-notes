* 怎么使用这组三模块
第一次按顺序执行；之后日常只改参数和最小调用。主链：
 
#+begin_example
  数据 → 参数 → Block → 调用/组合 → 执行 → 结果 → Contract → Tangle → 回归
#+end_example
 
| 动作                 | Org 快捷键 |
|----------------------+------------|
| 执行当前 Block       | C-c C-c    |
| 查看 Expanded Source | C-c C-v v  |
| 执行整个 Buffer      | C-c C-v b  |
| 执行当前 Subtree     | C-c C-v s  |
| Tangle               | C-c C-v t  |
| 跳到命名 Block       | C-c C-v g  |
| 跳到命名结果         | C-c C-v r  |
| 打开结果             | C-c C-o    |
* 环境与配置
** 最小运行条件
需要：
- Emacs；
- Org；
- Python 3；
- PATH 中可直接调用的 POSIX =sh=（若要运行 Shell 示例）。Windows 可来自 Git Bash、MSYS2 或 WSL。
 
本文的可执行 Shell Block 一律写成 =#+begin_src sh=，不写泛化的 =#+begin_src shell=。配置里的 =(shell . t)= 只是加载 =ob-shell.el=；Block 的语言名才决定实际执行器。Org 当前 =ob-shell= 会为 =sh/bash/zsh/...= 建立执行入口，并在执行 =sh= Block 时把 =shell-file-name= 绑定到 =sh=。Windows 的默认系统 Shell 可能采用 cmd/DOS 语义，因此对依赖 =printf=、=||= 等 POSIX 语法的教程，显式写 =sh= 才能锁定 Runtime Contract。
 
先在命令行确认 Runtime：
 
#+name: env-shell
#+begin_src sh
  printf 'shell=%s\n' "$SHELL"
  python3 --version 2>/dev/null || python --version
#+end_src
 
#+results: env-shell
: shell=/c/v/Emacs/libexec/emacs/31.1/x86_64-w64-mingw32/cmdproxy.exe
: Python 3.12.14
 
Windows 如果只有 =python.exe=，把后文的 Python command 改为 =python=。
** Babel 配置
把下面配置放入 Emacs 配置后重启，或直接 =M-x eval-buffer=。
 
#+name: babel-config
#+begin_src emacs-lisp :results value verbatim
  (require 'org)
  (require 'ob-python)
  (require 'ob-shell)
 
  (org-babel-do-load-languages
   'org-babel-load-languages
   '((emacs-lisp . t)
     (python . t)
     (shell . t)))
 
  (setq org-babel-python-command
        (or (executable-find "python3")
            (executable-find "python")
            (error "Python runtime missing")))
 
  (list
   (emacs-version)
   (org-version)
   org-babel-python-command)
#+end_src
 
#+results: babel-config
: ("GNU Emacs 31.1 (build 2, x86_64-w64-mingw32)
:  of 2026-08-24" "10.0-pre" "c:/msys64/usr/bin/python3.exe")
 
交互使用时保留 Org 默认执行确认；配套 batch verifier 只在隔离副本中临时关闭确认。不要对来源不明的 Org 文件运行整 Buffer、Subtree 或 batch E2E：Babel 执行的是本机代码，不是安全沙箱。
** Reproducibility
环境变化会直接改变 Babel 行为。先记录版本，不要把环境漂移误诊成代码错误。
 
#+name: environment-record
#+begin_src emacs-lisp :results value table
  (list
   (list "emacs" emacs-version)
   (list "org" (org-version))
   (list "system" (symbol-name system-type))
   (list "python-command" org-babel-python-command))
#+end_src
 
#+results: environment-record
| emacs          | 31.1                          |
| org            | 10.0-pre                      |
| system         | windows-nt                    |
| python-command | c:/msys64/usr/bin/python3.exe |
* 先把最小执行链跑通
** Python：=:results value=
非 Session 的 Python =value= 模式可以显式 =return=:
 
#+name: python-base
#+begin_src python :results value replace
  return 2 + 3
#+end_src
 
#+results: python-base
: 5
 
Contract：结果必须等于 5。
** Python：=:results output=
=output= 收集 stdout，不读取最终表达式值:
 
#+name: python-output
#+begin_src python :results output replace
  print("alpha")
  print("beta")
#+end_src
 
#+results: python-output
: alpha
: beta
** POSIX sh
 
#+name: shell-base
#+begin_src sh :results output replace
  printf '%s\n' "babel-shell-ok"
#+end_src
 
#+results: shell-base
: babel-shell-ok
 
执行成功只说明 Runtime 能跑。后面还要验证结果。
* Header Args：真正控制执行行为的接口
常用 Header Args：
 
| 参数     | 用途                              |
|----------+-----------------------------------|
| :var     | 输入变量                          |
| :results | 结果采集、类型、格式、写入策略    |
| :session | 是否共享解释器状态                |
| :dir     | 工作目录                          |
| :file    | 文件结果路径                      |
| :exports | 导出 code / results / both / none |
| :cache   | 按输入与代码 hash 复用结果        |
| :noweb   | 是否展开 Noweb 引用               |
| :tangle  | 是否抽取到源码文件                |
 
Header Args 可以定义在全局、文件、Subtree、Block 和 =#+call:= 层级。越局部的设置优先级越高。
** 用实际结果验证覆盖关系
 
文件顶部给 Python 设置了 =:results value replace=.下面在 Block 层覆盖成 =output=:
 
#+name: local-header-wins
#+begin_src python :results output replace
  print("local-output")
#+end_src
 
#+results: local-header-wins
: local-output
 
想知道 Babel 最终究竟执行什么，不猜：把光标放到 Block 内，运行 =C-c C-v v=.
 
延伸：Header Args 在工程阶段会直接控制 [[file:org-babel-02-composition-engineering.html#section-c53193e0af99][Session]]、[[file:org-babel-02-composition-engineering.html#section-6ffb2fed9911][Cache]] 与 [[file:org-babel-02-composition-engineering.html#section-12f6aff46ab5][Tangle]]。
* 参数传递：把变化从代码中抽出来
 
** 标量参数
#+name: price-total
#+begin_src python :var subtotal=100 tax_rate=0.08 discount=10 :results value replace
  return round(subtotal * (1 + tax_rate) - discount, 2)
#+end_src
 
#+results: price-total
: 98.0
 
同一段实现换参数：
 
#+call: price-total(subtotal=50, tax_rate=0.2, discount=5)
 
#+results: 
: 55.0
 
预期：55.0。
 
如果这一条 =#+call:= 在你的 Emacs 中报参数数量错误，先不要改 Python。跳到 [[file:org-babel-03-verification-debugging.html#section-0d0fb1d33f89][验证与排错模块：#+call / ob-async 兼容诊断]]。
** 多参数不是“多复制几份代码”
下面只有一个实现：
 
#+name: threshold-check
#+begin_src python :var amount=120 threshold=100 :results value replace
  return amount >= threshold
#+end_src
 
#+results: threshold-check
: True
 
#+call: threshold-check(amount=80, threshold=100)
 
#+results: 
: False
 
#+call: threshold-check(amount=120, threshold=100)
 
#+results: 
: True
 
分别预期 =False= 、 =True=.
** Org Table → Python
Org 表可以直接成为 =:var= 输入。示例直接使用列位置。这里的表有“表头 +
hline”，默认 =:colnames nil= 会在执行前把表头从传给 Python 的数据行中拿
掉，再在需要时恢复到结果表；所以 =rows= 从 =u01= 开始，不包含 =uid /
amount=. 如果显式设成 =:colnames no=, 表头也会进入 Python，下面的数值求和
就需要自己处理表头。
 
#+name: amounts
| uid | amount |
|-----+--------|
| u01 |     10 |
| u02 |     20 |
| u03 |     30 |
 
#+name: sum-amounts
#+begin_src python :var rows=amounts :results value replace
  return sum(float(row[1]) for row in rows)
#+end_src
 
#+results: sum-amounts
: 60.0
 
这里的高价值点不是“Python 会求和”，而是表格成为可编辑输入，代码不用改。
* Block → Block：把结果当下一步输入
先生成一组数：
 
#+name: make-values
#+begin_src python :var start=1 stop=5 :results value table
  return [[n, n * n] for n in range(start, stop + 1)]
#+end_src
 
#+results: make-values
| 1 |  1 |
| 2 |  4 |
| 3 |  9 |
| 4 | 16 |
| 5 | 25 |
 
再消费前一个 Block：
 
#+name: sum-squares
#+begin_src python :var rows=make-values(start=1, stop=5) :results value replace
  return sum(row[1] for row in rows)
#+end_src
 
#+results: sum-squares
: 55
 
依赖图：
 
#+begin_example
  start / stop
      ↓
  make-values
      ↓
  sum-squares
      ↓
  55
#+end_example
 
修改 =make-values= 后，=sum-squares= 属于受影响节点，应该重跑。
* #+call：给复杂 Block 一个轻量调用面
命名 Block 可以像函数一样调用：
 
#+name: multiply
#+begin_src python :var x=2 y=3 :results value replace
  return x * y
#+end_src
 
#+results: multiply
: 6
 
日常调用：
 
#+call: multiply(x=6, y=7)
 
#+results: 
: 42
 
预期：42。
 
排错：如果普通 Block 正常、=#+call:= 单独报 Emacs Lisp 参数数量错误，直接跳到 [[file:org-babel-03-verification-debugging.html#section-0d0fb1d33f89][#+call / ob-async 兼容诊断]]。
 
=#+call:= 有三层东西，别混在一起：
 
#+begin_example
  ,#+call: NAME[inside-header](arguments) end-header
#+end_example
 
- 圆括号 =arguments= 传给 Block 变量；
- 名称后的方括号 =inside-header= 作用于被调用 Block 本次执行；
- 圆括号后的 =end-header= 作用于 CALL 结果的处理。
 
例如：
 
#+call: multiply[:results value replace](x=8, y=9)
 
#+results: 
: 72
 
预期：72。
* 结果管理：不要只会 #+RESULTS
 
=:results= 至少要同时考虑四件事：
 
#+begin_example
  Collection: value / output
  Type:       scalar / table / list / file ...
  Format:     raw / verbatim / code ...
  Handling:   replace / append / prepend / silent
#+end_example
** replace：默认适合可重复实验
 
#+name: replace-result
#+begin_src python :var n=3 :results value replace
  return n ** 2
#+end_src
 
#+results: replace-result
: 9
 
再次执行只替换旧结果，不堆历史输出。
** verbatim：禁止列表被自动转成表格
 
#+name: verbatim-list
#+begin_src python :results value verbatim
  return [1, 2, 3]
#+end_src
 
#+results: verbatim-list
: [1, 2, 3]
** table：结果继续成为数据
 
#+name: table-result
#+begin_src python :results value table
  return [["u01", 100], ["u02", 200]]
#+end_src
 
#+results: table-result
| u01 | 100 |
| u02 | 200 |
** silent / none / discard：都不写结果，但语义不同
 
#+name: silent-result
#+begin_src python :results output silent
  print("this runs but is not inserted")
#+end_src
 
=:results silent= 不插入结果，但会把结果回显到 minibuffer；=:results none= 仍计算结果，只是不插入也不回显，结果仍可被其他 Block 引用；=:results discard= 连结果处理都跳过，被引用时得到 nil。需要下游继续消费结果时，不要误用 =discard=。Org Manual 将三者明确区分。
** append：只在你真的需要历史记录时用
 
#+name: append-result
#+begin_src python :results output append
  print("one-run")
#+end_src
 
#+results: append-result
: one-run
 
反复运行会不断追加。实验型笔记通常优先 =replace=，否则结果区很快失控。

Org 表可以直接成为 :var 输入。示例直接使用列位置。这里的表有“表头 + hline”，默认 :colnames nil 会在执行前把表头从传给 Python 的数据行中拿 掉，再在需要时恢复到结果表；所以 rows 从 u01 开始，不包含 uid / amount. 如果显式设成 :colnames no, 表头也会进入 Python，下面的数值求和 就需要自己处理表头。

8. #+call：给复杂 Block 一个轻量调用面

命名 Block 可以像函数一样调用： 

return x * y

日常调用：

排错：如果普通 Block 正常、#+call: 单独报 Emacs Lisp 参数数量错误，直接跳到 #+call / ob-async 兼容诊断。

#+call: 有三层东西，别混在一起： 


#+call: NAME[inside-header](arguments) end-header
  • 圆括号 arguments 传给 Block 变量；
  • 名称后的方括号 inside-header 作用于被调用 Block 本次执行；
  • 圆括号后的 end-header 作用于 CALL 结果的处理。

9. 结果管理：不要只会 #+RESULTS

:results 至少要同时考虑四件事： 


Collection: value / output
Type:       scalar / table / list / file ...
Format:     raw / verbatim / code ...
Handling:   replace / append / prepend / silent

9.1. replace：默认适合可重复实验

return n ** 2


9

再次执行只替换旧结果，不堆历史输出。

9.2. verbatim：禁止列表被自动转成表格

return [1, 2, 3]


[1, 2, 3]

9.3. table：结果继续成为数据

return [["u01", 100], ["u02", 200]]
u01 100
u02 200

9.4. silent / none / discard：都不写结果，但语义不同

print("this runs but is not inserted")

:results silent 不插入结果，但会把结果回显到 minibuffer；:results none 仍计算结果，只是不插入也不回显，结果仍可被其他 Block 引用；:results discard 连结果处理都跳过，被引用时得到 nil。需要下游继续消费结果时，不要误用 discard。Org Manual 将三者明确区分。

9.5. append：只在你真的需要历史记录时用

print("one-run")


one-run

反复运行会不断追加。实验型笔记通常优先 replace，否则结果区很快失控。
