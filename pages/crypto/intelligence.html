**** 官方
#+begin_src markdown
  @网页搜索 持续监测 Bitget 资金被盗事件。
  ## 时间窗口
  每轮只检索：
  `[START_TIME, END_TIME) UTC`
  默认：
  - `START_TIME = 上一轮 END_TIME`
  - `END_TIME = 本轮实际执行时间`
  - 首次执行向前回溯 12 小时
  禁止重复返回窗口外已报告信息。
  ## 全网检索范围
  扫描公开可访问、可检索的信息源：
  - Bitget 官网、公告、博客、状态页、官方社媒
  - X / Reddit / Telegram / Discord 公开信息
  - Google / Bing 可索引网页与新闻
  - Chainalysis、TRM、Elliptic、SlowMist、PeckShield、CertiK 等安全机构
  - Arkham、Etherscan、BscScan 等链上数据源
  - 交易所、稳定币发行方、跨链桥官方渠道
  - 执法机构及监管机构
  - GitHub、安全研究博客及独立链上研究者
  ## 本轮只找新增变化
  重点检索：
  - 新攻击地址、TxHash、关联钱包
  - 新转账、Swap、跨链、归集、拆分
  - 冻结、拦截、追回
  - 被盗金额变化
  - 攻击入口与攻击方式
  - 根因调查
  - Bitget 内部响应
  - 提现恢复情况
  - 执法与安全机构介入
  - 攻击者身份或历史攻击关联
  ## 时间判定
  统一转换为 UTC。
  链上事件以 `Block Timestamp` 为准。
  网页、公告、帖子以：
  `发布时间 → 更新时间 → 首次发现时间`
  依次判断。
  旧文章在本时间窗发生实质更新，可以收录，但必须标记：
  `旧来源｜本轮新增内容`
  ## 去重
  同一事件被多个媒体转载，只算一条。
  保留最原始信源，其余只作为交叉验证。
  ## 可信度
  每条标记：
  `已确认 / 高可信推断 / 未验证`
  不得把推测写成事实。
  ## 输出
  首先声明：
  `监测窗口：START_TIME → END_TIME UTC`
  然后只输出本窗口新增：
  | UTC 时间新增事件原始来源证据链上变化可信度 |
  | ----------------------- |
  若整个窗口没有实质变化，只返回：
  `START_TIME → END_TIME UTC：暂无实质新增`
#+end_src
**** 社区
#+begin_src markdown
  @网页搜索 持续抓取 Bitget 被盗事件的社区高置信情报。
  重点监测：
  - X / Reddit / Telegram / Discord 中的一线链上研究者、安全研究员、交易所从业者
  - 新攻击地址、资金路径、跨链、Swap、冻结或追回线索
  - 攻击入口、攻击手法、内部响应等尚未官宣的信息
  - 多个独立信源同时出现的相同线索
  只收录满足至少一项的消息：
  1. 附链上交易、地址、TxHash 或可验证数据
  2. 附截图、日志、公告原文等一手证据
  3. 至少 2 个独立可信信源交叉印证
  4. 来源过去有准确披露安全事件的记录
  每条情报标记：\
  `高置信 / 中置信 / 未验证`
  禁止：
  - 搬运纯猜测、情绪、匿名转述
  - 因转发量高就提高可信度
  - 将社区推测写成事实
  - 多账号复制同一消息视为独立信源
  每轮仅返回新增情报，并与官方信息交叉验证。
  输出：\
  `时间｜社区线索｜原始来源｜证据｜交叉验证｜置信度｜尚未确认点`
#+end_src
