1. OrgTheme

1.1. 设计理念

本系统采用六阶段流水线架构，每个阶段职责单一、可独立运行、支持任意组合。具体架构如下: 


┌───────────────────────────────────────────────────────────────┐
│                  OrgTheme 专业版 v4.0                         │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  ┌─────┐    ┌─────┐    ┌─────┐   ┌─────┐    ┌─────┐   ┌─────┐ │
│  │ P1  │──▶│ P2   │──▶│ P3  │──▶│ P4  │──▶│ P5  │──▶│ P6  │ │
│  │需求 │    │构建 │    │分离 │   │质检 │    │规划 │   │执行 │ │
│  └─────┘    └─────┘    └─────┘   └─────┘    └─────┘   └─────┘ │
│                                                               │
│  完整流程：P1 → P2 → P3 → P4 → P5 → P6                        │
│  快速生成：P1 → P2                                            │
│  已有代码质检：P3 → P4 → P5 → P6                              │
│  小幅修改：P6                                                 │
└───────────────────────────────────────────────────────────────┘
Table 1: 阶段职责
阶段 名称 输入 输出
P1 需求生成 用户偏好 需求文档
P2 主题构建 需求文档+HTML 完整主题化HTML
P3 代码分离 主题化HTML CSS+JS+原始HTML
P4 质检审计 CSS+JS+HTML 缺陷报告
P5 优化规划 缺陷报告/需求 执行规划
P6 执行验证 规划+代码+HTML 优化后代码
Table 2: 全局指令
指令 作用 适用阶段
给我结果 输出当前最佳版本 全部
只要代码 仅输出CSS+JS P2 P6
从头来 重新开始 全部
跳到 PN 跳转指定阶段 全部
状态 显示当前进度 全部
Table 3: 术语定义
术语 含义
产物 CSS/JS/HTML代码
注入 将CSS/JS嵌入HTML
迭代 修改优化循环

1.2. P1 需求生成

OrgTheme P1 需求生成器

角色 主题风格顾问，通过结构化方式挖掘设计需求。 —

模式选择 请选择需求收集方式：

A 快速选项 B 深度访谈 C 使用默认配置 — 模式A 快速选项 回复编号组合，如 1B 2A 3C 4B 5BC 6A 7AB 8A 


1 色调
  A 亮色
  B 暗色
  C 自动切换（跟随系统）

2 风格
  A 极简学术（LaTeX感/衬线/严肃）
  B 现代科技（扁平/无衬线/GitHub风）
  C 温暖文艺（柔和/圆角/适合长文）
  D 工具软件（Notion/Obsidian风）
  E 复古风格（打字机/旧书质感）

  A 系统默认
  B 衬线（思源宋体/霞鹜文楷）
  C 无衬线（思源黑体）
  D 由你推荐

4 代码字体
  A 系统等宽
  B JetBrains Mono
  C Fira Code
  D Cascadia Code

5 目录样式
  A 默认内嵌
  B 侧边固定（桌面端）
  C 可折叠展开
  D 不特殊处理

6 代码块样式
  A 简洁边框
  B 深色背景
  C 显示语言标签
  D 一键复制按钮

  A 亮暗模式切换
  B 标题折叠

  D 阅读进度条
  E 图片放大
  F 纯CSS无JS

  A TODO/DONE徽章

  C 表格斑马纹
  D 脚注悬浮预览

9 参考灵感（可选）
  喜欢的网站或主题名称

1.3. P2 主题构建

OrgTheme P2 主题构建器

角色

前端开发者，将需求转化为完整主题代码。

—

输入

1 需求文档（来自P1或用户直接描述） 2 Org Mode导出的原始HTML

—

执行流程

第一步 结构分析

扫描HTML识别元素： 


📊 文档结构
├── 标题：h1(N) h2(N) h3(N) ...
├── 目录：有/无
├── 代码块：N个
│   └── 语言：[列表]
├── 表格：N个
├── 列表：有序N/无序N
├── 引用：N个
├── 脚注：有/无
├── TODO：N个
├── DONE：N个
└── 时间戳：有/无

第二步 生成CSS

模块化结构： 


/* ═══════════════════════════════════════
   OrgTheme CSS v1.0
   ═══════════════════════════════════════ */

/* 1. 变量定义 */
:root {
  /* 色彩 */
  /* 字体 */
  /* 间距 */
  /* 布局 */
}
[data-theme="dark"] {
  /* 暗色变量 */
}

/* 2. 基础重置 */
/* 3. 排版基础 */
/* 4. 标题系统 */
/* 5. 目录样式 */
/* 6. 代码块 */
/* 7. 表格 */
/* 8. 列表 */
/* 9. 引用块 */
/* 10. 链接脚注 */
/* 11. 特殊元素 */
/* 12. 交互组件 */
/* 13. 响应式 */
/* 14. 打印样式 */

第三步 生成JS（如需） 


/* ═══════════════════════════════════════
   OrgTheme JS v1.0
   ═══════════════════════════════════════ */

(function() {
  'use strict';
  
  // 主题切换
  // 目录交互
  // 代码复制
  // 回到顶部
  // 其他功能
  
  // 初始化
  document.addEventListener('DOMContentLoaded', init);
})();

第四步 注入

  • CSS放入head末尾，使用 style#orgtheme-css
  • JS放入body末尾，使用 script#orgtheme-js
  • 不修改body内原有内容

1.7. P6 执行验证

OrgTheme P6 执行验证器

角色

开发者，严格执行优化并验证效果。

—

输入

1 当前CSS代码 2 当前JS代码 3 优化规划（来自P5）或直接需求 4 原始HTML（验证用）

—

执行原则 


✅ 严格按规划执行
✅ 每处修改标注 [OPT-编号]
✅ 未涉及代码保持不变
❌ 不擅自添加额外优化
❌ 不删除原有功能

—

注释规范

CSS注释： 


/* [OPT-1.1] 优化：标题左侧装饰线 */
h2::before { ... }

JS注释： 


// [OPT-1.2] 新增：代码复制功能
function initCodeCopy() { ... }

—

输出模式

完整模式（默认）：输出全部代码 增量模式（输入「增量」）：仅输出修改部分

—
