* 练习目标
- 掌握 Lisp 风格的过程抽象：把“如何求平方根”拆成可命名、可测试、可组合的小过程。
- 理解黑箱抽象：调用者只关心 =ex-sqrt= 的输入输出，不需要关心内部猜测如何改进。
- 练习递归式过程：用“猜测 → 判断 → 改进 → 继续”的结构逼近平方根。
- 熟悉 Org-mode 文学编程：使用 Noweb 具名块组织代码，并通过唯一 Assembly Block 导出。
* 题目描述
实现一个 Emacs Lisp 模块，用迭代逼近法计算非负数的平方根。程序需要完成以下行为：
1. 输入一个非负数字 =target=。
2. 从初始猜测值 =guess= 开始。
3. 判断当前猜测是否足够好。
4. 若不够好，则根据公式改进猜测。
5. 重复以上过程，直到误差小于容忍度 =tolerance=，或达到最大迭代次数。
6. 返回包含最终猜测值、目标值、容忍度、迭代步数的结果结构。
 
核心公式：
1. 平方：=x * x=
2. 平均值：=(a + b) / 2=
3. 改进猜测：=(guess + target / guess) / 2=

#+name: chunk-core

  ;; TODO: 本块依赖 chunk-data 与 chunk-helpers；保持 Assembly 中的装配顺序。
  ;; TODO: 不要把辅助函数逻辑重复写进核心函数，避免破坏黑箱抽象。
 
  (defun ex--sqrt-iterate (target guess tolerance steps)
    "Recursively improve GUESS until it approximates square root of TARGET."
    (cond
     ((ex--good-enough-p target guess tolerance)
      (ex-make-sqrt-state
       :guess guess
       :target target
       :tolerance tolerance
       :steps steps))
     ((>= steps ex-max-steps)
      (ex-make-sqrt-state
       :guess guess
       :target target
       :tolerance tolerance
       :steps steps))
     (t
      (ex--sqrt-iterate
       target
       (ex--improve-guess target guess)
       tolerance
       (1+ steps)))))
 
  (defun ex-sqrt (target &optional tolerance initial-guess)
    "Approximate square root of TARGET using recursive improvement."
    (unless (ex--valid-target-p target)
      (user-error "TARGET must be a non-negative number"))
    (let ((tol (or tolerance ex-default-tolerance))
  	(guess (or initial-guess ex-default-initial-guess)))
      (ex--sqrt-iterate target guess tol 0)))

* 技术难点剖析（润色草稿）
 
- 过程抽象 :: 程序不是把代码堆起来，而是把“怎么做”拆成可命名的小过程。
- 黑箱抽象 :: =ex-sqrt= 对外只暴露目标输入和结果输出，内部的猜测、判断、改进被封装起来。
- 递归逼近 :: 每一次递归都不是原地打转，而是让 =guess= 更接近目标答案。
- 命名 :: =ex--square=、=ex--improve-guess=、=ex--good-enough-p= 这些名字让代码接近问题语言。
- 文学编程 :: Org-mode 把解释、代码块、测试、导出组织在同一份文档里，减少“代码会跑但没人看懂”的问题。
* 任务指南（润色草稿）
 
1. 从 =chunk-helpers= 开始实现，优先保证辅助函数简单、纯净、可单独测试。
2. 实现 =chunk-core=，让主过程只负责调度：判断、改进、递归继续。
3. 补全 =chunk-tests=，覆盖正例、边界值和错误输入。
4. 执行 =M-x org-babel-tangle=，导出 =exercise-sqrt-process.el=。
5. 在 Emacs 中加载导出文件，运行 =M-x ert= 验证测试。
6. 手动执行 =M-x ex-sqrt-message=，输入 =2=、=9=、=100=，观察输出结果。
* 验收标准
 
- 所有具名块均设置 =:tangle no=。
- 只有组装块设置 =:tangle exercise-sqrt-process.el=。
- 组装块内只包含 Noweb 引用，不包含任何实现代码。
- functional 范式下不生成 =chunk-class=。
- =chunk-tests= 至少包含正例、边界用例、错误输入用例。
- =M-x ert= 执行后，所有测试通过。
- =ex-sqrt-message= 能作为 interactive 命令调用。
* 禁止事项
 
- 禁止在具名块上设置 =:tangle exercise-sqrt-process.el=。
- 禁止在组装块内写任何实现代码。
- 禁止生成 =chunk-class=，本练习不是 OOP 范式。
- 禁止省略 =:comments link=。
- 禁止把平方根核心公式散落在多个位置重复实现。
- 禁止让 =ex-sqrt= 直接处理所有细节；必须通过辅助函数分层。
- 禁止删除测试块；没有测试，本练习不算完成。

  (should (< (abs (ex-sqrt-state-guess (ex-sqrt 0))) 0.01)))

(ert-deftest ex-test-invalid-target ()
  "Test invalid sqrt input."
  (should-error (ex-sqrt -1) :type 'user-error)
  (should-error (ex-sqrt "2") :type 'user-error))

5. 技术难点剖析（润色草稿）

过程抽象
程序不是把代码堆起来，而是把“怎么做”拆成可命名的小过程。
黑箱抽象
ex-sqrt 对外只暴露目标输入和结果输出，内部的猜测、判断、改进被封装起来。
递归逼近
每一次递归都不是原地打转，而是让 guess 更接近目标答案。
命名
ex--square、ex--improve-guess、ex--good-enough-p 这些名字让代码接近问题语言。
文学编程
Org-mode 把解释、代码块、测试、导出组织在同一份文档里，减少“代码会跑但没人看懂”的问题。

6. 任务指南（润色草稿）

  1. 从 chunk-helpers 开始实现，优先保证辅助函数简单、纯净、可单独测试。
  2. 实现 chunk-core，让主过程只负责调度：判断、改进、递归继续。
  3. 补全 chunk-tests，覆盖正例、边界值和错误输入。
  4. 执行 M-x org-babel-tangle，导出 exercise-sqrt-process.el。
  5. 在 Emacs 中加载导出文件，运行 M-x ert 验证测试。
  6. 手动执行 M-x ex-sqrt-message，输入 2、9、100，观察输出结果。

7. 验收标准

  • 所有具名块均设置 :tangle no。
  • 只有组装块设置 :tangle exercise-sqrt-process.el。
  • 组装块内只包含 Noweb 引用，不包含任何实现代码。
  • functional 范式下不生成 chunk-class。
  • chunk-tests 至少包含正例、边界用例、错误输入用例。
  • M-x ert 执行后，所有测试通过。
  • ex-sqrt-message 能作为 interactive 命令调用。

8. 禁止事项

  • 禁止在具名块上设置 :tangle exercise-sqrt-process.el。
  • 禁止在组装块内写任何实现代码。
  • 禁止生成 chunk-class，本练习不是 OOP 范式。
  • 禁止省略 :comments link。
  • 禁止把平方根核心公式散落在多个位置重复实现。
  • 禁止让 ex-sqrt 直接处理所有细节；必须通过辅助函数分层。
  • 禁止删除测试块；没有测试，本练习不算完成。
