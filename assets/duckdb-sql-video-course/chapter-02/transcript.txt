# 重制版讲稿

## 从一张小表开始取数

这一章有五个小节：看整表、选列、写样本、指定来源，最后自己动手。

带着一个问题看下去：我只想看姓名和工资，应该改哪一行？

## 星号：取出全部列

先看看这张小表，Alice 和 Bob 各占一行，右边是我们从原例读出的四列。

如果想把它们全部拿出来，SELECT 后面写个星号就行。

现在看结果，四列都在，两个人也都在。

## 列名：只取需要的字段

如果只关心姓名和工资，就看第二条原例，输入里其实还有编号。

把目光移到第一行，它只点了 name 和 salary。

结果出来了，编号收起来，Alice 和 Bob 仍各占一行。

## VALUES：把小表写在 SQL 里

刚才两张小表都写在 SQL 里，秘诀就在 VALUES 后面这一对括号。

读完第一对，再看后面两对，每对的值按位置对齐。

运行后就是三行，原文没取列名，所以 DuckDB 给它们起了默认名字。

## FROM：把小表交给查询

有了小表，再看怎么交给查询，FROM 后面的括号就是读入的来源。

括号右边的 t 是这份来源的名字，x 是它唯一的列。

回到第一行，SELECT x 把它取出来，结果是一和二。

## 只改一处，再运行一次

现在回到第一条例子，Alice 和 Bob 的数据照旧。

暂停一下，试着把星号换成 name 和 salary。

如果你得到两行，而且屏幕上只有姓名和工资两列，就改对了。

## 本章回顾与总结

回看那张整表，想看全貌的时候，星号一次把所有列都带出来。

知道自己要哪几列，就直接写列名，第二条例子里，两个人的记录都留着。

没现成的表也能练，VALUES 后面每一对括号都能写进一行数据。

把这个小表放到 FROM 后面，它就成了查询的数据来源。

下次读这类 SQL，可以先找 FROM，再回头看 SELECT。
