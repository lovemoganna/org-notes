最小回归先用 T04 检查跨单位求和，T06 检查 JOIN 放大，T08 检查旧数值污染，T09 检查同 UID 被误写为资金因果。这四例的输入内联，能先隔离语义、计算与证据错误。它们仍要求真实 DuckDB 执行；有提示词不等于已测试。

通过这些检查后，再用 T02、T03、T05 覆盖不同业务语义和未知枚举；以 T10 检查来源不可用时能否正确阻塞。T01、T07 依赖指定 Google Sheets 和固定 DuckDB SQL，只有 Runtime 符合约束才执行，不得换源替代。最终仍要跑完整 T01–T10 和 Skill 原有触发正反例；此顺序只是快速定位缺陷，不是减少验收范围。任一最小回归失败，都应保存实际 SQL、Result 或错误日志，不得用其余成功案例抵消。

* 怎么选测试
这页有两组独立资产。S01–S13 用真实公开数据检验 =sql-business-thinking= 的业务口径、SQL 和证据。T01–T10 检验 =ontology-constrained-analysis= 的 Runtime、两张本体表、Gate 1–4、Signal 与 Finding。两种能力不是一个问题，不合并通过率。23 个案例仍是待执行的测试需求。

| 遇到的问题 | 用例 | 验证什么 |
|------------+------+----------|
| 多表订单、状态或时间粒度可能重复计数 | S01、S02、S05 | 真实数据和计算口径 |

* 为什么生成报告不等于通过测试
运行依赖不能倒置：来源和引擎真实可用，才有本轮数据；两张本体表的结构和业务语义先通过，才能生成合法问题；SQL 取得真实 Result 才有 Signal；关系验证、竞争解释和稳健性完成才可能得到 Validated Finding。下游报告不能追认上游缺失的证据。

S 组主要考察 SQL 业务分析，不强加本体 Skill 的四 Gate。T 组严格按 Runtime Gate、Gate 1–4 执行；没有信息增量时可以合法停止，不应为了凑报告结果编造 Finding。

* 五表 JOIN 金额虚增时，先查哪个粒度〔补〕
S01 的订单、订单明细、支付、评价和客户记录不能假定都是一订单一行。先从实际文件核对主键候选、订单键的匹配与未匹配数、每个订单对应的明细／支付／评价行数，以及连接前各表的金额口径。多方都有重复订单键时，直接相连会将同一金额计算多次。

默认先在各自的原生粒度计算核对值；需要按订单比较时，再分别按经验证的订单键预聚合为一订单一行，之后连接订单主表。比较连接前后订单数、行数、支付金额、明细金额及未匹配记录，并按实际状态区分支付、取消和退款。=SUM(DISTINCT amount)= 不是安全的去重办法：不同订单可能支付相同金额。只有实际 SQL、Result 与回算一致，才能把经营结论写成 Finding；这个方法建议不代表 S01 已经运行。

* 如何在其他模型中执行盲测〔补〕
1. 冻结数据输入、模型版本、工具权限和实际读取的 Skill Commit。每轮只把一个案例的 =#+begin_example= 内容交给被测模型；裁判区、旧报告、其他案例和预期结果不得进入上下文。
2. T01、T07 锁定了来源、SQL 和四表白名单。Runtime、数据物化、Gate 依赖必须按序执行。只有后续独立且只读、状态隔离的验证才能并行；不安全就串行并记录原因。
3. 由外部执行回执裁定结果：记录本轮来源字节（能获取时）、引擎、SQL、Result、Gate 时间、文件、实际错误和模型版本。自报 PASS 不构成证明。
4. “启用 Skill／未启用 Skill”对照必须保持输入相同。现有 T 组提示词含“使用 ontology-constrained-analysis”，不能一组保留、另一组删掉。先为两组生成相同的中性调用副本，仅由运行环境决定是否加载 Skill；原提示词仍用于单独测显式调用。
5. 将失败分类为 Skill 缺陷、执行偏差、环境阻塞或测试错误。对通用缺陷先最小复现，再修改规则并重跑旧失败、核心案例和独立反例。两轮无改善或有重大回归时回退。

* 看到错误先查哪一层〔补〕
| 现象 | 核查对象 | 不合法的捷径 |
|------+----------+--------------|
| URL 能打开但 SQL 读取失败 | 原始字节、权限、DuckDB、扩展及错误日志 | 静默换 CSV 或改掉固定 SQL |
| SQL 跑完才宣称 Gate 1 通过 | 本体结构/语义回执和每次 SQL 时间 | 补写 Gate 时间、追认本体 |
| JOIN 后金额不一致 | 主键、原生粒度、匹配数与 JOIN 前后合计 | 为匹配预期硬编码金额 |
| 有 Result 却不形成 Signal | 内部比较、信息增量和合法下一问题 | 凑异常、强行生成 Finding |
| 新运行报告仍引用旧数字 | 查询 ID、Result 和动态数值绑定 | 重用历史观察值 |
| 来源不可得仍出现数字 Finding | 获取错误、等价运行时检查和阻塞报告 | 用截图、示例或旧报告冒充数据 |
