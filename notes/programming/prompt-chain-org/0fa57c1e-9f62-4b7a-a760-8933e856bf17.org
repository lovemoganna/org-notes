* 这条链解决什么
把一条真实而模糊的 UI 修改要求，转成开发者可以实施和验收的最小需求。只做文本任务交付；不假装已经修改 PivotStudio 代码。

本笔记就是提示链定义和测试记录的唯一源文件。后续运行记录追加到本文，网页由仓库现有 GitHub Actions 重新生成；不另建测试文章。

* 原始任务
#+begin_example
透视结构放置区现在占据的空间很大，而且随着放置的维度和度量越多，高度就会越高，此外左边的侧边栏有一部分还空着，想办法合理调整下布局。
#+end_example

* 提示链
** Prompt A：提取真实问题与约束
#+begin_example
阅读用户提供的原始 UI 改进需求。
只提取四项：
1. 已确认的现象；
2. 用户真正想达到的结果；
3. 改动时必须保留的约束（只收录原文或上下文明确提出的要求）；
4. 需要到真实产品中进一步检查的信息。
每项用短句，不推测现有布局的具体实现。
不生成 UI 方案、不擅自增加功能，也不声称已经修改代码。
#+end_example

** Prompt B：交付一份最小可执行需求单
#+begin_example
你将收到原始 UI 需求与上一阶段的结构化结果。
请把它们转换为开发者可直接执行的最小任务单，只保留：
- 目标与具体问题；
- 需要检查或调整的界面区域；
- 一种优先实施的低风险布局调整方向；
- 能在真实产品里验证的验收条件；
- 不得破坏的现有能力；
- 仍需现场核实的信息。
保持简洁。不得把待核实的布局事实写成已确认，不得假设源码或技术栈，不得宣称实施完成。
#+end_example

* 执行定义
- 顺序：Prompt A → Prompt B。
- A 的输入：上面的“原始任务”原文。
- B 的输入：相同原始任务 + A 的完整原始输出；把 A 输出原样粘贴，不要重新摘要。
- 第一版执行方式：人工分两次向 AI 发送上述独立提示，原样保存每步回复。此处不需要通用 Agent Router 或 API Key。
- 模型/工具不可用时记为阻塞，禁止填写臆造的结果；模型输出不代表真正改过前端代码。

*** Prompt B 原始输出
#+begin_example
目标：降低透视字段配置区的空间占用，避免字段增加后持续挤压主要工作区域。

调整范围：透视字段放置区及左侧边栏的闲置空间。
