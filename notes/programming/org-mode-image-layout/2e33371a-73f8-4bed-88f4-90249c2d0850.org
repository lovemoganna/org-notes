* 什么时候使用
当 Org 文章中的图片过大、图集松散、手机端溢出，或修改源码却不影响线上显示时，使用下方提示。先检查实际导出器及站点样式；只修改目标文章，避免影响其他页面。

* 可复制的维护提示
#+begin_example
优化 Org Mode 文档中的图片尺寸与排版。优先使用原生 `#+ATTR_HTML:` 控制图片宽度、高度及最大宽度，避免直接修改图片文件。单张图片默认设置 `:width 240px`，并保证 `max-width:100%;height:auto;`，防止图片变形或超出容器。多张图片采用统一尺寸和紧凑布局，桌面端优先每行 3 张，移动端根据屏幕宽度自适应。图片下方保留简短说明，支持点击放大查看原图。

执行前先检查现有 Org 结构与 HTML 导出机制，确保 `#+ATTR_HTML:` 作用于正确元素。若图片位于表格内，应控制表格总宽度及列宽，不能误认为表格属性会直接作用于内部图片。优先修改 Org 源文件，仅在原生属性不足时增加局部 CSS，不修改全站通用样式。

修改后必须执行 HTML 导出，检查实际生成的 HTML、图片显示尺寸、布局、响应式效果和图片链接。确认修改已进入最终发布文件后，再提交并部署。保留原图、正文、标题、链接及其他无关内容。禁止仅凭源码修改或部署成功就认定排版问题已解决。
#+end_example

* 两种最小用法
** 单张图片
`#+ATTR_HTML:` 紧接图片链接；宽度 240px 是初始建议值，不是所有图片的固定标准。

#+begin_example
#+ATTR_HTML: :width 240px
[[file:images/example.png]]
#+end_example

避免将图片的高度强行设为固定值；缩小展示尺寸不等于压缩或裁切原图。是否支持点击放大取决于网站的图片预览功能。

** 表格中的多张图片
表格前的 `#+ATTR_HTML:` 作用于表格，不直接修改单元格内各张图片的属性。可先限制表格宽度，再按列数检查实际的缩略图宽度。

#+begin_example
#+ATTR_HTML: :width 660px :style min-width:0;width:100%;max-width:660px;table-layout:fixed;margin:auto
| [[file:images/01.png]] | [[file:images/02.png]] | [[file:images/03.png]] |
#+end_example

以上是 Org Museum 当前发布器使用过的表格写法。其他导出器可能采用不同的 HTML 结构或 CSS，不能保证直接照搬即生效。特别注意：在本站的导出流程中，给 `:style` 值额外加引号曾造成生成的 HTML 样式值包含引号；因此此例不额外加引号。

* 如何添加附件：本地管理与网站发布
同一份 Org 笔记可能在 Emacs 本地使用，也可能导出到 Org Museum。两种方式的附件路径不同：本地优先用 `org-attach` 管理文件；公开发布优先用仓库内的相对路径和 `file:` 链接。

** Emacs 本地：org-attach
将光标移到目标 Org 标题，按 `C-c C-a` 打开附件菜单。常用操作：

| 按键 | 操作 |
|------+------|
| `C-c C-a c` | 复制文件到该标题的附件目录 |
| `C-c C-a m` | 将文件移动到附件目录 |
| `C-c C-a o` | 打开附件 |
| `C-c C-a f` | 打开附件目录 |

附件与标题关联。使用基于 `ID` 的附件管理时，在 Emacs 按 `C-c C-l` 插入链接，目标填写 `attachment:report.pdf` 或 `attachment:screenshot.png`。以下仅展示链接目标，避免发布器把示例误当作实际附件：

#+begin_example
* 项目资料
:PROPERTIES:
:ID: 12345678-1234-1234-1234-123456789abc
:END:

附件链接目标：attachment:report.pdf
图片附件目标：attachment:screenshot.png
#+end_example

`org-attach` 的实际存储目录可配置。添加附件后应检查文件确实存在，并确认 `attachment:` 链接可在当前 Emacs 配置下打开。不能假设这类本地链接会被网站发布器自动打包。

** 普通 Org 文件：相对路径
如果自行维护图片或 PDF 目录，可以直接使用相对路径：

#+begin_example
#+ATTR_HTML: :width 240px
[[file:images/diagram.png]]

[[file:attachments/report.pdf][查看 PDF 报告]]
#+end_example

图片链接可在 HTML 中显示为图片，PDF 等文件通常显示为可点击链接；具体结果取决于导出器。Org 文件只保存路径引用，不包含附件的二进制数据。

** Org Museum：note-assets 目录
当前公开仓库的源笔记采用 `notes/<kind>/<topic>/<id>.org`，附件统一放在 `note-assets/<同一 id>/`。以三级目录中的 Org 文件为例：

#+begin_example
notes/
  programming/
    my-topic/
      <id>.org
note-assets/
  <id>/
    diagram.png
    report.pdf
#+end_example

在 `<id>.org` 中引用：

#+begin_example
#+ATTR_HTML: :width 240px
[[file:../../../note-assets/<id>/diagram.png]]

[[file:../../../note-assets/<id>/report.pdf][查看 PDF 报告]]
#+end_example

`../../../` 适用于上述目录层级；移动笔记后要重新核对相对路径。该仓库限制附件位于 `notes/` 或 `note-assets/` 内，附件格式和单文件大小须符合发布契约，当前单文件上限为 20 MiB。不要将本地绝对路径或未随仓库提交的 `org-attach` 文件直接用于公开网页。

** 附件发布验收
1. 在源仓库中确认 Org 文件和每个附件都已提交，文件名大小写与链接一致。
2. 检查图片实际显示、缩略图尺寸、PDF 链接，以及移动端是否溢出。
3. 核对导出的 HTML 与最终发布包：资源路径有效，不只是本机预览正常。
4. 部署后打开线上网页，确认图片和附件能访问，并核对版本属于此次提交。

* 怎么证明修改真正生效
1. 检查 `#+ATTR_HTML:` 是否紧贴需要控制的对象，不能误把表格属性当成图片属性。
2. 导出 HTML，核对生成的 `img` 或 `table` 属性以及浏览器中的实际展示尺寸。
3. 检查桌面与手机视口：无横向溢出，图片不拉伸，标题与图片能对应。
4. 如果网站支持灯箱，检查缩略图点击后能否查看原图；同时检查图片是否加载成功。
5. 发布后验证线上版本与本次源提交一致。构建成功或仓库 CSS 改动本身不构成视觉验收。

* 已遇到的故障边界
2026-10-11，[[wiki:9e15fa89-5e58-47a9-aebf-5784261806ad][十二符咒修仙图鉴]] 的 12 张图腾曾显示过大。首次增加局部 CSS 后，发布产物未包含新增规则，因此线上问题没有随源码同步消失。随后改为在 Org 表格前设置 `#+ATTR_HTML:` 并限制总宽度，实际导出的 HTML 中可以检查到相关属性。后续修复了 `:style` 多余引号问题。该记录证明了这个仓库需要同时核验生成物，不能证明上述宽度适用于所有文章。
