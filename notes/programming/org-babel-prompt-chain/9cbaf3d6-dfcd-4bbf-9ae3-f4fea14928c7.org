* 核心思想
这篇实验不以“收藏更多提示词”为目标，而是把真实问题的处理方法变成可执行、可追溯、能持续积累的个人能力。

职责只有三层：*用户提出任务；AI 按 A → B 顺序执行纯文本提示；Org 保存提示、输入和原始输出*。Git 负责版本历史，笔记网站负责公开展示。复杂的调用过程不应转嫁给使用者，也不需要另建提示词管理平台。

最小闭环：真实任务 → Prompt A 提炼问题 → Prompt B 使用 A 的完整结果交付任务单 → 写回同一 Org 文件 → 更新同一篇文章。本轮只证明 ChatGPT 完成了这条文本链路与远程回写；尚不能据此认定提示链效果优于单提示，也不能称为原生 Org-Babel 模型执行。

* 一、真实任务
原始需求：透视结构放置区现在占据的空间很大，而且随着放置的维度和度量越多，高度就会越高，此外左边的侧边栏有一部分还空着，想办法合理调整下布局。

期望交付：一份简短、可供开发者检查与实施的布局修改任务单；本实验不修改 PivotStudio。

* 二、Prompt A：识别用户真正的问题
只提取事实、目标、限制和证据缺口；不提前提出解决方案。

#+name: prompt-a
#+begin_src text :eval never :exports code
阅读下面这段真实 UI 需求，只输出四项：
1. 已确认的现象；
2. 用户希望达到的效果；
3. 原始需求明确提出的限制（没有就写“未明确”）；
4. 仍然需要在真实界面中核实的信息。
不要猜测源码、尺寸或已有实现，也不要提出具体改造方案。

原始需求：

#+end_src

* 三、Prompt B：交付可执行任务单
由 AI 将 Prompt A 的完整原始输出连同原始需求交给 B；组合关系在提示词之外，不写入提示指令。

#+name: prompt-b
#+begin_src text :eval never :exports code
基于上一轮中的原始需求与问题摘要，直接输出一份最小开发任务单：
- 要解决的具体问题；
- 应检查的界面区域；
- 一项低风险、可以实际尝试的布局改动；
- 能在真实产品中检查的验收条件；
- 仍需现场确认的事实。
用人能直接读懂的短句。区分事实和建议，不假装已经查看或修改源码。
#+end_src

** Prompt A 实际回复（原样记录）
#+begin_example
1. **已确认的现象：** 透视结构放置区占用较多空间；维度和度量增加时，该区域高度持续增长；左侧侧边栏存在闲置空间。
2. **期望效果：** 更合理地分配布局空间，减少字段放置区对主要工作区域的挤占。
3. **明确限制：** 原始需求未明确规定必须采用哪种布局，也未规定具体组件的调整方式。
4. **待核实：** 放置区和侧边栏的实际尺寸、字段交互方式、滚动行为及不同窗口宽度下的布局表现。
#+end_example

- A 输出：上方“Prompt A 实际回复”的完整文本，未另行总结。
- B 指令：上方 Prompt B 纯文本正文。

** Prompt B 实际回复（原样记录）
#+begin_example
**目标：** 减少透视结构放置区的空间占用，避免字段数量增加时持续压缩主要工作区域。

**调整范围：** 透视结构放置区、左侧侧边栏及其与主要工作区的布局关系。

**优先方案：** 检查左侧侧边栏的可用空间。若空间与交互条件允许，将维度和度量配置组件整合到侧边栏，并使用局部滚动或折叠管理较多字段，避免整个页面高度随字段数量持续增加。

**验收条件：**

- 增加维度和度量后，主要工作区域不被持续向下挤压。
- 所有已放置字段仍然可以查看、调整和移除。
- 透视计算结果不受布局调整影响。
- 不同窗口宽度下不存在明显遮挡或异常溢出。

**待确认：** 侧边栏实际可用宽度、现有拖放交互、组件层级及响应式布局约束。
#+end_example

** 结论与证据边界
这次证明两条独立的纯文本提示能在 ChatGPT 中顺序生成结果，并将实验保存和发布到原文章。尚未验证多次运行的稳定性、两次独立模型调用、原生 Org-Babel 执行，以及相对单提示的质量提升；也没有实际修改 PivotStudio。
