写提示词时，我要先回答四个问题：/让模型做什么、它需要了解什么、它要依据什么、交付怎样才算合格/。单靠增加词数不一定能提高质量；关键是减少任务、来源和验收标准的歧义。〔补〕

* 快速使用
:PROPERTIES:
:CUSTOM_ID: 快速使用
:END:
| 遇到的问题   | 先改哪里 | 怎么验收                               |
|--------------+----------+----------------------------------------|
| 答非所问     | 指令     | 是否完成指定任务，而不是泛泛谈论主题   |
| 结果不贴业务 | 上下文   | 是否使用了正确的读者、业务场景和限制   |
| 结论没有依据 | 输入数据 | 能否逐条对应给定数据或材料             |
| 输出无法交付 | 输出标准 | 是否满足格式、范围、必要字段与质量要求 |

这四项是写作检查项，不是每一条提示都必须显式写出四个小标题。简单任务可以少写；高风险、复杂或需要自动验收的任务应明确写出判断依据。〔补〕

* 四个要素
:PROPERTIES:
:CUSTOM_ID: 四个要素
:END:
1. *指令*：明确动作和交付对象，例如“写一个 Python 加法函数并展示调用”。
2. *上下文*：说明读者或执行环境，例如“面向有 3 个月 Python 经验、正在学习数据处理的人”。
3. *输入数据*：给出要处理的对象或材料，例如 CSV 文件、列名或事实来源。不要凭空补充尚不存在的数据。〔补〕
4. *输出标准*：约定格式、范围和成功条件，例如返回字典、写单元测试或给出解释。输出标准不只是文风要求。

*边界*：提示词属于输入规范，不能保证模型输出正确。尤其是涉及性能、金融风控或事实判断时，示例里的指标是/需求条件/，不是/已验证结果/。〔补〕

* 三档示例
:PROPERTIES:
:CUSTOM_ID: 三档示例
:END:
任务复杂度变高时，增加的是有效约束，而不是机械增加字数。以下三段是原有完整案例的可复制任务文本；它们是提示，不是实际运行记录。

** 基础
:PROPERTIES:
:CUSTOM_ID: 基础
:END:
目标是用一个清楚的动作和一个可检查的交付要求训练基础写法。

** 进阶
:PROPERTIES:
:CUSTOM_ID: 进阶
:END:
增加用户能力背景、输入数据、统计方法和返回值格式，便于按结果逐项检查。

** 高阶
:PROPERTIES:
:CUSTOM_ID: 高阶
:END:
增加吞吐、特征、延迟、算法、日志和测试要求。原例中的“每秒约 1000 条、25 个特征、50 ms”是案例设定或性能目标，未提供测量日志，不能说系统已经达到该水平。〔补〕

* 用后怎样检查
:PROPERTIES:
:CUSTOM_ID: 用后怎样检查
:END:
1. *核对任务*：是否逐项回答需求；是否遗漏关键输入、对象和限定词。
2. *核对来源*：输出里的事实能否回指输入；不确定的判断有没有被写成确定结论。
3. *核对交付*：格式、字段、测试或示例是否满足标准；代码若未运行就不能标“测试通过”。
4. *最小调整*：先改最早出现歧义的一项，再用相同测试案例重新比较。不同模型可能产生不同答案，不能只凭一次输出宣布最佳提示。〔补〕

* 常见误区
:PROPERTIES:
:CUSTOM_ID: 常见误区
:END:
原有笔记特别提醒四件事：不能只写一次提示而忽视迭代；不同模型的响应可能不同；专业领域需要专门的上下文；还要检查误导性和有害输出。它们属于提示设计的约束，不代表已开展针对模型的对比实测。

* 提示优化助手
:PROPERTIES:
:CUSTOM_ID: 提示优化助手
:END:
=@prompt_optimizer= 是原笔记提供的一种/文本调用格式/，没有证据显示它是当前 ChatGPT 或其他工具已安装的真实命令。使用时应把它和相应字段作为普通提示文本提交给模型，不能仅发送命令名就假定系统会调用已部署工具。〔补〕

本模板还给出三个完整使用场景：数据科学代码、创意小说和小学科普。保留下方 XML 模板与原始填写实例，作为可复制的来源资产。示例里提到的 COVID-19 相关性分析只是任务要求，并非已经完成分析。

* 阅读示例
:PROPERTIES:
:CUSTOM_ID: 阅读示例
:END:
原阅读材料说明提示可以是单条指令，也可以是一组逐渐改进的指令。用故事、图像与“600 字全球变暖论文”说明如何增加任务背景、数据和输出要求；这些例子强调/表达更具体/，并没有通过对照实验测量提升幅度。

** 三档原始提示

*** 基础

#+begin_src text
写一个简单的Python函数，实现两个数字相加。请包含函数定义和一个使用示例。
#+end_src


*** 进阶

#+begin_src text
我是一位有3个月Python经验的开发者，正在学习数据处理。请编写一个Python函数，用于处理CSV文件中的数值数据，实现以下功能：
- 读取指定CSV文件的特定列
- 对该列数据进行基本统计分析（平均值、中位数、标准差）
- 处理可能存在的缺失值
请使用pandas库实现，并确保代码包含详细注释解释每个关键步骤。函数应该返回一个包含统计结果的字典，并提供一个完整的使用示例，包括如何处理名为 “sales_data.csv ” 中的 “monthly_revenue ” 列。
#+end_src


*** 高阶

#+begin_src text
作为一家金融科技公司的高级Python工程师，我需要开发一个健壮的数据分析模块，用于实时处理交易数据流并检测潜在的欺诈模式。
背景：我们的系统每秒接收约1000条交易记录，每条记录包含25个特征（时间戳、金额、地理位置、设备信息等）。历史数据表明，欺诈交易通常表现出特定的时间序列异常模式。
任务：设计并实现一个高性能Python类，该类应：
- 使用适当的数据结构维护一个滑动时间窗口内的交易数据
- 实现至少两种异常检测算法（可考虑孤立森林、局部异常因子等）
- 采用并行处理优化性能，处理延迟不超过50ms
- 包含适当的错误处理和日志记录机制
- 能适应不同的欺诈模式（提供配置接口）
代码应符合PEP 8标准，包含完整的类型注解，并附带单元测试展示其在不同负载情况下的性能和准确性。
请特别关注内存使用效率和算法复杂度分析。提供简明的文档说明如何扩展该模块以适应新的欺诈检测算法。
#+end_src
