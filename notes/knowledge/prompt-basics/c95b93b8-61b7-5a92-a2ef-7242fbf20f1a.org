不要先追求长提示词。先确定任务是什么、模型能参考什么、最后怎样判断结果合格。原稿把有效提示词归纳为四个要素，并给出三种复杂度的实际提示和一套 XML 优化模板。本版将使用入口置前，保留原样模板与具体示例。原稿中的“效果”是用途与预期描述，不是经测试的模型性能记录。

* 四个必要问题

| 要素 | 使用时先问 | 常见遗漏 |
|------+------+----------|
| 明确指令 | 我要模型完成什么动作？ | 只有话题，没有任务 |
| 上下文 | 读者、场景、约束和已有状态是什么？ | 模型不知道使用条件 |
| 输入数据 | 哪些文件、字段、示例或事实可以引用？ | 输入范围不清 |
| 输出指标 | 交付什么格式？什么质量算合格？ | 只约束文风，不约束正确性 |

这四项是原文的分析框架，不是每次都必须填满的固定表单。简单任务可以只给明确指令；复杂任务应写出已知条件、必要数据和可验证标准。〔补〕

* 三档真实提示

同一类技术任务的复杂度提高时，提示会增加背景、输入和验收约束。这不证明长提示一定优于短提示。

** 基础

#+begin_src text
写一个简单的Python函数，实现两个数字相加。请包含函数定义和一个使用示例。
#+end_src

*原稿的结构分析：* 指令：写一个Python函数；上下文：无（基础级通常简化上下文）；输入数据：两个数字；输出指标：包含函数定义和使用示例。

*原稿预期：* 生成一个基础的加法函数，适合编程初学者理解函数概念和基本语法。

** 进阶

#+begin_src text
我是一位有3个月Python经验的开发者，正在学习数据处理。请编写一个Python函数，用于处理CSV文件中的数值数据，实现以下功能：
读取指定CSV文件的特定列
对该列数据进行基本统计分析（平均值、中位数、标准差）
处理可能存在的缺失值
请使用pandas库实现，并确保代码包含详细注释解释每个关键步骤。函数应该返回一个包含统计结果的字典，并提供一个完整的使用示例，包括如何处理名为 *“sales_data.csv”* 中的 *“monthly_revenue”* 列。
#+end_src

*原稿的结构分析：* 指令：编写具有特定功能的Python函数；上下文：面向有3个月经验的开发者，学习数据处理；输入数据：CSV文件的具体场景，文件名和列名示例；输出指标：使用pandas库，包含详细注释，返回特定格式，附带完整示例。

*原稿预期：* 生成一个实用的数据处理函数，整合多个编程概念，需要理解库的使用和数据处理流程。

** 高阶

#+begin_src text
作为一家金融科技公司的高级Python工程师，我需要开发一个健壮的数据分析模块，用于实时处理交易数据流并检测潜在的欺诈模式。
背景：我们的系统每秒接收约1000条交易记录，每条记录包含25个特征（时间戳、金额、地理位置、设备信息等）。历史数据表明，欺诈交易通常表现出特定的时间序列异常模式。
任务：设计并实现一个高性能Python类，该类应：
使用适当的数据结构维护一个滑动时间窗口内的交易数据
实现至少两种异常检测算法（可考虑孤立森林、局部异常因子等）
采用并行处理优化性能，处理延迟不超过50ms
包含适当的错误处理和日志记录机制
能适应不同的欺诈模式（提供配置接口）
代码应符合PEP 8标准，包含完整的类型注解，并附带单元测试展示其在不同负载情况下的性能和准确性。
请特别关注内存使用效率和算法复杂度分析。提供简明的文档说明如何扩展该模块以适应新的欺诈检测算法。
#+end_src

*原稿的结构分析：* 指令：设计并实现具有特定功能的Python类；上下文：金融科技公司、高级工程师角色、实时交易数据、欺诈检测需求；输入数据：详细的系统参数、数据特征、性能要求和历史观察；输出指标：多重质量标准（PEP 8、类型注解、单元测试）、性能要求、文档要求、扩展性要求。

*原稿预期：* 生成一个复杂的解决方案，需要整合高级编程概念、算法知识、系统设计经验和领域专业知识。

* 一次最小迭代〔补〕

1. 保留第一版提示与模型的真实输出，不凭印象打分。
2. 记录失败点：错误事实、遗漏、格式不符或不可运行的代码。
3. 只修改与失败点相关的指令、上下文、输入或验收条件。
4. 在相同输入和相同模型条件下重试；必要时换新样本，检查是否只是记住了旧案例。
5. 比较事实准确性、可执行性与格式是否改善。未实测时只能写“预期”，不能写“已提升”。

原文提醒：不同模型、不同领域会产生不同响应；复杂任务还要检查误导、有害输出和领域风险。

* 使用边界与来源

- 原稿 HTML 表格中的 =sales_data.csv= 与 =monthly_revenue= 被混入 HTML 下标标签；本版恢复为普通文件名排版。该字段拼写需要使用者根据真实数据核对。
- 高阶案例所写“每秒约 1000 条交易、25 个特征、延迟不超过 50ms”是示例需求，不是经过性能测试的系统事实。
- 原稿的“输出效果”是描述性预期；没有任何模型运行、实测评分、代码执行或安全验证记录，不得以此推断效果已提升。
