一个提示词是否可用，不能只看它是不是写得长。先确认任务、背景、输入和结果条件是否能被独立核对。以下是基于原文整理的操作入口；不是对模型输出质量的实测保证。

* 判断入口
| 遇到的问题 | 优先补什么 | 检查方式 |
|-------------------+-------------+----------------------|
| 回答方向不对 | 指令 | 是否能说清唯一主任务 |
| 输出泛泛而谈 | 上下文 | 是否交代角色、场景和边界 |
| 回答凭空补数据 | 输入数据 | 是否指定材料及未知字段处理 |
| 结果无法验收 | 输出期望 | 是否明确结构、数量及验证条件 |

* 从简单到复杂
原文用同一类 Python 开发任务比较了基础、进阶和高阶提示。这些是需求复杂度的演示，不能据此认定更长的提示一定效果更好。

1. *基础*：实现两个数相加的 Python 函数，要求函数定义和调用示例。
2. *进阶*：处理 CSV 数值列，指定 pandas、均值/中位数/标准差、缺失值、示例与返回格式；原文示例涉及 =sales_data.csv= 和 =monthly_revenue=。
3. *高阶*：实时交易数据的异常检测模块，示例假设每秒约 1000 条记录、25 个特征、处理延迟不超过 50ms，并提出并行、日志、单元测试等要求。*这是提示中的预期指标，不是通过测试的性能数据。*

* 可复制的最小模板
#+begin_example
任务：我要完成 [唯一的主要任务]。
场景：[角色、对象、限制和使用场合]。
输入：[已提供的材料、字段和缺失项]。
输出：[结果格式、检查点、不得推断的部分]。
请先指出信息缺口；不清楚的事实标记待确认。
#+end_example

* 原文中的两个短例
#+begin_example
简单提示："山间的日落图像"
有效提示："生成一张平静的日落图像，展示位于群山之间的河谷。"
#+end_example
这些短例说明约束有助于限定目标，不证明某个模型必定生成更好的图片。

* 何时停止迭代
用同一材料比较两版输出。记录遗漏、臆造、格式错误和成本，再决定是否保留修改。原文提供一段 XML 提示优化模板和其他示例，原样保存在附件；不得把示例中的假设性能数字升级为已测结论。
