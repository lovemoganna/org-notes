写提示词之前，先回答四个问题：要求模型做什么、为什么做、基于哪些输入、交付结果怎样检查。复杂度不同，输入的约束也应不同。原文包含四要素、三档完整示例和一套可复制的 XML 风格优化模板；这些不可替代的素材都保留在下文。

* 四个输入要素
| 要素 | 先回答的问题 | 缺失时常见风险 |
|------+----------------+------------------|
| 指令 | 做什么？ | 任务范围含糊 |
| 上下文 | 在什么情境使用？ | 目标和读者错配 |
| 输入数据 | 具体依据是什么？ | 用模型猜测替代数据 |
| 输出标准 | 怎么判断结果合格？ | 仅规定格式，无法验收 |

这是一份检查清单，不是每条请求都必须填写四个栏目。原文明确强调“输出指标”既包括格式，也包括质量、长度、风格等要求。

* 选任务难度
以下三档来自原文的 HTML 表格，只恢复了源 HTML 将下划线渲染为下标的文件名展示；任务要求并不是已完成的运行结果。

** 基础
- *作用*：生成一个基础的加法函数，适合编程初学者理解函数概念和基本语法。
- *四要素分析*：
  • 指令：写一个Python函数
  •
  • 上下文：无（基础级通常简化上下文）
  •
  • 输入数据：两个数字
  •
  • 输出指标：包含函数定义和使用示例
  •
#+begin_example
写一个简单的Python函数，实现两个数字相加。请包含函数定义和一个使用示例。
#+end_example

** 进阶
- *作用*：生成一个实用的数据处理函数，整合多个编程概念，需要理解库的使用和数据处理流程。
- *四要素分析*：
  • 指令：编写具有特定功能的Python函数
  •
  • 上下文：面向有3个月经验的开发者，学习数据处理
  •
  • 输入数据：CSV文件的具体场景，文件名和列名示例
  •
  • 输出指标：使用pandas库，包含详细注释，返回特定格式，附带完整示例
  •
#+begin_example
我是一位有3个月Python经验的开发者，正在学习数据处理。请编写一个Python函数，用于处理CSV文件中的数值数据，实现以下功能：

• 读取指定CSV文件的特定列
•

• 对该列数据进行基本统计分析（平均值、中位数、标准差）
•

• 处理可能存在的缺失值
•

请使用pandas库实现，并确保代码包含详细注释解释每个关键步骤。函数应该返回一个包含统计结果的字典，并提供一个完整的使用示例，包括如何处理名为 *“sales_data.csv”* 中的 *“monthly_revenue”* 列。
#+end_example

** 高阶
- *作用*：生成一个复杂的解决方案，需要整合高级编程概念、算法知识、系统设计经验和领域专业知识。
- *四要素分析*：
  • 指令：设计并实现具有特定功能的Python类
  •
  • 上下文：金融科技公司、高级工程师角色、实时交易数据、欺诈检测需求
  •
  • 输入数据：详细的系统参数、数据特征、性能要求和历史观察
  •
  • 输出指标：多重质量标准（PEP 8、类型注解、单元测试）、性能要求、文档要求、扩展性要求
  •
#+begin_example
作为一家金融科技公司的高级Python工程师，我需要开发一个健壮的数据分析模块，用于实时处理交易数据流并检测潜在的欺诈模式。
背景：我们的系统每秒接收约1000条交易记录，每条记录包含25个特征（时间戳、金额、地理位置、设备信息等）。历史数据表明，欺诈交易通常表现出特定的时间序列异常模式。
任务：设计并实现一个高性能Python类，该类应：

• 使用适当的数据结构维护一个滑动时间窗口内的交易数据
•

• 实现至少两种异常检测算法（可考虑孤立森林、局部异常因子等）
•

• 采用并行处理优化性能，处理延迟不超过50ms
•

• 包含适当的错误处理和日志记录机制
•

• 能适应不同的欺诈模式（提供配置接口）
•

代码应符合PEP 8标准，包含完整的类型注解，并附带单元测试展示其在不同负载情况下的性能和准确性。
请特别关注内存使用效率和算法复杂度分析。提供简明的文档说明如何扩展该模块以适应新的欺诈检测算法。
#+end_example

* 如何检验实际效果
1. *固定条件*：同一个任务、同一输入材料和同一模型环境，保存原提示与优化提示。
2. *比较结果*：根据内容准确性、约束遵守、完整性与可用性逐项比较；不能仅因新提示更长就说效果更好。〔补〕
3. *记录限制*：如果没有实际运行、基准结果或可复核评价，只能写成“示例需求”，不能写成“已达到性能目标”。

例如，高阶示例提出每秒约 1000 条交易、25 个特征、延迟不超过 50ms、至少两种异常检测算法。这些都是输入里的设计要求，*不是已经测到的系统性能或欺诈检出率*。

* 选择与边界
- *快速问答*：先写明任务和输出格式；没有独立数据时不要虚构来源。
- *研究与分析*：补充数据、适用条件、方法和评价标准，并要求明确不确定性。
- *代码与风控任务*：把性能、正确性、风险边界和可复核测试写入要求；不要把生成代码当作已通过工程验收。
- *需要优化旧提示*：使用上面的原始模板；将真实输入、目标输出、已知问题与建议数量同时写清楚。
