这篇笔记用于判断：*一条提示词缺了什么、该补到什么程度，以及怎样证明改进有效*。完整度取决于任务，不是字段越多越好。原材料中的梯度案例是设计要求，未提供实测性能数据。

* 四个输入要素
:PROPERTIES:
:CUSTOM_ID: 四个输入要素
:END:
| 要素     | 需要写清楚               | 检查问题                     |
|----------+--------------------------+------------------------------|
| 指令     | 期望模型执行的动作       | 输出能否区分“解释”与“实施”？ |
| 上下文   | 任务背景、读者和限制     | 哪些情况会改变答案？         |
| 输入数据 | 已知材料、字段和例子     | 事实与假设是否分离？         |
| 输出标准 | 格式、质量要求、失败条件 | 什么结果需要重试？           |

当任务是简单、通用的加法函数，只要动作与使用示例就可能足够；当任务是交易异常检测，才需要吞吐量、特征定义、延迟预算、测试条件与错误处置。*不能把高级例子的性能目标当成模型已实现的表现。*

* 三档原始案例
:PROPERTIES:
:CUSTOM_ID: 三档原始案例
:END:
1. *基础：* 写一个两个数字相加的 Python 函数，包含定义与调用示例。检查是否可以运行，不能只看代码像不像。
2. *进阶：* 面向有三个月 Python 经验的开发者，读取 CSV 指定列，计算平均值、中位数和标准差，处理缺失值；原文例子指定 pandas、=sales_data.csv= 与 =monthly_revenue=。验收需有可运行的数据样本。
3. *高阶：* 交易数据实时异常检测的设计任务，原文设想每秒约 1,000 条记录、每条 25 个特征、处理延迟不超过 50 ms，提出滑动窗口、至少两类算法、并行处理、日志、类型注解和单元测试。*这些只是输入约束，不是已经实现或测得的性能。*

* 使用与验证
:PROPERTIES:
:CUSTOM_ID: 使用与验证
:END:
1. 填写用户级别、任务类型、当前问题、原始提示、期望输出；再决定是否需要专用模型偏好与建议数量。
2. 固定一组有代表性的输入，对比原始提示和改写提示产生的实际结果。
3. 按准确性、结构、遗漏、无依据推断、重试成本等同一口径记录差异。没有运行记录时，只能称优化建议，不能称有效性提升。
4. 保留原始提示与修改清单；不同模型、参数或数据集必须单独报告结果。
