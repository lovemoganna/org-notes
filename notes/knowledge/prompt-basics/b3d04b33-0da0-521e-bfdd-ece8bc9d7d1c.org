[[file:../../../note-assets/b3d04b33-0da0-521e-bfdd-ece8bc9d7d1c/sketchnote-header.webp]]

一条提示是否有用，取决于任务是否说清、输入是否真实、验收标准是否可操作。提示词复杂度应随任务复杂度调整，不能简单认为字段越多越好。

* 四个输入要素
| 要素 | 应说明的内容 | 反查问题 |
|------+--------------+----------|
| 指令 | 期望执行的具体动作 | 需要解释、编写还是验证？ |
| 上下文 | 背景、受众与限制 | 哪些条件会改变答案？ |
| 输入数据 | 已知资料、字段与实例 | 事实、假设是否分离？ |
| 输出标准 | 形式、质量及失败条件 | 怎样确认结果达标？ |

* 三档案例
1. *基础*：生成两个数字相加的 Python 函数，附定义与调用示例。
2. *进阶*：对 =sales_data.csv= 中的 =monthly_revenue= 列用 pandas 做平均值、中位数、标准差统计，并处理缺失值。原始背景为有三个月 Python 经验的开发者。
3. *高阶*：原文设想每秒约 1000 条、25 个特征的交易异常监测任务，要求至少两种异常检测算法、滑动窗口、并行处理、日志、类型注解和测试，并提出 50ms 延迟上限。*这些均为设计要求，没有实测性能记录。*

* 使用与验收
1. 填写任务、背景、原始提示、期望输出；针对当前任务配置必要字段。
2. 固定代表性测试集和模型参数，对照旧提示与新提示的实际输出。
3. 记录准确性、结构遗漏、错误推断及重试成本；没有运行记录时只能称“建议”，不能宣称改进有效。
4. 保留编辑历史。不同模型、数据集或参数要分别验证。

* 来源和边界
原文另含完整的梯度 HTML 表格、XML 详细模板以及三个应用的全部输入。完整素材请阅读冻结的源文件，不能用本页的精简实例取代原始完整模板。
新增判断〔补〕：提示结构只是质量条件之一，最终效果必须通过相同任务的结果比较验证。
