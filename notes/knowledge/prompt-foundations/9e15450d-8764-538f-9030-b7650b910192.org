* 先解决哪个问题
拿到一个含糊需求时，为什么模型经常给出方向正确、却不符合实际用途的答案？原材料将有效提示拆成四个要素：*指令、上下文、输入数据、输出指标*。这不是结果保证，而是把需求写得可检查的输入框架。

* 四要素
| 要素 | 必须说明 | 缺失后的典型风险 |
|------+----------+----------------|
| 指令 | 具体要完成的动作 | 回答跑题或泛泛而谈 |
| 上下文 | 使用者、场景和限制 | 错用背景或专业程度 |
| 输入数据 | 用于回答的真实材料与范围 | 模型补造未给的数据 |
| 输出指标 | 格式、长度、口径和验收要求 | 有答案却不能直接使用 |

* 先做一次梯度实验
原材料比较了基础 Python 加法题与进阶 CSV 数据处理题。前者只要求定义函数并给出示例；后者补充了“约有三个月 Python 经验”、使用 pandas、读取指定列、计算平均值、中位数和标准差、处理缺失值，以及 =sales_data.csv= 中的 =monthly_revenue= 字段。后者给出更多约束，并不意味着已经验证代码能够运行。

#+begin_example
任务：分析 CSV 中的月度收入字段。
背景：读者有三个月 Python 使用经验。
输入：sales_data.csv；列 monthly_revenue。
输出：使用 pandas；说明缺失值处理；计算平均值、中位数和标准差；给出返回字典及调用示例。
#+end_example

* 怎么决定是否增加信息
1. 先看答案是否正确执行了核心动作。没有执行就补充“指令”。
2. 若对象、领域或受众错误，补充“上下文”。
3. 若回答引用了不存在的数据，明确“输入数据”的来源与禁用范围。
4. 若结果难以验收，补充“输出指标”，例如原文中的“600 字论文”或明确的代码输出形式。

原稿还使用了故事创作和山谷日落图像两组简单/有效提示对照。这些示例展示的是描述程度差异，并没有构成生成质量的受控实验。

* 验收与边界
同一任务先跑基础提示，再增补最缺失的一项，保存两个实际输出，比较任务满足度、事实错误和可使用性。只评提示文本的完整度，不能推断模型必然正确。〔补〕
