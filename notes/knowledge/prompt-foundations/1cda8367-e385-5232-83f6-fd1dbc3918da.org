* 四要素：先明确任务
有效的提示应说明指令、上下文、输入数据和输出指标。没有必要的背景无需硬加；复杂任务需要的是可判断、可追溯的限制，而非更长的标题。

| 要素 | 核心问题 | 示例 |
|------+----------+------|
| 指令 | 要完成什么动作？ | 写 Python 函数 |
| 上下文 | 谁在什么环境使用？ | 有三个月经验的学习者 |
| 输入 | 基于什么实际材料？ | CSV 文件、字段及单位 |
| 输出指标 | 怎么知道结果正确？ | 统计字典和调用示例 |

* 分层示例
三份提示按任务约束由少到多排列，而不是“越长越好”的效果排名。以下均为来源中的教学输入；没有记录模型执行或性能测量结果。

** 基础
只需一个可核对的函数和调用示例，不必额外编造背景。
#+begin_example
写一个简单的Python函数，实现两个数字相加。请包含函数定义和一个使用示例。
#+end_example

** 进阶
加入使用者背景、数据结构、缺失值处理和可检查的返回值。文件名与列名是示例输入，不代表文件已经存在。
#+begin_example
我是一位有3个月Python经验的开发者，正在学习数据处理。请编写一个Python函数，用于处理CSV文件中的数值数据，实现以下功能：
- 读取指定CSV文件的特定列
- 对该列数据进行基本统计分析（平均值、中位数、标准差）
- 处理可能存在的缺失值
请使用pandas库实现，并确保代码包含详细注释解释每个关键步骤。函数应该返回一个包含统计结果的字典，并提供一个完整的使用示例，包括如何处理名为 *“sales_data.csv”* 中的 *“monthly_revenue”* 列。
#+end_example

** 高阶
将交易流、模型算法、日志、配置、测试和性能边界一次说明。每秒约 1000 条、25 个特征、延迟不超过 50 ms 均是*场景假设或要求*，不是已经验证的系统性能。
#+begin_example
作为一家金融科技公司的高级Python工程师，我需要开发一个健壮的数据分析模块，用于实时处理交易数据流并检测潜在的欺诈模式。
背景：我们的系统每秒接收约1000条交易记录，每条记录包含25个特征（时间戳、金额、地理位置、设备信息等）。历史数据表明，欺诈交易通常表现出特定的时间序列异常模式。
任务：设计并实现一个高性能Python类，该类应：
- 使用适当的数据结构维护一个滑动时间窗口内的交易数据
- 实现至少两种异常检测算法（可考虑孤立森林、局部异常因子等）
- 采用并行处理优化性能，处理延迟不超过50ms
- 包含适当的错误处理和日志记录机制
- 能适应不同的欺诈模式（提供配置接口）
代码应符合PEP 8标准，包含完整的类型注解，并附带单元测试展示其在不同负载情况下的性能和准确性。
请特别关注内存使用效率和算法复杂度分析。提供简明的文档说明如何扩展该模块以适应新的欺诈检测算法。
#+end_example

** 选择方法〔补〕
任务只有一个明确动作时用基础版；需要已有数据和规定格式时用进阶版；存在多种算法、性能与风险约束时才用高阶版。先选最短且足够完整的版本，再用实际输出判断是否需要增加信息。

原始资料以 HTML 表格展示，部分标识符的下划线被渲染为下标；上述可复制稿恢复为 =sales_data.csv= 和 =monthly_revenue=。完整 HTML 原貌另存于文末原始来源附件。
* 最小执行流程
1. 明确动作及对象，不用“分析一下”替代需求。
2. 列出真正可获得的数据及领域限制。
3. 固定输出形状、校验条件和异常边界。
4. 保留前后提示及相同测试输入，核验而非自评改善。

* 根据缺失信息修正提示词
当答案方向正确，却不符合实际用途时，先定位缺失信息，不直接加长整段提示。
1. *指令缺失*：没有完成核心动作时，写明具体动作与对象，避免泛泛回答。
2. *上下文缺失*：使用者、业务环境或专业程度不匹配时，补充适用场景与限制。
3. *输入缺失*：回答引用了不存在的材料时，列明实际来源、可用字段和禁止推断的范围。
4. *输出指标缺失*：结果难以使用或验收时，写明格式、长度、计算口径及判断条件。例如要求“600 字论文”，就要明确长度及评估内容。

* 对照实验与验证边界
在同一个模型、同一配置与同一任务输入下，先运行基础提示，再只补最缺失的一项，分别保存真实输出。检查任务满足度、事实错误和结果可使用性，记录改善与反例。没有实际执行时只能提出待验证的改进方向，不能宣称模型效果已经提升。〔补〕
