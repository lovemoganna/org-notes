* 这 20U 究竟在验证什么

20 USDT 足以检验一笔小额现货订单能否正确执行，却不足以仅凭少数交易证明策略长期赚钱。第一次实盘的主要产出不是收益，而是一份能解释买入、持有、退出和实际费用的成交记录。

三个目标不能混为一谈：

| 目标 | 要回答的问题 | 证据 |
|-
| 订单执行 | 能否按计划买入、卖出并结算？ | 订单号、成交数量、时间、手续费、余额变化 |
| 策略判断 | 预设规则在扣费后是否可能有优势？ | 独立于调参样本的历史测试、模拟记录和实盘记录 |
| 自动化 | 程序能否稳定重现已定义规则？ | 下单日志、异常处置、对账结果 |

达成第一项不证明第二项；安装交易机器人不等于具备第三项。零杠杆现货没有合约式强平，但所持币仍可能大幅下跌甚至失去流动性。

* 下单前：先检验 20U 是否够用

不要先挑币再研究能否下单。先固定合规可使用的交易所和现货交易对，并在当日交易界面查四件事：

1. =最小成交金额=（Notional）：单笔订单按价格乘数量是否达到门槛。
2. =最小数量及步长=（LOT_SIZE）：可以买入、卖出的数量和精度。
3. =实际手续费=：区分挂单成交（Maker）和立即吃单成交（Taker），留意活动、地区与账户等级。
4. =退出能力=：止损单和 OCO 是否适用于该现货交易对，卖出时是否会因数量取整而留下不可交易的零碎币。

Binance 不同交易对有不同 =MIN_NOTIONAL/NOTIONAL= 和 =LOT_SIZE= 过滤器，不能假设所有币都支持 5U 订单。Kraken 在 2026-10-20 的最低额说明中，以 BTC =0.0001 BTC=、ETH =0.01 ETH= 举例；它们是基础币数量门槛，不等于固定的 USDT 金额。具体能否用 10U 买入，取决于当时价格和交易对实际规则。

官方依据：[[https://www.binance.com/en/support/faq/detail/115000594711][Binance 现货限额]]、[[https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/general][Binance exchangeInfo API]]、[[https://support.kraken.com/articles/360001389303-overview-of-cryptocurrency-minimums][Kraken 最低交易量]]。

* 先计算成本，而不是先预测涨跌

假设拿 10U 买入，买卖各收一次 Taker 手续费，忽略成交价格变化、点差和滑点，往返费用约为：

| 单边费率 | 10U 一买一卖的费用 |
|-
| 0.10% | 0.020 U |
| 0.80% | 0.160 U |
| 0.90% | 0.180 U |

这是费率情景计算，不是任一账户的报价。2026 年官方资料列出的示例包括 Binance 国际站普通用户现货约 =0.10%=；Kraken Pro 基础等级 Taker =0.80%=；Coinbase Advanced 美国低交易量等级 Taker =0.90%=。地区、会员等级、交易对和活动可能改变结果。

实际净盈亏用成交单核算：=卖出到账金额 - 买入付出金额 - 双边手续费=。若成交价格已经是真实成交价，不要再把滑点额外重复扣一次；滑点用于解释与预期价格的偏差。价格波动、资产计价和手续费币种还可能影响计算口径。

官方费率：[[https://www.binance.com/en/fee/trading][Binance]]、[[https://www.kraken.com/features/fee-schedule][Kraken Pro]]、[[https://www.coinbase.com/blog/were-lowering-fees-for-many-active-traders-on-coinbase-advanced][Coinbase Advanced 2026 年调整]]。

* 第一轮实验怎么做

以下是学习实验的默认安排，不是交易信号或收益承诺。

1. 先在模拟环境练习：用一种流动性较好的现货交易对（例如 BTC/USDT，须确认平台可交易），下限价单、撤单、查看成交明细，再练习退出。
2. 写下本轮假设：例如观察 4 小时 K 线是否出现收盘突破。必须先定义突破条件，再观察下一根 K 线的实际交易机会，不能用事后图形选择“完美买点”。
3. 确定单笔额度：20U 中暂定只动用约 10U，其余保留。若买入额或止损卖出额不满足平台门槛，则缩小策略复杂度或继续模拟，不要为了满足门槛盲目加钱。
4. 下单前写退出条件：教学参数可暂设止损 =-3%=、止盈 =+5%=。以 10U 为例，忽略手续费时对应 =-0.30U= 与 =+0.50U= 的仓位损益；真实结果必须加回实际成交成本。止损是触发条件，不保证成交价。
5. 核对成交后记录原始证据：订单号、委托时间、成交时间、成交价、数量、手续费、账户余额。不成交、部分成交、取消、卖出数量不足都应当留记录。
6. 退出后对账：分别计算价格收益、费用与最终净盈亏，并检查是否照着事前规则执行。

别把“只需几天掌握策略”当作可检验目标。前两周可用于熟悉操作，后续交易次数取决于是否出现事先定义的条件；没有机会时不交易也是正确执行。

** 一个可检验但尚未验证的策略假设〔补〕

若需要固定观察规则，可暂定：只观察 BTC 现货，4 小时已收盘 K 线收盘价同时高于此前 20 根已收盘 K 线的最高价和当前 20 周期均线，才产生候选买入信号。实际执行不得提前使用未收盘数据；以信号产生后可成交的价格评估。先在历史样本外数据与模拟盘检验，再决定是否进行真实买卖。

该规则尚无本篇提供的回测成绩、真实成交胜率或净收益证据；参数 =20=、=-3%=、=+5%= 只是演示变量，不是最优值。价格跳空、流动性骤降和交易所故障可能使实际亏损超过计算中的止损金额。

* 什么时候引入机器人

先能人工执行并复盘，再考虑自动化。否则机器人只是更快地重复未验证的交易。

- 想理解订单和风控：先用交易所现货界面，不必写代码。
- 规则相对固定、想回测和模拟执行：[[https://github.com/freqtrade/freqtrade][Freqtrade]] 支持回测、Dry-Run 和现货实盘；其中最低下单额还会受到预留比例与止损计算影响。
- 想自己控制交易所接口：[[https://github.com/ccxt/ccxt][CCXT]] 能实现行情读取与订单创建，但它是 API 工具库，不会自动提供盈利策略，也不替用户解决风控。
- 想运行多层现货网格：20U 通常容易受多笔订单门槛约束。先验证每格最低金额、费用与总资产净值，不以“网格已实现利润”代替整体盈亏。

接入 API 时仅授予必要的读取、现货交易权限；禁止提现权限，保护密钥并限制风险敞口。程序异常或网络断开时必须有停止下单和人工退出的路径。

* YouTube 的实盘案例怎样筛

视频可以教操作，但“LIVE TRADING”“80% 胜率”“被动收入”不能证明完整真实盈利记录。区分三种证据：讲解图表、展示委托与成交、可核对的连续完整账本。只有第三种才有资格支持长期业绩判断。

- [[https://www.youtube.com/watch?v=pK4GWB1fGDQ][Binance 现货交易教程（2025）]]：适合核对买卖界面和订单类型；教程不等于交易业绩。
- [[https://www.youtube.com/watch?v=BTuxJDWbAOY][Kiel Wilson：现货 OCO 操作（2023）]]：适合学习止盈与止损的条件委托；界面可能已变化。
- [[https://www.youtube.com/watch?v=apCZMd0UFfk][SerCrypto：Spot Grid Bot（2026-10-17）]]：作为现货网格机制案例；未核实完整实盘账本或长期净利润。

视频作者可能有教学、吸引订阅者或推荐佣金等多种动机，不能仅凭内容推断个人利益。应查阅披露和原始成交证据；[[https://www.kraken.com/affiliate][Kraken 官方联盟计划]] 说明交易相关返佣机制确实存在。

* 何时算完成入门

- 执行完成：能根据当日规则独立完成真实的买入、卖出与余额对账，无意外杠杆或提现权限。
- 策略进入验证阶段：同一套规则能在历史、模拟与实盘记录中一致复现；净收益按实际成本核算，并记录亏损和未成交。
- 自动化具备前提：已有明确的风控、异常处理和停止规则；程序运行与成交记录可复核。

投入 20U 不等于一定要把 20U 全部交易。若最低订单额、费用或退出限制使试验失去意义，停止实盘，继续模拟即可。
