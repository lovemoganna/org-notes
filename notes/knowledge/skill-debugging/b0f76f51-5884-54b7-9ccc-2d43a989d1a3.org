* 要解决的不是测试次数，而是无效循环
当 Skill 一改再改、当前样本通过但旧能力退化、提示词越补越长时，问题通常不在“测试不够多”，而在没有锁定验收契约、没有真实失败证据、或把每次反馈都变成永久规则。

默认采用六阶段：=需求与基线 → 测试准备 → 执行与诊断 → 修复与瘦身 → 回归与验收 → 仓库维护与退出=。六阶段是职责边界，不代表每个无缺陷任务都必须执行修改。未发现问题可跳过修复，未验证不能记为通过。

| 遇到的症状 | 进入阶段 | 必须取得的结果 |
|------------+----------+----------------|
| 目标漂移、版本不明、提示冲突 | 01 | 目标、约束、验收条件、Git 基线 |
| 无法判断测试是否足够 | 02 | 最小有效用例集和真实环境 |
| 模型只说“通过”，没有实际产物 | 03 | 真实输入、执行记录和失败证据 |
| 重复规则、补丁堆积、逻辑错误 | 04 | 对应根因的最小差异与精简依据 |
| 改好当前例子却破坏旧功能 | 05 | 原失败案例、旧案例、独立反例与 E2E |
| 通过后仓库留下大量垃圾文件 | 06 | 干净版本、保留的回归资产、提交回执 |

* 六阶段：可直接复制执行的提示资产
以下是当前任务的主调用模板。同一任务只选一个主 Skill；其他 Skill 仅在出现实际职责缺口时调用。提示词的真实执行效果尚未完成统一跨模型实测。

** 01 需求与基线
#+begin_example
读取 GitHub 当前版本及 MAINTENANCE.md。根据任务调用对应 Skill，确认目标、现有能力、依赖关系和验收标准。统计文件规模，识别重复、冲突及疑似无效内容。保留可回滚基线，不做修改。
#+end_example

验收：原始需求未变，验收条件可以逐项判定，Git 基线及必要依赖可追溯。只有产品 / BRD 需求才使用 =bprd-plus=，不能让它替代通用运行验证。

** 02 测试准备
#+begin_example
读取目标 Skill 最新规则和必要依赖。检查运行环境，复用现有测试资产，建立覆盖核心功能、关键边界和历史失败的最小测试集。合并等价用例，保留具有独立检错能力的测试，明确通过标准。
#+end_example

验收：正常、边界和历史失败风险有覆盖；工具、数据源和权限真实可用；每个用例有输入、预期、判定方式。用例数量不作为唯一质量指标。

** 03 执行与诊断
#+begin_example
按目标 Skill 实际执行任务。对照验收标准检查功能错误、规则冲突、输出冗余及执行偏差。复现失败并定位根因。区分 Skill、实现、数据、环境和测试问题。保留真实证据，不得模拟通过。
#+end_example

验收：实际执行结果和产物可核对；失败有触发条件；根因有证据，无法定位时明确标注。=loop-engineering-meta= 负责定位首次偏离预期的位置和控制修复反馈，不代替主 Skill 的业务执行。

** 04 修复、瘦身与清理
#+begin_example
根据已确认根因修复并精简当前 Skill。删除无效规则、重复说明和失效分支，按需加载非核心资料。审计 GitHub 测试文件：保留有效回归，合并重复测试，清理可再生的临时产物；历史证据按保留要求归档。删除或移动前检查所有引用、CI 和依赖。禁止误删、硬编码和无关修改。
#+end_example

验收：修改与根因一一对应，必要业务能力和风险约束完整保留；测试文件没有被错误删掉。没有仓库写权限或用户未授权时，只提出修复建议，不改远端。

** 05 回归与验收
#+begin_example
使用原测试集和必要的新增用例复测。检查核心功能、异常边界、历史缺陷、CI、最终产物及文件依赖。比较修改前后的结果、规则规模和仓库文件变化。未通过则继续定位修复，不得降低标准。
#+end_example

验收：原失败案例、核心旧案例、独立反例和完整链路已实测；没有阻断退化；精简带来的复杂度下降有比较依据。未执行的 Rendered QA 或外部平台验证标为未验证。

** 06 仓库维护与退出
#+begin_example
根据测试证据判断是否完成。遵循 MAINTENANCE.md 维护 canonical Skill；Prompt 按 AgentComponent/prompt-repository.md 归档。更新受影响的索引和 CI 引用，按需设置测试产物保留期限。记录文件增删、关键 Diff、测试结果和 Commit。禁止重复版本和无效历史堆积。
#+end_example

验收：关键条件全部通过，版本可回退，归档资产不重复，运行产物不污染主目录，发布状态有真实凭据。

* 任务适配：只加载真正需要的 Skill
| 任务对象 | 主 Skill | 边界 |
|----------+------------+------|
| 产品功能、BRD、需求文档 | =bprd-plus= | 定义系统行为，不替代代码 E2E |
| SQL 业务问题与教学 | =sql-business-thinking= | 关注真实 SQL、粒度、JOIN、口径 |
| 本体约束的真实数据分析 | =ontology-constrained-analysis= | 关注对象关系、Signal、Finding 的证据链 |
| 多表自动看板 | =dataset-dashboard-builder= | 必须跑真实分析与最终看板验收 |
| 可执行 Org / Org Babel | =org-literate-engineering= | 文档静态审查不等于代码可执行 |
| 历史 Org / Markdown 笔记升级 | =note-reforge= | 不是摘要、润色或替代测试器 |

通用根因闭环优先读取 =loop-engineering-meta=，避免在每个 Skill 内重复写一套 Loop。快速了解用途可使用 =skill-quick-reference=；中文知识图解使用 =sketchnote-generator=；知识发布时才进入 =org-museum-ingest= 或 =org-museum-update=。这些入口必须先确认仓库当前版本和可用工具，不能只报名称就算调用成功。

* 大型提示词怎样瘦身
| 处理动作 | 可以处理的内容 | 不得跨越的边界 |
|----------+----------------+----------------|
| 删除 | 不改变执行、判断、异常处理和验收的废话、重复结论 | 不能删掉仅在边界情形触发的硬约束 |
| 合并 | 多条规则约束同一行为且没有独立语义 | 不能合并导致适用条件消失 |
| 下沉 | 仅特定领域、异常场景、测试时才用的细节 | 不能隐藏必须默认加载的关键依赖 |
| 保留 | 删除会造成事实丢失、行为变更或风险上升的规则 | 不能只因规则长就认定无效 |
| 待确认 | 测不出是否有效或与现有契约冲突的规则 | 未证实前不可盲删 |

关键问题只有一个：*删除这条内容，是否改变行为、判断、异常处理或验收？* 不能证明可安全删除，就先保留并测试。上下文成本可测时再记录具体数值，不凭字数减少宣称效率提高。

* 回归失败时回到哪里
- 输入或验收定义错误：回 01。
- 用例缺失、环境不可运行：回 02。
- 行为失败、诊断不明：回 03。
- 修复损失旧能力：回 04，并重跑 05。
- 连续两轮没有实质改善或出现重大回归：停止本轮修复，在受控分支或可恢复快照上回退本轮改动，不覆盖其他人的新提交。
