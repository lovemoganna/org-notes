* 先找到发生冲突的决策
相关方冲突通常围绕目标、责任、资源、决策权或成果口径展开。原文既讨论项目相关方管理，也讨论内容安全标准与政府事务、机审策略、模型训练、蓝军和业务部门的协作。不能把一次沟通会当成冲突已经解决。

* 可执行排查顺序
1. 找出决策者、资源提供方、执行团队、最终用户及受影响者。
2. 为每方记录目标、必须满足项、可协商项、决策权及尚未证实的担忧。
3. 扫描范围、进度、预算、质量、合规和指标归属上的冲突点。
4. 用 RACI 或既有组织授权确定执行、批准、咨询和知会；未知决策权不能猜测。
5. 将冲突登记为可跟踪事项：证据、负责人、可选方案及代价、升级路径、复查日期。
6. 只有决定已获授权且剩余风险被记录，才把冲突标记为已处置。

| 字段 | 必填内容 |
|------+----------|
| 冲突点 | 两项真实目标或约束的碰撞 |
| 证据 | 会议原话、合同、需求或实际记录 |
| 决策权 | 谁批准；不明确就标为待核 |
| 方案 | 选择及代价，不只写“加强沟通” |
| 复核 | 责任人、时间、触发升级的条件 |

* 内容安全案例如何使用
- 标准与政府事务：先核对规则的适用辖区、版本及解释权限。
- 标准与机审策略：分别记录定义、召回、误判与上线门槛。
- 标准与模型训练：区分标签边界、样本质量、验证结果。
- 标准与蓝军测试：隔离攻防实验与生产处置权限。
- 标准与业务需求：讨论增长、用户体验与风险底线的权衡，明确审批主体。

* 不把示例写成实绩
原文有“deepfunk AI 智能助手”的相关方冲突情景和行动方案。本轮只能将其视为原文所述案例，不能认定真实项目已实施、建议已通过实测或角色已经对该方案签字。完整案例的角色、张力与建议均保存在来源附件。

* 退出条件
对每个冲突，必须能回答“谁批准了什么、代价是什么、何时复查”。如果缺任一项，结论只能是“待决”。
