提示词的价值不是文字越长越好，而是让模型知道要做什么、基于什么、什么结果可用。首先检查指令、上下文、输入材料和输出标准；任务越复杂，再加入领域条件与验证方式。四要素是检查清单，不代表每条提示都必须写满四栏，也不能保证模型一定正确。

* 先判断任务

| 当前任务 | 默认做法 | 必须警惕 |
|----------+----------+----------|
| 单一、低风险任务 | 一句话说清动作和交付物 | 不要为形式塞入无关背景 |
| 多步骤、依赖文件的任务 | 提供上下文、样本和输入输出契约 | 不要让模型猜字段或预期值 |
| 有性能、安全或业务后果的任务 | 明确资源、性能约束与检查办法 | 不得把模型自称通过当成验证 |

* 四个输入要素

| 要素 | 要回答的问题 | 示例 |
|------+----------------+------|
| 指令 | 具体做什么 | 编写函数并展示调用 |
| 上下文 | 谁用、在什么环境用 | 面向有三个月 Python 经验的开发者 |
| 输入材料 | 基于什么已知内容 | 指定 CSV 与列名 |
| 输出标准 | 如何确认能用 | 返回字典、示例、测试和错误处理 |

“输出标准”不仅是格式，也可以包含可执行性、准确性和解释要求。〔补〕需要验证时应分别列出“预期表现”和“实际测试结果”，不能混写为已验证事实。

* 三档提示

1. *基础*：写一个简单 Python 函数，将两个数字相加，提供函数定义和使用示例。重点是动作和交付物清楚。
2. *进阶*：针对 CSV 的指定数值列计算平均值、中位数和标准差，处理缺失值，使用 pandas，返回统计字典并解释关键步骤。原始示例给出的文件为 =sales_data.csv=，列为 =monthly_revenue=。需要真实使用时先核对文件和列确实存在。
3. *高阶*：设计交易流欺诈异常检测模块。原始场景要求约每秒 1000 条记录、每条 25 个特征、处理延迟不超过 50ms，且考虑滑动窗口、至少两种检测算法、日志、并行处理、可配置性和单元测试。以上是*假设任务的输入约束*，没有运行日志、基准环境和准确率数据，不能宣称这些指标已达成。

任务升级不靠增加形容词，而靠补齐真实环境、输入边界、失败处理和结果验证。模型生成代码以后仍需在指定运行时执行，核验性能与正确性。〔补〕

* 通用最短调用

#+begin_src text
任务：请完成[具体动作]。
上下文：[读者、环境、已知约束；若不需要可省略]。
输入：[真实材料、文件、样本，或明确表示暂未提供]。
输出：[交付物、格式和必须满足的条件]。
验证：[哪些内容需要运行、核对或人工确认]。
#+end_src

对原本已经清楚的单次问答，不必强制填写整套模板。数据没有提供时应显式说明，不让模型假设已经读取。〔补〕

* 怎么验收生成结果

1. *内容保真*：逐条核对输入文件、原始术语、数值、示例及引用。模型写出的新增信息应独立验证。
2. *任务完成*：把输出与明确的功能和格式逐项比较，不用“回答很流畅”替代验收。
3. *实际执行*：代码要运行；性能指标需写明硬件、负载和测量方法；安全判断需有适用的验证依据。
4. *失败回路*：记录第一个失败点，只改影响结果的条件，再用同一测试重跑。〔补〕

* 边界

- 明确的提示通常有助于传达意图，但不是正确性、可靠性或安全性的保证。
- 不同模型、领域和上下文长度可能改变输出表现；选择规则是实践建议，不能写成已实测的普遍规律。
- 原始“高阶”任务中的交易吞吐量、特征数和 50ms 延迟均为示例要求，不是测试报告。
- 下列存档完整保留原文，包括嵌入式 HTML 表格、三档提示示例、XML 模板及全部原始案例；它不作为网页可执行代码。

#+begin_src text
提示词（Prompt）是AI交互的关键桥梁，其精髓在于结构化的指令设计能显著影响AI输出质量。

核心观点是：有效提示需包含 *明确指令*、 *充分上下文*、 *必要输入数据* 和 *清晰输出期望* ，这四大要素共同引导AI生成符合人类意图的高质量内容。

简言之，精心设计的提示词是操控生成式AI产生理想输出的根本方法。

# 操作实践

## 基础认知 

1. 提示词应更关注其清晰性、具体性、结构性和目的导向性。
2. 结构应更明确地映射到四个基本要素：
   - 指令：明确的任务指导（要做什么）
   - 上下文：提供背景环境（在什么情况下做）
   - 输入数据：具体参考信息（基于什么做）
   - 输出指标：期望的结果规范（做成什么样）
3. “输出指标” 这一要素，它不只是对格式的要求，更是对质量和特性的期望。

## 思维盲区

1. 缺少对提示词迭代优化过程的认识
2. 未考虑不同AI模型，对相同提示词的不同响应特性
3. 忽略了提示词的领域特异性（不同领域可能需要不同结构的提示词）
4. 未探讨提示词的伦理考量（如何避免误导性或有害提示）

# 阅读材料

## 什么是提示词（Prompt）？

### 简介

欢迎学习"什么是提示词？"。

观看本视频后，您将能够定义提示词及其 *构成要素* 。您还将了解编写有效提示词的重要性，以指导生成式AI模型产生理想的结果。

生成式AI模型的一个显著特点是其输出与人类能够产生的内容极为相似。这种输出具有相关性、情境性、创造性、细微性以及语言准确性，而实现这种输出的关键因素之一就是提示词。

### 提示词的定义

提示词是您提供给生成式模型以产生所需输出的任何输入。您可以将其视为给模型的指令。例如：

```markdown
"写一个简短的段落描述您最喜欢的度假目的地。"
"编写HTML代码生成在线表单中的城市下拉选择菜单。"
```

这些都是用于产生特定输出的直接提示词。提示词也可以是一系列指令，逐步完善输出以达到理想结果。例如：

```markdown
"写一个关于一位科学家研究火星生命的短篇故事。在研究过程中他面临了哪些挑战？"
```

从这些例子可以看出，提示词包含 *问题* 、 *背景文本* 、 *引导模式* 或 *示例* ，以及提供给模型的部分 *输入* 。

根据作为提示词提交的自然语言请求，生成式AI模型收集信息、推导推论并提供创造性解决方案。这些指令帮助模型基于提供的输入产生相关且合乎逻辑的响应或输出。

### 简单提示与有效提示的对比

让我们通过更多示例来更好地理解这一点：

#### 示例1：故事创作

假设您希望模型写一个关于一位农民如何在10年内成为成功商人的短篇故事，包括他的奋斗和成就。

```markdown
简单提示："来自小镇的富人故事，他的奋斗和成就"
```

这种我们称为"朴素提示"的方法会产生泛泛的输出，即以最简单的方式向模型提问。

```markdown
有效提示："写一个关于一位农民如何在10年内成为富有且有影响力的商人的短篇故事，详述他的奋斗和成就。"
```

这种提示更加具体和有指导性。

#### 示例2：图像生成

假设您想要模型生成一个您心目中的日落风景图。

```markdown
简单提示："山间的日落图像"
```

这个提示太过简短，缺乏您心目中图像的详细轮廓。

```markdown
有效提示："生成一张平静的日落图像，展示位于群山之间的河谷。"
```

这个提示提供了更多细节，有助于生成您想要的图像。

### 构建有效提示词的要素

要掌握编写有效提示词的艺术，让我们逐一了解构建良好提示词的基本要素：

#### 指令（Instructions）

给模型提供关于您希望执行的任务的明确指导，引导生成式AI模型的行动以影响其响应的形成。例如：

```markdown
"写一篇600字的论文，分析全球变暖对海洋生物的影响。"
```

#### 上下文（Context）

建立指令背景的环境，为生成相关内容提供框架。例如：

```markdown
"近几十年来，全球变暖经历了显著变化，导致海平面上升、风暴强度增加和天气模式改变。这些变化对海洋生物产生了严重影响。写一篇600字的论文，分析全球变暖对海洋生物的影响。"
```

这个提示将帮助模型生成与上下文一致的输出。

#### 输入数据（Input Data）

作为提示的一部分，您提供的任何信息都可以作为生成模型的参考，以获得包含特定细节或想法的响应。例如：

```markdown
"您已获得一个包含太平洋海温记录和海平面测量的数据集。写一篇600字的论文，分析全球变暖对太平洋海洋生物的影响。"
```

#### 输出指标（Output Indicator）

提供评估模型生成的输出属性的基准，可以概述您期望输出的 *语调* 、 *风格* 、 *长度* 和 *其他品质* 。

在提示"写一篇600字的论文，分析全球变暖对海洋生物的影响"中，输出指标指定生成的输出应是600字的论文，将根据分析的清晰度和相关数据或案例研究的整合进行评估。

### 总结

在本视频中，您了解到提示词是您提供给生成模型的任何输入或一系列指令，用于产生所需输出。这些指令有助于引导模型的创造力，并帮助它产生相关且合乎逻辑的响应。

构建良好结构化提示词的基本要素包括指令、上下文、输入数据和输出指标。这些元素帮助模型理解我们的需求并生成相关响应。
