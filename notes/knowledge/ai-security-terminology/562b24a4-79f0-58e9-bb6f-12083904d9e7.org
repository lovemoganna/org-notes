针对术语定义过于笼统、标注和模型难以一致理解的问题，先明确术语、现有定义和待解决的歧义，再要求输出简洁定义与详细定义。这里记录的是一次提示词优化实践，不是对攻击原理已完成独立安全验证的结论。

* 使用入口

1. *确定输入*：说明主题、子主题、当前定义和最突出的问题；保留原始语义，不替来源补写证据。
2. *执行提示*：同时填写模板首句的 Topic、SubTopic、Define、Question 四个变量，并同步修改下方四个同名多行示例区块。只修改一处会产生输入冲突。
3. *对照结果*：分别检查定义是否包含攻击者的控制点、作用机制、可能后果，并验证是否覆盖输入的歧义。
4. *标注证据*：将模型生成的定义和来源已证实的事实分开；没有实测或权威依据时，不升级为通用安全结论。〔补〕

* 已记录输出

*目标*：微调提示词。

- *Target URL*：https://www.ibm.com/cn-zh/topics/prompt-injection
- *Workflow*：问题发现-聚焦优化
- *Running_Effect*（实践记录，不代表外部验证）：
  - 简洁定义：直接提示注入是一种针对大型语言模型（LLM）的攻击，攻击者通过向 LLM 输入精心构造的恶意提示，绕过其安全机制，诱导其产生非预期的输出，从而实现泄露信息、操纵结果或破坏系统等目的。
  - 详细定义：直接提示注入是一种利用大型语言模型（LLM）基于概率模型生成文本的特性进行的攻击。攻击者控制用户输入，直接向 LLM 提供恶意构造的提示（Prompt），这些提示通常包含特殊的指令、诱导性内容或试图利用 LLM 内部机制的漏洞。由于 LLM 缺乏真正的理解能力，它可能会被这些恶意提示“欺骗”，从而绕过安全机制（如内容过滤、访问限制），泄露敏感信息（如模型内部数据、训练数据、用户隐私），操纵输出结果（如生成虚假信息、有害内容），甚至导致拒绝服务（如陷入无限循环或崩溃）。这种攻击的成功可能导致严重后果，包括数据泄露、系统瘫痪、声誉受损等。

* 用途
这是一个专为AI安全研究设计的模板，用于优化和完善安全术语定义，特别是提示注入攻击相关概念。它通过结构化呈现现有定义及其问题点，引导AI提供更精确、更有针对性的术语定义改进建议。

** 适用场景
- AI安全研究人员完善技术文档中的安全术语定义
- LLM开发团队制定更精确的安全威胁模型说明
- 安全培训材料编写者提高教学内容的准确性和可理解性
- 标注团队建立更清晰的安全问题识别标准
- 安全审计人员统一安全漏洞分类标准

* 潜在风险与改进建议
- *潜在风险:*
  1. 未指定输出格式可能导致回答不够结构化或实用
  2. 缺乏要求提供实例说明，可能导致优化后的定义仍然抽象
  3. 没有明确要求多角度思考，可能导致优化建议片面

- *改进建议:*
  1. 增加对输出格式的明确要求，如"请提供：①优化后的定义 ②核心风险特征列表 ③具体攻击示例"
  2. 要求提供跨领域对比："请对比与其他领域类似概念的定义方法，借鉴其精确性"
  3. 添加特定要求："请确保优化后的定义既适合技术人员理解，也便于非技术人员快速掌握核心概念"
  4. 扩展模板以包含更多变量，如 =Examples= 和 =RelatedConcepts=，使输入更全面
