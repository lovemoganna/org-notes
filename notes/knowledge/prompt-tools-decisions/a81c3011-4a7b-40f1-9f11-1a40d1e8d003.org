* 不先挑工具，先判任务
1. *编写和理解一条提示*：先用现有模型直接试写，通常不需要额外平台。
2. *大量模板统一管理*：重点比较版本、权限、搜索、协作、审计和导出能力。
3. *系统评估多个版本*：需要固定测试集、指标、成本、重复执行与可复核结果。
4. *法规或领域数据*：工具是否能接入授权来源、说明证据边界比包装效果更重要。

* 原文六类能力
| 类别 | 何时有用 | 需要额外验证 |
|------+----------+--------------|
| 提示建议 | 没有起始写法 | 产出是否真的更贴合目标 |
| 结构优化 | 任务背景/输出不清楚 | 是否删掉重要约束 |
| 迭代优化 | 已有多版候选 | 是否具备可复现实验 |
| 偏差缓解 | 存在偏差或风险 | 不能替代模型的安全测评 |
| 领域支持 | 需要行业术语 | 是否有可靠、现行来源 |
| 预设提示库 | 重复场景多 | 更新、授权与质量 |

* 选择时的实际检查
1. 先用 2–3 个真实任务分别跑“现有方法”和“候选工具”，保存输入及输出。
2. 核查模板的原样保真、测试可复现性、导出能力和数据权限。
3. 只有出现明确收益（时间、准确性、协作或质量）才增加工具；若只是重排文字，保持现状。
