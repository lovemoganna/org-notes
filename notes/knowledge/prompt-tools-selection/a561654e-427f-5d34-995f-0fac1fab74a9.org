原笔记把多款产品并列为提示工程工具，但产品定位可能变化。选型先从任务出发：需要提示实验、团队协作、应用开发，还是法律合同审查？不要把产品同名、旧接口或营销描述当作今日功能。

* 按问题选择
| 需求 | 先确认的能力 | 证明方式 |
|------+----------------------+-------------------------|
| 提示模板实验 | 保存、多模型试验、变量替换 | 官方文档加真实试用 |
| 提示版本管理 | 版本比较、审核、回滚 | 实际项目演示 |
| AI 应用协作 | 代理工作流、权限、数据接入 | 官方产品说明和授权模型 |
| 法律合同场景 | 合同审查与起草的专业支持 | 业务权限与数据合规核查 |

* 产品记录与核验
| 产品 | 原文描述 | 当前证据状态 |
|------+-------------------------+-------------------------|
| IBM watsonx.ai Prompt Lab | 多模型提示实验 | IBM 官方资料仍描述为提示实验环境；具体模式和要求可能变动 |
| Spellbook | 原文归为 Scale AI 的通用 IDE | **与官方现状不符**：官方将其定位为法律合同起草和审查工具 |
| Dust | 原文描述为提示链接与版本管理 | 当前具体功能应重新核对，不能仅凭原笔记定论 |
| PromptPerfect | 原文称支持多模型提示优化 | 旧脚本/API 与当前可用性未经本次验证 |
| promp(l)ify | 原文仅提供工具入口 | 未做网站登录、购买或功能实测 |

Spellbook 核验：[[https://spellbook.com/about][官方 About]]。IBM 核验：[[https://www.ibm.com/docs/en/watsonx/saas?topic=prompts-prompt-lab][Prompt Lab 文档]]。〔补〕

* 试点验收
1. 用相同的 5—10 个真实问题，分别跑无工具和有工具两个版本（5—10 是试点建议，不是置信度保证）。〔补〕
2. 比较正确率、时间、复现能力、人员改写成本及敏感数据处理条件。
3. 核对购买和数据授权，保留实际产品版本、入口和日期。
4. 如果无法复现官方能力，就记录“待核验”，不得推导“产品不可用”。

* 旧示例保全
原稿的 "+PromptPerfect" 导入示例只是展示写法，**没有运行日志，也没有证明该 Python API 仍有效**。源码、原始产品描述和工具 URL 均存于完整原文附件。〔补〕
