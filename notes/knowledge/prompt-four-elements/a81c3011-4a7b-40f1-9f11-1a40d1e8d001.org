给模型下指令前，先判断缺的是任务、背景、真实输入，还是对结果的验收标准。四要素是提问检查表，不保证输出正确，更不能替代运行测试。

* 直接用的判断
1. *简单任务*：先把「要做什么、得到什么格式」说清楚，缺少业务背景时不必凭空补背景。
2. *需要复现的工作任务*：给出受众、有效输入、边界条件、输出字段和可核查的成功条件。
3. *工程性能任务*：必须补真实数据、执行环境、基线、负载与失败标准；即使提示词规定「每秒约1000条交易、25个特征、延迟不超过50ms」，这也只是原文的*需求设定*，不是已达成的结果。

* 四要素
| 要素 | 需要回答的问题 | 常见缺口 |
|------+----------------+----------|
| 指令 | 模型应完成哪个动作？ | 只写主题，没有交付动作 |
| 上下文 | 谁使用结果，受到什么限制？ | 忽略受众及可用资源 |
| 输入 | 哪些真实材料可作为依据？ | 要求模型猜不存在的数据 |
| 输出标准 | 怎样证明结果能用？ | 只有格式，没有验收或反例 |

* 逐级改进
原稿通过三个 Python 案例说明难度差异。它们是*不同复杂度的需求示例*，不是三个模型实测成绩。

- *基础*：写一个简单 Python 两数相加函数，包含函数定义与调用示例。
- *进阶*：有 3 个月 Python 经验的开发者使用 pandas 读取 CSV 指定列，计算平均值、中位数、标准差，处理缺失值，返回字典并附示例。原文以 `sales_data.csv` 和 `monthly_revenue` 举例。
- *高阶*：金融科技交易流的假设任务，要求滑动窗口、至少两类异常检测、错误处理、日志、配置接口、类型标注和测试；原稿提出约 1000 条/秒、25 个特征与 50ms 延迟约束，均应按*待验证目标*处理。

* 何时不改提示词
- 如果同一提示仍无法复现结果，先检查数据、工具、温度/采样设置、外部服务状态。
- 如果输出质量没有比较基线，先存两份结果和一组失败用例，不根据措辞漂亮程度决定胜负。
- 如果问题源于非法数据结构或程序错误，应修输入契约/代码，而不是持续加提示话术。
