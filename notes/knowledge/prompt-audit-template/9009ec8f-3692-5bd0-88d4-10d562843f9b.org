* 为什么要使用这份模板

一份提示词写得完整，不代表它能完成任务。这份模板可以检查任务、输入、约束和输出是否明确，并暴露可能的歧义。真正的效能必须由模型在具体任务中的输出证明，而不是由提示词的长度、角色设定或自评分决定。

* 五步评审

1. *全面解读*：找出任务对象、输入来源和关键限定。意义不明的地方保留疑问，不把猜测写成作者意图。
2. *目标定位*：说明期望模型完成什么，以及什么结果算失败。没有可观察的目标，后续评分就没有依据。
3. *结构剖析*：分别核查角色、指令、约束和输出格式；发现缺失输入、相互矛盾的指令以及无法执行的条件。角色称谓不能代替专业证据。
4. *效果预测*：把潜在问题变成测试假设，例如编造来源、漏掉限制条件、输出格式失效。预测不能写成已验证结果。
5. *质量评估*：从相关性、深度、创新性、实用性和完整性五个维度解释优缺点。未运行测试时，这五项是文本审查判断，不是模型性能数据。

* 使用边界
| 检查项 | 合理做法 | 错误做法 |
|--------+----------+----------|
| 来源 | 没有出处就明确未提供 | 擅自编造灵感链接 |
| 保真 | 保存完整模板与参数 | 为了简洁删掉关键条件 |
| 评分 | 说明理由和样本 | 将自评当作准确率 |
| A/B | 同任务保存完整输出 | 只比较文笔 |
| 风险 | 区分建议与真实数据 | 效果预测写成事实 |

* 真实任务验证〔补〕
判断提示词是否有效，先定义成功标准，再检查实际输出。静态审查适合发现表达缺陷；运行测试才有资格支持效果结论。

1. *确定用例*：选择真实任务，保留输入、必要上下文、预期结果和不可接受的错误。至少覆盖常见输入、边界输入和信息缺失的情形；用例数量按任务风险与成本决定。
2. *固定对照条件*：让原版与候选提示词在相同模型、输入和主要运行配置下分别执行，保存完整输出。结果可能波动时重复运行，不能只挑最好的一次。
3. *按结果验收*：逐例检查事实与引用、任务完成度、关键约束、输出可用性；必要时记录时间与成本。硬性要求未满足时，不用其他维度的高分冲抵。对主观质量使用事先确定的判定标准，必要时由独立评审复核。
4. *决定保留还是回退*：只有关键用例改善且没有不可接受的退化，才考虑采用候选版本。没有实际运行记录，就保留“待测试”，不报告准确率或效果提升。

例如，待评估提示词要求提供“原始来源”和“灵感参考”。输入没有给出来源时，合格输出应说明“未提供，需手动补充”；任何自行补出的链接必须单独核验真实性和关联性。报告写得完整，却引用虚构来源，仍属于实质失败。

评估设计依据：[[https://platform.claude.com/docs/en/test-and-evaluate/develop-tests][Anthropic：定义成功标准与设计测试]]；[[https://developers.openai.com/api/docs/guides/evaluation-getting-started][OpenAI：用数据集及评估准则测试输出]]。这里给出的是可复用的验证方法，不代表本模板已完成实测。
