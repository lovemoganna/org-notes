相关方之间的争执往往不在“沟通态度”，而在目标、资源、优先级和决策权限不同。先明确各方要保护什么，再将不同意见翻译成可处理的决策问题。原文同时覆盖通用项目、名为 deepfunk 的 AI 助手情境案例、内容安全标准跨角色协作；这些案例是**示例方案**，不能当作已执行的项目事实。〔补〕

* 识别四种冲突
| 类型 | 典型表现 | 第一项核查 |
|------+-----------------------+-----------------------------|
| 目标差异 | 安全、速度、增长的优先级不同 | 各方交付结果和不可牺牲条件 |
| 资源冲突 | 人、算力、预算同时被要求占用 | 资源持有者与真实排期 |
| 权限冲突 | 每个人以为另一个人批准 | RACI/审批路径及最终决策人 |
| 证据冲突 | 对误报、漏报或效果的定义不同 | 指标口径、测试集和判定标准 |

* 处理顺序
1. **单独取证：** 向每位相关方询问必须满足、希望满足和不能接受的条件。
2. **把分歧落表：** 记录冲突对象、触发条件、影响范围及现有证据。
3. **确定决策权：** 指定最终批准者；如果权限重叠，先明确治理规则，再议方案。
4. **提出可检验选择：** 为至少两种方案写清成本、风险、收益和执行边界。
5. **形成回执：** 记录决定、责任人、截止时间及复盘条件。〔补〕

* 内容安全协作的专门边界
原文覆盖政府事务、机审策略、模型训练、蓝军攻防、业务需求等角色：
| 角色 | 常见分歧 | 决策前必须核对 |
|------+--------------------------+------------------------|
| 政府事务 | 监管解释与响应时效 | 原始法规、适用地区和法律意见 |
| 机审策略 | 漏判与误判之间的容忍度 | 真实样本、召回/准确及处置成本 |
| 模型训练 | 安全约束与模型能力 | 训练/推理边界、测评结果 |
| 蓝军攻防 | 漏洞共享范围和修复顺序 | 报告授权、保密等级及风险优先级 |
| 业务需求 | 用户体验、上线时间与安全 | 产品风险、退出条件、负责人 |

不得把“模型能力争议”或“告警异常”直接写成违规。权衡由有权限的业务、合规和技术人员依据证据作出。〔补〕

* 可复用冲突登记
| 字段 | 作用 |
|------+-------------------------------|
| 议题ID/触发场景 | 找到具体事件和争议来源 |
| 相关方与各自目标 | 区分诉求、证据和假设 |
| 决策人/执行人 | 减少无人负责或多人批准 |
| 备选方案与影响 | 明确权衡，不只记录争吵 |
| 截止时间/回看条件 | 检查决定是否真的执行 |
