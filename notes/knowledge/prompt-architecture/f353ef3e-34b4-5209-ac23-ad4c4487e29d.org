提示词四要素如何指导可验证的输出。此为根据历史笔记整理的下一版草稿；原作者的事实、示例和历史方法保留在同目录的完整原文附件中，不将示例中的指标视为已经实测的结果。

* 先判断任务
遇到的不是“提示词写得不够长”，而是模型不知道任务、背景、输入与成功标准。先找最缺失的一项，再补对应信息；不必每次都套固定模板。

| 自查问题 | 要填什么 | 不应误写为 |
|----------+----------+--------------|
| 要模型做什么？ | 明确动作、对象与边界 | 只有“帮我看看” |
| 为什么做？ | 读者、场景、已有条件 | 无关背景堆砌 |
| 基于什么？ | 输入数据、示例、来源 | 模型自行猜测事实 |
| 怎样算完成？ | 输出格式、可验收指标 | 仅写“高质量” |

* 三种任务梯度
原文区分基础、进阶和高阶提示。这是 *任务约束递增*，不是“文字越多质量越好”的经验定律。

** 基础：加法函数
#+begin_example
写一个简单的Python函数，实现两个数字相加。请包含函数定义和一个使用示例。
#+end_example
此时任务明确，但没有指定编程环境与异常输入处理。

** 进阶：CSV 统计
原文场景：有 3 个月 Python 经验的开发者；使用 pandas 读取 =sales_data.csv= 的 =monthly_revenue= 列，求均值、中位数、标准差，处理缺失值；返回统计字典并附带注释与完整调用示例。这里是 *提示要求*，没有源文件或真实代码运行结果。

** 高阶：实时欺诈检测
原文设定每秒约 1,000 条交易，每条 25 个特征；提出滑动窗口、至少两种异常检测算法、并行处理、延迟不超过 50ms、配置入口、PEP 8、类型注解和单测等要求。

*注意：* =50ms= 是原始提示设定的 *验收目标*，不是已测得性能；该示例没有证明方案能够实现该延迟。

* 可复制优化器
下面完整保留原文的 XML 模板及三组调用实例。=prompt_optimizer= 只是原文定义的调用约定，不是本环境已经注册的系统命令。复制到模型时，应连同模板发送，不能只发调用名。

* 验证与迭代〔补〕
1. 固定同一任务、样例输入和目标模型，再比较原提示与优化稿。
2. 先审查是否遵循约束，再用单元测试或事实比对验证实际输出。示例中的“预期效果”不能替代运行证据。
3. 记录失败输入和每次改动，只修改引起失败的约束，防止模板膨胀。

* 边界
原文提到了模型差异、领域条件和伦理风险，但没有进行不同模型的 A/B 测试。若不具备输入事实或可执行验证条件，应保留“未验证”而不是声称提高准确率。
