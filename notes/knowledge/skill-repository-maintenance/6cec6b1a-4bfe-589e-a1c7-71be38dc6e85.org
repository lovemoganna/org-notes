* 症状：测试跑了很多遍，GitHub 却越来越乱
多次通过只能证明已运行用例在对应环境里通过，不能证明未来用不到的测试都可删除。仓库治理的目标是*减少不必要的长期维护成本，同时保留能够发现回归的独立证据*。

| 我看到的情况 | 默认决策 | 证据门槛 |
|--------------+----------+----------|
| 核心 =SKILL.md=、脚本和实际引用 | 保留 | 删除会中断有效执行 |
| 正常、边界和历史失败回归 | 保留并集中管理 | 能发现独立类型的失败 |
| 语义等价的重复测试 | 合并 | 逐项确认断言和边界没有丢 |
| 构建缓存、临时 HTML、重复截图与日志 | 清理或排除 Git | 可以重建且不是交付 / 证据依赖 |
| 诊断性故障记录 | 选择性归档 | 保留最小复现、版本和必要证据 |
| 未知引用、未知覆盖价值 | 待确认 | 不得直接删除 |

* 默认布局：运行资产与测试资产分工
仓库当前以 =skills/<skill-name>/tests/= 为主。优先就地整理，避免为“统一目录”做大规模迁移。以下是可选目标示例〔补〕，不是当前已经实施的目录改造。

#+begin_src text
skills/<skill-name>/
  SKILL.md
  references/           # 按需加载的详细规则
  scripts/              # 必须执行的工具
  tests/
    fixtures/           # 固定输入及必要来源
    regression/         # 关键旧缺陷与反例
    check_repo.py       # 需要时保留
  assets/               # 正式交付的模板或媒体
#+end_src

只创建有实际文件的目录；现有目录名称、引用约定和 CI 优先于美化后的树形结构。

* 一次清理应该怎样执行
1. *列清单*：固定 commit，读取文件、Git 跟踪状态、=README=、CI、脚本和跨 Skill 引用。
2. *查依赖*：将每个候选文件标成“运行必需 / 独立回归 / 历史证据 / 可重建产物 / 待确认”。
3. *先做最小变更*：重复测试经断言等价核对后合并；临时产物移出长期跟踪；不删除被引用的 fixture / golden。
4. *复验*：运行原失败案例、核心回归和 CI，比较变更前后的用例覆盖、行为及失败状态。
5. *提交*：记录文件列表、删除依据、关键 Diff、CI 结果和 commit；失败停止并回退本轮清理。

发布到 Org Museum 时，=Museum-Update= 的单次提交必须只修改一个已存在的 Org 源文件。这是发布器的真实校验条件；多篇文章逐篇提交，最后以部署后的同一站点版本核验两篇。

* 可直接复制的仓库清理提示词
这段保留既有测试资产中的完整提示词：
#+begin_example
完成 Skill 修复与回归测试后，清理 GitHub 仓库中的冗余测试资产。先检查文件用途、引用关系和 Git 状态，区分运行必需文件、有效测试、历史证据和临时产物。保留核心测试及历史缺陷回归案例，合并重复测试，删除确认无效的文件，将临时产物排除版本控制。禁止删除必要依赖或未经确认的文件。清理后重新运行核心测试，比较清理前后的文件数量、规模和测试结果。全部通过后再提交远程仓库，记录删除、合并和保留的依据。
#+end_example

如果工作内容是修复 Prompt / Skill 的行为，再使用 [[wiki:b0f76f51-5884-54b7-9ccc-2d43a989d1a3][六阶段调试与精简流程]]。不要把本篇变成第二套通用调试器。

* Git 与 CI 的关键边界
下面的 =.gitignore= 是本轮建议中的原始示例，并未确认已经适用于当前所有目录：

#+begin_src gitignore
# Skill 测试产生的临时文件
*-workspace/
tests/**/output/
tests/**/reports/
__pycache__/
*.pyc
#+end_src

- 不要全局忽略 =*.html=；正式看板、报告和固定验证产物可能以 HTML 为交付或测试依据。
- =.gitignore= 不会让已跟踪文件自动消失。确认是临时产物后，可用 =git rm --cached= 从跟踪状态移除，必须审查 Diff。
- 对可重建运行输出，优先使用 GitHub Actions Artifact 和设置保留期限。7 天普通日志、30 天重要故障证据只是*示例策略〔补〕*，不是仓库现有配置。
- 删除、重命名、移动文件前核查所有引用。CI 失败或功能退化，必须回退本轮清理；不能以文件数量变少为验收依据。
- 旧 Skill 的可恢复版本优先通过 Git 版本历史管理，避免添加 =final-new-v2= 同内容副本。不要在有未提交变更的工作区使用可能覆盖修改的粗暴恢复命令。

* 为什么测试资产不能无限累积
重复测试如果没有独立失败检测价值，只增加维护、诊断和加载成本；反过来，删除唯一的历史失败用例又会使旧缺陷难以再次识别。判定依据不是文件名、年龄或通过次数，而是*依赖、独立断言、复现价值和重建成本*。

清理必须降低复杂度，但不能降低发现问题的能力。完整验收依赖真实运行与 GitHub 状态；未运行、无法复现或环境受阻的项目必须保持未验证。
