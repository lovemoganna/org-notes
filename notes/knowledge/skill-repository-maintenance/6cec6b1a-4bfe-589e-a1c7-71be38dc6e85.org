* 何时需要清理
一个 Skill 已被反复测试，却留下大量重复脚本、日志、截图和旧版本副本时，治理对象不是“所有测试文件”，而是*无复用价值的运行产物及冗余测试*。不能因为测试连续通过，就删除未来防止回归所需的样本。

| 当前文件属于 | 默认处理 | 判断条件 |
|--------------+----------+----------|
| 核心文件 | 保留 | =SKILL.md=、必需脚本、依赖、关键参考资料 |
| 有效测试 | 集中管理 | 能验证核心功能、重要边界或历史缺陷 |
| 历史证据 | 选择性归档 | 对复现关键故障、比较版本仍有价值 |
| 临时产物 | 清理/排除 Git | 可重建的重复报告、缓存、临时截图和输出 |

* 一个清晰的仓库布局〔补〕
采用正式运行区与测试区分离的建议结构，实际迁移前必须检查现有加载路径和 CI 引用。此为目标结构示意，*不是已经实施的仓库现状*。

#+begin_src text
Org-Skills/
  skills/
    skill-name/
      SKILL.md
      references/
      scripts/
      assets/
  tests/
    skill-name/
      cases.yaml
      fixtures/
      regression/
  .github/workflows/
  .gitignore
  README.md
#+end_src

Skill 主目录只放运行时必要资产；=tests/= 放固定输入、核心回归和历史失败复现；自动化验证置于 =.github/workflows/=。=references/= 和 =assets/= 均按需保留，不能为凑齐目录而创建空文件夹。

* 怎样判断测试文件该不该删除
1. *检查引用*：搜索 CI、脚本、README、Skill 元数据、入口命令是否依赖目标文件。未知依赖时不删。
2. *检查断言*：仅当多个测试在输入边界、失败检测和覆盖行为上等价，才合并；名字相似不代表等价。
3. *保留回归*：每个历史缺陷至少保留能够识别该缺陷的精简案例；若重新运行旧版做不到，说明验证证据不足。
4. *清理产物*：重复运行报告、调试缓存、构建输出默认不提交；关键故障证据按需留存并建立有效期。
5. *删后复验*：先在独立分支完成清理，重跑关键测试，再确认文件与引用无遗漏。

* 文件清理映射
| 文件类别 | 建议动作 | 可执行的门槛 |
|----------+----------+--------------|
| 同功能测试脚本 | 合并 | 证明断言和边界未丢失 |
| 已修复 Bug 的回归案例 | 保留最小复现 | 旧版可识别失败，新版可通过 |
| 多轮日志、HTML 报告 | 保留必要摘要，其他定期清理 | 故障证据已提取 |
| 临时截图、缓存 | 排除版本管理 | 非运行依赖，也不是正式交付 |
| 旧 Skill 完整副本 | 优先使用 Git Tag 和历史 | 旧版可恢复，且未被脚本依赖 |
| 失效说明和重复文档 | 删除或合并 | 无独立知识价值，无外部引用 |
| 固定测试数据 | 保留并注明版本与来源 | 当前回归依赖该数据 |

* 排除临时产物：原始示例
以下 =.gitignore= 来自本轮建议，实际是否适合仓库必须核对。=*.html= 等全局通配可能误伤有意提交的页面，因此只过滤已明确的临时目录。

#+begin_src gitignore
# Skill 测试产生的临时文件
*-workspace/
tests/**/output/
tests/**/reports/
__pycache__/
*.pyc
#+end_src

已被 Git 跟踪的文件不会因为加入 =.gitignore= 而自动停止跟踪。确认确属临时文件后，才使用 =git rm --cached= 取消追踪；该操作仍会改变下次提交中的跟踪状态，应先检查差异。GitHub Actions 的临时 Artifact 可配置保留期，如普通测试结果 7 天、重要故障证据 30 天；此为*建议参数*，不是当前仓库配置。

* 可直接复制的清理提示词
#+begin_example
完成 Skill 修复与回归测试后，清理 GitHub 仓库中的冗余测试资产。先检查文件用途、引用关系和 Git 状态，区分运行必需文件、有效测试、历史证据和临时产物。保留核心测试及历史缺陷回归案例，合并重复测试，删除确认无效的文件，将临时产物排除版本控制。禁止删除必要依赖或未经确认的文件。清理后重新运行核心测试，比较清理前后的文件数量、规模和测试结果。全部通过后再提交远程仓库，记录删除、合并和保留的依据。
#+end_example

* 发布门槛与回滚
本项治理合并进五阶段调试流程的“05 回归验收”，*不新增一个必须每次执行的阶段*。仓库整理时重点证明两件事：有效测试还在；无用文件不再反复产生。检查未通过先回退本轮清理，不应为追求文件数量少而损失测试资产。
