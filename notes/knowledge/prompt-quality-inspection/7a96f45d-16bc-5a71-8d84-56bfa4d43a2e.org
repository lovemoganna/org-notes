我用这份笔记检查提示词的目标、结构和风险。它解决的是“提示词写得是否清楚”，不能仅凭语言评价证明提示词在真实模型上有效。原始模板与一次历史评价记录保留在下方，额外增加的判断方法标记为〔补〕。

* 什么时候使用

- 一份提示词读起来复杂，但不确定角色、任务、输入和输出是否完整。
- 准备对比两个 Prompt 的结构缺口，先提出改法，再决定是否投入实际测试。
- 要给提示词评审结果做记录，避免把模型的自评分数当作可复验性能。

* 使用方法〔补〕

1. *输入原文*：将需要检查的提示词放入原始模板末尾“待检测分析的提示词开头”和“结尾”之间。不要把模板本身误当作待测对象。
2. *检查结构*：核对任务目标、输入条件、角色、约束、输出格式以及适用场景；缺失项应明确指出，不根据语气猜测。
3. *记录评估*：从相关性、深度、创新性、实用性、完整性五个维度提出判断。若要评分，必须同时注明标准、理由和对应原文证据。
4. *做真实验证*：使用相同测试样本、模型版本与参数比较结果，保存输入、输出、失败案例。没有运行记录就只写“预测”或“待验证”。
5. *最小修正*：只修改由失败证据支持的问题，再用原样测试回归；不能把“格式更规整”作为效果改善的唯一证据。

* 判断什么

| 维度 | 核心问题 | 不足的证据 |
|------+----------+------------|
| 相关性 | 指令是否服务于真实目标？ | 只说“目标高度一致” |
| 深度 | 是否要求解释必要的机制与边界？ | 只要求“详细分析” |
| 创新性 | 新方法是否解决了具体缺口？ | 只强调措辞新颖 |
| 实用性 | 结果能否用于明确任务？ | 只按模型主观感受评分 |
| 完整性 | 输入、约束和输出是否齐全？ | 只清点段落数量 |

* 证据边界〔补〕

- *来源不明时不猜*：原始模板曾要求“根据提示词内容推断可能的来源”。这属于原模板的历史指令，不等于能确认来源。实际交付应写“未提供”，不得把猜测链接写成证实出处。
- *预测不等于实测*：对潜在表现、创新性或效果的文字评估只生成假设；必须依赖外部测试才能确认。
- *自评不等于独立审查*：当待测文本就是评价模板本身时，会出现“用自己的标准评价自己”的循环。应另外设计测试输入、判定标准和对照样本。
- *不为省字删模板*：原始提示与输入分隔标记不可改写；若将来替换模板，需要另存新版本并重新运行相同案例。

* 复用时的最低验收〔补〕

1. 原始提示可完整复制，分析步骤和格式字段没有遗漏。
2. 每条缺陷能定位到原文，建议针对该缺陷，而不是泛泛列举。
3. 结论分为“原文事实、结构判断、效果预测、真实测试”四类。
4. 未提供来源、模型版本、测试样本和效果指标时，如实标注缺口，不虚构。
