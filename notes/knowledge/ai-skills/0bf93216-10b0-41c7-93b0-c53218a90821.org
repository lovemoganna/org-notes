* 我真正要解决的问题
不是知道 16 个 Skill 的名字，而是碰到具体问题能在 30 秒内选对工具、正确加载、拿到可验证的结果。
我将“受欢迎”和“有效”分开：安装量代表采用趋势，不等于解决问题的成功率。2026-10-10 已逐个核对下文 16 个 =SKILL.md= 的真实源码路径，但没有在同一代理、同一任务上完成全部 16 个 E2E 对照测试。它们是“可查证的候选”，不是效果排名。
默认一次只选一个主 Skill；只有任务出现独立缺口，才加第二个。能直接靠现有代码和测试解决的问题，不为了用 Skill 而安装。

* 一、先选，不要先装
| 真实症状 | 先用 | 不要误用成 |
|----------+------+------------|
| Skill 改过很多轮，单个案例通过但其他案例失败 | =skill-creator= | 只重写一遍提示就宣布优化成功 |
| Bug 修了三次仍复发 | =diagnosing-bugs= | 直接猜根因、加补丁 |
| 修改完成后模型只说“测试通过” | =verification-before-completion= | 拿输出总结当测试证据 |
| 要做的功能说不清输入、边界与验收 | =grill-me= | 明确需求后仍不断询问 |
| 同一业务对象或指标定义冲突 | =domain-modeling= | 用代码结构代替业务语义 |
| 模块依赖越来越多、改一处牵动多处 | =improve-codebase-architecture= | 不看代码就全仓重构 |
| 页面有遮挡、焦点、布局或 Label 问题 | =web-design-guidelines= | 把静态审查当浏览器测试 |
| 切换数据集、筛选或刷新时出现状态残留 | =agent-browser= | 用一张截图推断交互正确 |
| 需要完全不同的视觉呈现 | =frontend-design= | 只想修原风格中的 Bug |
| React 性能或组件组合不合理 | =vercel-react-best-practices= / =vercel-composition-patterns= | 当作任意 JavaScript 框架通用规则 |
| PostgreSQL 索引、RLS、慢 SQL | =supabase-postgres-best-practices= | 强行套进 DuckDB |
| GitHub Actions 中运行了 AI Agent | =agentic-actions-auditor= | 审计不含 AI 的普通 CI |
| 上述任务没有合适 Skill | =find-skills= | 按热门榜单直接安装 |

=systematic-debugging= 与 =diagnosing-bugs= 高度重叠，默认选择后者建立失败反馈环；若更缺少根因调查纪律，可以二选一采用前者，不要无差别叠加。=test-driven-development= 用于实施修复，=verification-before-completion= 用于最后验收，职责不同。

* 二、安装与调用：不要把“知道名字”当作“已执行”
安装的是工作流说明，Skill 不会赋予模型额外的终端、浏览器、仓库或数据库权限。先查看当前代理是否支持 Skills，确认代码、数据、执行环境和授权条件。

在支持 [[https://github.com/vercel-labs/skills][Skills CLI]] 的终端操作：
#+begin_src sh
# 先列出可用 Skill
npx skills add vercel-labs/agent-skills --list
# 项目内安装一个
npx skills add vercel-labs/agent-skills --skill web-design-guidelines
# 不安装，临时交给支持的代理使用
npx skills use vercel-labs/agent-skills --skill web-design-guidelines --agent claude-code
#+end_src
=--agent= 指定目标代理；=-g= 表示用户级安装。若是只有聊天能力的模型，先让它实际读取 =SKILL.md= 及依赖，不能只说 Skill 名就假设加载成功。

通用调用契约（不是某仓库的官方快捷命令）：
#+begin_example
使用 [Skill 名称]。先加载其 SKILL.md 和必需依赖。
对象：[真实仓库/文件/任务]
问题：[一项需要解决的真实缺陷]
约束：[技术栈、已运行功能、不可更改项]
执行：[用真实代码/数据分析、修改、复测]
验收：[测试输入、命令、预期、实际结果、失败证据]
没有权限或环境时，明确说明未执行，不得模拟通过。
#+end_example

* 三、三条最值得直接复制的工作流
** A. Skill 压测与精简：解决“越优化越臃肿”
默认组合：=skill-creator=（构造与评测）+ =diagnosing-bugs=（失败定位，按需）+ =verification-before-completion=（最后验收）。
#+begin_example
使用 skill-creator 测试 [目标 Skill]。
先冻结 Git 基线，读取真实 Skill、依赖与旧失败记录。
设计正常、边界、历史失败和独立反例；分别检查触发正确性与任务完成情况。
在可运行环境用真实输入执行，记录实际结果、失败证据及成本。
合并同根因问题，只做最小修复；不得硬编码样本答案。
复测原失败案例、核心旧案例与独立反例；比较修复前后。
连续两轮无改善或出现重大回归则停止并安全回退。
最后提供具体测试命令、退出状态、差异和未验证项。
#+end_example
真正的验收不是“模型说优化好了”，而是旧功能没有丢、反例没有过拟合、失败证据可以复现。

** B. 数据仪表盘修复：解决“组件不一致、状态残留”
默认组合：=web-design-guidelines=（代码扫描）+ =agent-browser=（真实交互）。只有项目实际使用 React，且根因涉及状态和组件接口时，才额外考虑 =vercel-composition-patterns=。只修缺陷时不用 =frontend-design=。
#+begin_example
在 [项目] 中仅检查当前首页仪表盘。
先识别实际图表库、数据链路、格式化、状态与渲染组件。
固定一套真实数据，使用 web-design-guidelines 扫描标题、Label、Tooltip、溢出和焦点。
用 agent-browser 重现加载、筛选、切换数据集、刷新、空数据与窄屏交互。
按共性根因归并缺陷，先修组件和规则，再做整体回归。
不得替换已有技术栈，不改现有视觉风格，不允许 Mock 结果。
交付修复前后证据；没有运行浏览器就明确标记未验收。
#+end_example
关键是同一输入、多次操作得到稳定结果，不能把“看起来不错”的截图当作功能通过。

** C. 架构失控：解决“每次修复都引入新问题”
默认组合：=domain-modeling=（定义对象与词汇）+ =improve-codebase-architecture=（找最小切口）+ =test-driven-development=（保护旧行为）。
#+begin_example
仅分析 [最近高频修改的模块]，不要全仓重构。
用 domain-modeling 校正对象、状态、关系和 GLOSSARY.md / ADR。
用 improve-codebase-architecture 从实际变更历史识别高耦合模块。
只选择一个有证据的改进点，说明影响范围、可测接口和回滚方式。
先建立失败测试或旧行为回归，再实施最小改动。
对比改前改后依赖、测试结果与修改范围；无实证收益不重构。
#+end_example
验收是复杂度和故障面实际降低，不能只看文件数、抽象层数或代码行数。

* 五、容易失败的地方
1. =grill-me= 入口会委托 =grilling=；=improve-codebase-architecture= 要配合 =codebase-design=。孤立复制入口文件可能没有完整方法。
2. =agent-browser= 还需浏览器 CLI：=npm i -g agent-browser && agent-browser install=；使用前按官方说明运行 =agent-browser skills get core=。没有浏览器权限，不得声称“已完成 UI 交互回归”。
3. =web-design-guidelines= 在检查时会读取远端规则文件。无法访问规则时，不能冒充按最新版本审查。
4. =agentic-actions-auditor= 是 Trail of Bits 插件，Claude Code 可先运行 =/plugin marketplace add trailofbits/skills=，再从 =/plugin menu= 安装。它只审计 GitHub Actions 内的 AI Agent 风险，不会自动修改代码。
5. 安装第三方 Skill 之前审查脚本、网络资源、权限与可能的敏感数据访问。生产使用时固定经过审查的版本。真实 E2E 通过率和上下文开销需用自己的独立案例测试。

* 资料与证据边界
已复核上表 16 个开源 =SKILL.md= 真实路径，且 [[https://github.com/vercel-labs/skills][Skills CLI]] 提供 =--list=、=--skill= 和 =skills use= 用法；这不等于所有技能在所有模型上都已测试通过。原版 2026-10-09 的安装数量只是当时的动态平台指标，本版不使用未经重新核实的数字排序。继续发现参考 [[https://skills.sh/][Skills.sh]]、[[https://github.com/anthropics/skills][Anthropic Skills]]、[[https://github.com/openai/skills][OpenAI Skills]]、[[https://github.com/obra/superpowers][Superpowers]]、[[https://github.com/trailofbits/skills][Trail of Bits]]。

结论：只有能说清“何时调用、读取什么、做什么、怎样验收、什么时候不适用”的 Skill，才有复用价值。先用一个真实问题验证它，再考虑扩展技能库。
