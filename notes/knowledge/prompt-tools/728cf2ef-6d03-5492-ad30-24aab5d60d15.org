* 选择工具之前先确认什么
原稿罗列了多家提示工程产品，但工具名称、API 和功能会随时间变化。*这份历史资料只能帮助列出候选，不能直接当作 2026 年的产品规格。* 实际选择先确定任务缺口，再核对当前官方文档。

* 从六种能力反推需求
| 任务缺口 | 原文对应能力 | 验证方式 |
|----------+--------------+----------|
| 不知道从何提问 | 提示建议 | 是否能给出相关初稿 |
| 输出结构混乱 | 提示结构优化 | 能否满足固定格式 |
| 需要多次改写 | 迭代优化 | 是否可复现版本变化 |
| 需要减少偏差 | 偏差缓解 | 用反例检查失误而非相信宣传 |
| 特定行业任务 | 领域支持 | 核对数据边界、合规与术语 |
| 多人复用 | 预定义提示库 | 核对版本、权限与可导出性 |

* 原文列出的工具怎样理解
- *IBM watsonx.ai / Prompt Lab*：原稿用于说明模型实验与提示测试一类平台；具体功能以当前文档为准。
- *Spellbook、Dust、PromptPerfect*：原稿分别以提示编辑、链式提示和自动优化举例。这些属于历史性描述，未在本轮复核现行产品接口、价格、可用地区及服务状态。
- *PromptBase、OpenAI Playground、GitHub、LangChain、promplify*：分别代表提示市场、模型实验、代码资料、应用编排与管理类用途；名称出现不代表推荐、支持或已经完成测试。

* 一个可复核的选择流程
多模型比较需核对模型版本、参数和日志；多步骤自动化还要检查 API、权限、异常处理和分步产物。必须证实工具相对直接使用现有模型有实际收益。

1. 提出一个固定任务及合格答案标准。
2. 阅读产品当前官方说明，核对接入、权限、计费、保留期和版本。
3. 对同一任务实际测试免费或试用能力，保留输入与输出。
4. 与直接使用现有模型比较；若工具不减少人工工作或错误，就不引入。〔补〕

* 边界
没有进行实时产品接入测试，也没有证据支持“某工具今天一定具备某功能”。
